### 測試縫隙分析（為何上輪 590/600（comp）全綠、真機還是壞）

D9-bug7 那輪修的是「RELEASE 半邊被錯殺」——`should_swallow_unbound_locked_
key` 曾經連 cmd-l 的 RELEASE 都一起吞掉，導致殼端計時器收不到放開訊號。
那輪的單元測試（`session_lock.rs` 裡對 `should_swallow_unbound_locked_key`
的純函式測試）驗的正是「RELEASE 不該被吞」這件事，而且驗對了——**修法本身
沒錯，只是修錯了層**。真正的 disarm 開關根本不在 comp 這端送不送 RELEASE，
而在 gpui vendored 的 `gpui_linux/src/linux/wayland/client.rs` 自己的
client-side 軟體 autorepeat 計時器：它只認兩個 disarm 訊號——同 keycode 的
RELEASE，或是 `wl_keyboard::Event::Leave`。comp 端事後確實有把 RELEASE 轉發
過去了（D9-bug7 修對的部分），但 `DuduclawComp::settle_layer_keyboard_
focus` 在「鎖定」這個時間點幾乎必然是 no-op——殼的 layer surface 早在
Cmd+L 被殼看到之前就已經持有鍵盤焦點（那正是這個全域快捷鍵能生效的前提），
所以 `held.as_ref() == Some(&surface)` 短路，從未真的送出一組 leave+enter。
單元測試測的是「純函式的輸入輸出對不對」，這一層完全測不到「這個函式的
呼叫時機/上下文是否讓另一邊的計時器真正被喚醒」——這是一個**跨行程協定
層級的副作用**，只有真 VM 上的真 Wayland client（gpui）才能觀察到。這次
把「真機情境」寫回測試的方式：`session_lock.rs` 新增一個 source-scan
regression test，鎖住 `set_session_locked` 必須在 `settle_layer_keyboard_
focus` **之前**呼叫新的 `force_keyboard_leave_enter_cycle()`——這個測試
測的不是純函式輸入輸出，而是「呼叫順序」本身，因為呼叫順序就是這次真正
會被漏掉的東西。

### Bug 1（P0，鎖屏密碼欄洪流）根因＋修法

兩個獨立、都會造成同一症狀的洞，這輪都補了：

1. **gpui 自帶的 client-side 軟體 autorepeat 計時器從未被真正 disarm**（讀
   pinned rev 原始碼實錘，見 `session_lock.rs` 新增的
   `force_keyboard_leave_enter_cycle` doc comment 引用的原文——gpui 自己的
   註解寫著「Prevent keyboard events from repeating after opening e.g. a
   file chooser and closing it quickly」，作者早就預留了這個逃生門，只是
   comp 沒在對的時機拉它）。修法：`set_session_locked` 現在會在
   `settle_layer_keyboard_focus` **之前**，先把鍵盤焦點清成 `None`
   （`force_keyboard_leave_enter_cycle`），保證兩個方向（鎖定／解鎖）都
   送出一組真正的 wl_keyboard leave+enter，逼 gpui 的計時器世代號失效。
2. **鎖屏密碼欄從未在 `lock()` 時清空**——`lockscreen_password_field` 是
   開機時建立一次、終身複用的 gpui Entity；`lock_and_refresh` 過去只清
   Launcher 搜尋欄，密碼欄唯一會被清空的時機是「成功送出一次驗證」。這
   代表上一次鎖屏留下的殘留字元（不管來自何種機制）會在下一次鎖屏「畫面
   一出現就已經是滿的」——這正好對上使用者回報的「瞬間殘留」而非「逐漸
   累積」。修法：`lock_and_refresh` 現在比照 Launcher 搜尋欄，每次鎖定都
   無條件 `.clear()` 密碼欄。

VM 三輪活測（clone 母盤、QMP 47065/47066，含 W5-1 原始 race 手法——Cmd 先
放、L 後放，用既有 `w51_cmdl_race.py` 工具重放）：**三輪全部 PASS**——

### Bug 2（深色模式同行程不跟隨）根因＋修法

`main.rs:773` 那份 `self.theme = flow.state().selections.theme` 賦值本身
