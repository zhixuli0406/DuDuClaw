## 活體抓到的八個真 bug（本波最有價值的部分）

1. **comp udev 後端不 flush Wayland client**（開機黑畫面級）——`flush_clients()` 只寫在算繪路徑末端，
   沒有 damage 就提早返回，剛連上的 client 開場 roundtrip 永遠拿不到回應。殼單執行緒 0% CPU 卡死在
   `do_sys_poll`。主 session 直接修（event loop callback 每輪無條件 flush）。
2. **`InputEvent::PointerMotion` 是空 arm**（真硬體游標完全不會動）——winit 只發絕對座標所以一直沒露餡，
   libinput 對滑鼠一律發相對移動。A4-1 抓修。
3. **絕對座標映射到 shadow output**——CD-2 的影子 output 插在 `(0,100_000)`，`outputs().next()` 回它。
4. **`StartLimitIntervalSec`/`StartLimitBurst` 放錯 section**（systemd 只在 `[Unit]` 認得），長期靜默失效。
5. **通知中心 429 熱迴圈**（雙層根因：失敗不推進 `last_refreshed_at` → 永遠 stale；stale 計時器每次重繪就多 arm 一個）。
6. **`flatpak override` 忽略 `--installation=`**（1.16.6 實測：exit 0、無警告、`--show` 讀得回來，位元組卻落在預設安裝點）。

7. **殼在 comp 上收不到鍵盤／滑鼠**——根因在 client 端：gpui 的 Wayland 後端只存一個 seat
   （`gpui_linux/.../wayland/client.rs:309` 原文即 `// TODO: Multi seat support`），第二個 seat 的
   capabilities 事件會 `release()` 掉前一個的 keyboard/pointer，殼因此只剩 agent seat 而焦點在人類 seat。
   修法＝讓 agent seat 先廣播，使 last-wins 落在人類 seat；codrive 安全模型零改動。

8. **comp 的 initial configure 沒帶尺寸**（使用者親測回報「盒上畫面被截斷、下一步按鈕不見了」）——
   `send_configure()` 不設 size 時送 0x0，在 xdg-shell 等於「client 自己決定」，殼因此在 1280x800
   的輸出上選了約 1280x957，OOBE footer（返回／略過／繼續）整條落在下緣外。看起來像少一顆按鈕，
   其實是視窗太大。cage 不會露出這個問題（kiosk compositor 會把唯一 client 強制成輸出尺寸）。
   修法＝初次 configure 前把 pending size 設成主輸出尺寸；刻意不加 Maximized/Fullscreen 狀態
   （會連帶改變每個 GTK/Qt app 的 CSD，屬未複核的視覺變更）。

另修一個既有 flake：`shell_control::listener` 拒絕路徑的 `writeln!().unwrap()` 撞 EPIPE（1/15）。
