## 下午：`computer_*` 工具接真（使用者拍板 B）與網域白名單（拍板 A）

上午活測實錘七個工具是佔位後，使用者選 B（真的接上）；接上後活測發現容器沒網路又沒網址列（L17），使用者選 A（每員工白名單加導覽工具）。

1. **八個工具經 gateway 內部路由驅動容器 session**。`mcp-server` 行程把每次呼叫以簽章請求送到 `POST /api/internal/computer-use`（loopback 加 HMAC 簽章，nonce 防重放）；gateway 持有 session 與容器，自己重查工具權限與審批清單。每員工一個 session、全域上限 5、閒置 2 分鐘回收。
2. **審批閘身分修正**。MCP 審批閘原本拿 `gateway-internal` 當員工 id 讀設定，三個審批清單在正式路徑上從未生效；改用實際員工後生效（行為變更）。
3. **網域白名單 `allowed_domains` 與 `computer_navigate`**。gateway 解析並釘選位址，容器只放行到這些位址的 TCP 443、不開 DNS。沒設白名單的 session 沒有網路。
4. **容器加固**。`no-new-privileges`、Chromium 受管政策（禁無痕、下載、列印、檔案對話框、本機網路存取等）、輔助程式在隔離 world 執行、截圖目錄 root 專用、網址經 stdin 傳入。
5. **共用 SSRF 位址檢查（既有漏洞，已發布版本受影響）**。`web_fetch::is_internal_ip` 只認得六個網段，IPv4-mapped IPv6 可繞過。修正前實測 `web_fetch_cached` 抓 `http://[::ffff:127.0.0.1]:18971/healthz` 拿回 gateway 的回應。全 repo 改用 `duduclaw_core::net_addr::is_public_ip`。
