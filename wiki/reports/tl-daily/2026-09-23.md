## CI 兩個失敗修復（使用者「將CI兩個問題都修復」）
CI 從 09-09 起就紅：Security Audit（新公告）＋ Windows leg（`continue-on-error`，所以整體仍綠、沒人注意；6 月時 Windows 曾全綠）。修法分五輪 commit，每輪都先在本機用 mingw-w64 對 `x86_64-pc-windows-gnu` 交叉 `cargo check --tests` 驗過再推：
1. **a0f13de9**：sysd 非 unix `bind` stub 簽名漂移（Windows 編譯錯）；rustls 0.23.38→0.23.45（RUSTSEC-2026-0285）；ringbuf 0.4.8（RUSTSEC-2026-0293）無法升——songbird 0.5/0.6 都鎖 `^0.4`，走 `--ignore`＋`.cargo/audit.toml` 寫可達性理由（songbird 只放 `u8`，Drop 不會 panic）。**Security Audit 從此綠。**
2. **7b5e07f3**：Windows 測試樹編譯——`data_migrations` PermissionsExt、gateway `sysd_integration`（`nix` 是 cfg(unix) 依賴）、非 unix `CodriveClient` stub 缺 Debug。
3. **addb1b90**：Windows 測試執行——`DUDUCLAW_COMPAT_DIRS` 用 `split(':')` 會把 `C:\` 切開（真 bug，改 `split_paths`）；四個跑 bash 腳本的 migration 測試閘 unix；**順手抓到跨平台潛伏 flake**：compat_runners 測試整個替換 `PATH`，與 data_migrations 的 `bash` spawn 交錯就炸（macOS 3 跑 2 炸），改成前置而非替換。CI test 步驟加 `--no-fail-fast`。
4. **b1f64673**：Ubuntu 偶發——data-file-guard 測試 harness 寫 stdin 撞 EPIPE（off 模式腳本不讀 stdin 就退出）；inference `models_dir` 斷言改走 `Path::join`；**真 bug**：`audit_chain` 在 Windows 併發 append 會分叉 hash 鏈——`LockFileEx` 對 append-only handle 鎖不住（呼叫端 warn 吞掉），non-unix 改走 sidecar `with_file_lock`。
5. **5143bd0e**：gateway 12 個 Windows 測試——**真 bug**：`llamafactory_cli()` 用 `Path::join` 拼遠端 POSIX 路徑（Windows 主機會把 `venv\bin\llamafactory-cli` 丟給 GPU 機）；其餘為測試碼：TOML/JSON 字串用 `format!` 塞 Windows 路徑把 `\` 當跳脫、`/etc/hosts`／`/opt/evals` 在 Windows 不是絕對路徑、目錄 handle 設 mtime 需 backup semantics、statvfs/getifaddrs/shell-script 探測閘 unix。這輪把 Windows gateway 失敗從 12 壓到 3。
6. **05f6d611**：最後三個——oversize 封存 fixture 同樣的 `format!` 塞 JSON 問題；目錄 handle 設 mtime 要 `FILE_WRITE_ATTRIBUTES`；tick fetch-failure 測試固定睡 1.5s 在慢 runner 不夠（整套跑 660s，Ubuntu 只要 126s），改輪詢計數器（20s 上限）＋平台各自的失敗指令。**05f6d611 這輪六個 job 全綠，Windows leg 自 6 月底以來首次全綠（build＋兩個 test 步驟）。**
