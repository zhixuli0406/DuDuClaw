# 原生 Linux 受保護模式（預計 v1.82.0 提供）

> **狀態：預計 v1.82.0 提供。v1.81.0 無法使用。** 程式碼已包含在 v1.81.0，但客戶主機還無法安裝或啟用。
>
> v1.81.0 的做法：`sudo duduclaw service install --protected-linux` 照 v1.80 的方式安裝單一執行檔的受保護服務，`sudo /opt/duduclaw/bin/duduclaw service upgrade --protected-linux` 負責更新。AI 員工的建立與執行都和 v1.80 相同。詳見[單一執行檔受保護服務](../../guides/zh-TW/linux-protected-service.md)。
>
> 以下內容（設定裡的管理頁、個人與共用員工、員工專屬的連接器帳號、註銷與還原、從 v1.79.3 遷移）都是預計提供的版本。

受保護模式讓每位 AI 員工在原生 Linux 主機上使用自己的帳號與獨立的執行環境。對話、記憶、檔案、連線與權限都留在該員工身上，閘道自己的帳號不會借給員工。缺少隔離服務或可信任政策時，員工的工作會被拒絕，不會改用閘道帳號執行。

此功能預設不啟用，僅 Enterprise 版提供；沒有使用的安裝行為不變。目前尚未在真實 Linux 主機完成驗收（見[還需要真實主機的部分](#還需要真實主機的部分)）。

## 如何開啟（預計 v1.82.0）

以下步驟要等隔離元件可以安裝後才適用。在 v1.81.0 會停在第 1 步：安裝程式只裝單一執行檔的受保護服務，就緒檢查不會回報隔離已就緒，管理頁也不會出現。

1. 在支援的主機（Ubuntu 22.04、Ubuntu 24.04 或 Debian 12；x86_64 或 ARM64）執行 `sudo duduclaw service install --protected-linux` 安裝受保護服務，步驟見[受保護服務指南](../../guides/zh-TW/linux-protected-service.md)。
2. 執行 `sudo duduclaw service readiness --protected-linux`。儀表板的就緒橫幅會說明什麼擋住了受保護工作（帳號或連線設定未完成、授權被撤銷、服務暫時無法使用），並附支援參考編號。
3. 系統狀態回報受保護模式就緒後，管理員會看到「設定 › 受保護模式」，內有 AI 員工、連接器帳號、Google 租戶來源與紀錄四個分頁。
4. 既有員工透過管理員遷移確認頁帶入：每筆提案在密碼與雙因素驗證後核准、拒絕或重試，低風險提案可批次處理。

主機正式採用前，請先跑[驗收手冊](../../guides/zh-TW/linux-protected-acceptance.md)。

## 個人與共用 AI 員工

| | 個人專屬 | 共用 |
|---|---|---|
| 屬於 | 一位同仁（擁有者） | 一個租戶 |
| 誰能使用 | 只有擁有者 | 租戶成員，依原有角色 |
| 如何建立 | 同仁在「我的帳號」申請（每人同時最多 3 筆待處理）；管理員通過密碼與雙因素後備妥設定，並在核准卡片確認。管理員也可直接提出 | 管理員提出，並在核准卡片確認 |
| 連線 | 擁有者自己的帳號 | 租戶帳號，以及允許使用的主機端連線 |
| 背景工作（排程、提醒、定期檢查） | 不提供 | 管理員核准後可用（24 小時內決定，授權最多 30 天） |
| 被他人呼叫或指派 | 他人（包含管理員）不能指派工作給它；擁有者開啟「公開呼叫」時，其他人可用 `@` 呼叫 | 依一般交辦規則 |
| 管理員能看到的資料 | 只有基本資訊 | 一般 |

受保護模式下不能直接建立 AI 員工，每位員工都來自申請或提案，並經過核准。

### 誰看得到個人專屬員工的資料

對話與執行紀錄、記憶、設定檔、員工自己的 Wiki、任務內容、檔案與核准內容都屬於擁有者。主管不會透過部屬取得這些資料。不是擁有者的管理員必須先以密碼與雙因素重新驗證身分（5 分鐘內有效）才能讀取，每次讀取都會記錄管理員、員工、擁有者與資料類別。跨員工的清單與搜尋不會列出這些員工，其他 AI 員工也不能修改、移除或讀取個人專屬員工的設定、技能、Wiki 與信箱。

## 註銷、還原、接手、清除與釋放

| 步驟 | 發生什麼事 |
|---|---|
| 註銷 | 管理員可註銷個人或共用員工。員工立即停止，進行中的工作中止，連接器帳號撤銷，資料封存在隔離區 90 天；員工名稱在這 90 天內保留。 |
| 還原（個人） | 由擁有者以註銷前就已設定的最強兩步驟驗證方式申請（驗證失敗計入登入鎖定）。管理員通過密碼與雙因素後核准，核准者必須是與申請人不同、且符合資格的另一位管理員；只有申請人自己符合資格時，可在 7 天冷卻期後核准自己的申請並留下紀錄。擁有者沒有任何第二重驗證時無法自行申請，由管理員代為申請。擁有者自己變更密碼、Email 或兩步驟驗證會記為本人變更，他人改動過則拒絕還原。註銷後撤銷擁有者的登入工作階段不會擋住還原。 |
| 還原（共用） | 由管理員申請，從註銷當時的成員名單勾選要恢復的成員（權限只能維持或降低，已停用或離職的成員會略過並列出），並勾選要重新核准的租戶共用連線，再由第二位管理員核准。只有勾選的成員與連線生效，其他成員需重新綁定，員工專屬連線需重新設定，排程與任務維持暫停；每位恢復的成員都會收到通知。 |
| 還原後 | 網站憑證授權與其他員工的回報關係只會列出，由管理員逐項重新授權，不會自動恢復。 |
| 由新員工接手 | 主機確認舊員工資源已不存在後，擁有者（個人員工，只能接手給自己）或管理員（共用員工，只能留在同一租戶）可用新的員工編號建立新員工。只會帶過 SOUL.md、CONTRACT.toml、agent.toml、SKILLS 與篩選後的設定（拒絕與詢問清單、模型）；記憶、對話、任務與排程留在隔離區，舊員工的權杖與授權失效，主機工作區不會複製。中途失敗時，檔案移回隔離區並重新驗證。 |
| 清除 | 滿 90 天後，管理員通過密碼與雙因素即可清除隔離區。未滿 90 天需勾選確認並提出「提前清除」，由第二位管理員核准；核准時會再比對一次內容，有變更就要重新申請。清除會刪除隔離區檔案、該員工的記憶、對話、排程、任務與保留中的網站憑證授權；已由新員工接手的資料不受影響。 |
| 釋放主機資源 | 清除後，管理員可釋放主機端：清除主機工作區、停用帳號並釋放員工代號，員工 UID 永不重複使用。釋放一旦開始就不能取消，只能重試到完成。 |

申請與清除發生時，員工主人與管理員會收到通知（每日每位主人或租戶最多 5 則），稽核紀錄保留封存摘要、檔案數量與大小。中斷的清除會在下次操作或重新啟動時完成；主機無法連線、紀錄不一致或仍有工作執行時，該步驟會被拒絕或稍後重試。

**升級後的前 7 天。** 核准資格依管理員身分的 7 天紀錄判斷，而這份紀錄從升級時才開始。這 7 天內無法核准任何還原、清除或釋放。

## 受保護員工能做什麼

- 在自己的環境內執行程式、分析程式碼與執行 Office 腳本，結果在同一次呼叫中回傳；取消或連線中斷只會結束該次呼叫。
- 讀取自己被授權的工作區檔案。
- 文件、試算表、圖片、網頁與專家 ZIP 包由另一個有資源上限的服務解析，輸出驗證後才交回。
- 只有管理員在員工的 `agent.toml` 的 `[isolation]` 設定 `public_web = true` 時，才能擷取與抽取公開網頁（預設關閉，僅管理員可改，在設定檔或管理員設定編輯器中修改）。只能連到公開的 HTTPS 網站，IP 位址、網址內的帳密、非預設連接埠、內部名稱與轉址都會被拒絕。
- 從技能庫安裝技能（經受保護的公開網路下載，在隔離解析服務內解開並掃描，再走既有審核），並用自己的模型設定與預算，從自己的事件合成技能。技能只寫入自己的技能目錄，不覆寫同名技能；發布到全域技能庫需要管理員在核准卡片同意。
- 交辦工作給其他員工或建立臨時助手，每次呼叫都依員工本人的授權重新確認。個人專屬員工替共用員工做事需擁有者核准。臨時助手以原員工身分，只用原執行的工具，在原執行結束後才開始，24 小時內未啟動即失效。
- 查看與撤回自己提出的探索申請，查看與比較自己的分支試算。分支試算的建立、選定與終止在下一版提供；費用未量測時顯示「無法取得」，不會顯示為零。

## 瀏覽器錄製（預設關閉）

錄製有一道開關：主機必須實測證實 Chromium 能在 helper 沙箱內啟動。在那之前，就緒檢查顯示 `helper_recording_unsupported`，錄製工具與「從錄製蒸餾技能」都不會出現，員工也需開啟 `public_web`。錄製可用時，產物會帶著錄製結束時記下的雜湊，被改過的檔案讀取時會被拒絕；原始 trace 可能含敏感畫面。收到停止請求不代表錄製已結束。

## 升級注意事項

- 個人專屬員工上沒有記錄建立者的舊排程與提醒，會在執行時停止，需由擁有者重新建立。
- 此版本之前核准的背景工作需要管理員重新核准，系統會自動送出一次申請。
- 管理員不再自動擁有他人個人專屬員工的存取權。
- 存在被隱藏的個人專屬員工時，無法使用即時日誌追蹤。
- 改版前提出的探索申請，員工看不到（管理員仍看得到）。
- 錄製預設關閉。

## 還需要真實主機的部分

元件層級測試已在 Ubuntu 22.04、Ubuntu 24.04 與 Debian 12 以 root 跑過，完整流程則還沒有。待完成的項目：各發行版的驗收手冊（含 Ubuntu 24.04 使用 7.0 kernel、Landlock ABI 8 的情況）、Google、Notion、GitHub 與 Odoo 的真實供應商帳號、開啟錄製所需的 Chromium 實測，以及註銷與釋放中必須以 root 才能做的檢查。這些通過之前，請不要把受保護模式當成正式環境的隔離保證。
