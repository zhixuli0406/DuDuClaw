# 終端控制室

[English](../71-control-room.md) · [日本語](../ja-JP/71-control-room.md)

`duduclaw tui` 讓你在終端機看到 AI 員工趁你不在時做了什麼，也能在終端機叫它們停下或調整方向。它是 gateway 的客戶端，每個動作都走和儀表板相同的授權，控制室本身沒有任何權限。

按鍵與指令請看[使用指南](../../guides/zh-TW/tui.md)。這一頁說明控制室的用途和界線。

## 用來做什麼

員工會自己依目標、排程和職責工作，於是你會有三個問題：現在有什麼在跑、什麼在等我、怎麼讓它停。控制室把這三件事放在同一個畫面，也能透過 SSH 使用。

| 問題 | 看哪裡 |
|---|---|
| 什麼在等我？ | 收件匣：待核准項目和等你回覆的目標，每列都寫明是誰提出、為什麼。斷路器通知也會出現在這裡，屬於資訊，不算待處理，也不觸發桌面通知；畫面內可顯示錯誤浮動通知。 |
| 現在有什麼在跑？ | 員工清單、執行與任務區塊、下一次排程、`duduclaw tui watch`。 |
| 怎麼讓它停？ | `p` 暫停所選員工的自主工作，`u` 恢復。Admin 可從命令面板暫停全部。 |

對話改為靠右的使用者訊息與帶名稱／時間的員工純文字回覆，工具步驟和回合結果集中在所屬回合下方。輸入列持續顯示；待審與暫停目標以內嵌卡放在其上。數字僅作選項標籤，`Enter` 開啟原有決策卡；權限重查、確認碼、版本綁定與不自動重試均不變。置中浮層及右下通知採 raised 底色、背景變淡，支援深色、淺色、ANSI 與 `NO_COLOR`。`motion = "on"` 只讓執行中的工具步驟約每 80 毫秒轉動，`"off"` 改用靜態符號。輸入焦點、草稿保留與浮層按鍵詳見使用指南。

## 讓工作停下

有三個控制看起來很像，做的事不同。

| 控制 | 會停什麼 | 什麼繼續 |
|---|---|---|
| 自主暫停（`p`） | 該員工的目標回合、排程、心跳、職責、Autopilot 動作與指派排程。立即送出、不用確認，因為緊急停止不能等。 | 目前這個回合會跑完。你仍可以和該員工對話。 |
| 員工狀態暫停（命令面板） | 改變員工自身狀態，有確認卡。 | 狀態不可運作時，自主工作都不會跑。 |
| 取消對話回合 | 該回合。如果還有派出去的工作在跑，控制室會問你要不要一起停。 | 你沒停的工作會跑完，但不能再以這個回合往下交辦。 |

狀態列會顯示誰被暫停。讀不到暫停狀態時，gateway 會把自主工作當成已暫停，控制室也會明說。變更還沒確認時顯示「待確認」，不用猜的。

## 控制室不做的事

- 不授予常設權限，也不改全域行為。這些留在儀表板，你才看得到完整表單。
- 需要本人在場的核准，仍然開瀏覽器處理。
- 已經執行的外部動作，停止工作也追不回來。
- 取消回合時，不會追蹤該回合建立的任務板任務與目標。

## 信任界線

員工產生的文字一律不信任。名稱、任務標題、工具輸出和對話回覆在畫出來之前都會清掉終端控制序列，連結也不會變成可點擊。桌面通知只有固定文字和數字，不含姓名或內容，而且預設關閉。畫面內浮動通知與通知信箱只使用固定文案及清理過的員工顯示名稱，不包含訊息、任務或工具內容。

內嵌終端區塊屬於你自己，不經過 gateway。它顯示的「等你處理」標記只是顯示，不授權也不回答任何事。Windows 不提供這個區塊。

請在 gateway 所在主機上執行控制室，遠端就用 SSH。不要轉發 gateway 連接埠，那會讓轉發端主機碰到本機登入路由。

## 外觀

配置對齊儀表板：全畫面採中性底色，約 34 格的側欄不畫框；主內容內縮一格，使用另一層底色，只留一圈淡圓角框。側欄頂部是品牌與搜尋列（`Ctrl-P` 開既有命令面板），下方分成「需要你／執行中／閒置」，暫停員工放在閒置組並保留暫停符號及文字。員工以兩列顯示，右側對齊狀態膠囊或資訊，第二列使用次要文字色；選取時整列填色並顯示 `›`，失焦時底色較淡。未選取員工若有未讀收件匣項目，顯示 `✦`（ASCII 為 `*`）。小於 100 欄或高度不足時縮成一列，超出的員工顯示隱藏數，方向鍵移動會保留選取列可見。

對話、任務、紀錄分頁仍以 `Tab`／`Shift-Tab` 切換，`[`／`]` 保留前後紀錄導覽。`I` 開收件匣，Manager／Admin 以 `S` 開排程；分割、PTY、決策卡與自主工作區塊仍可使用。側欄底部依序是收件匣與排程件數、連線及有權讀取的費用。費用不可用或被拒絕就隱藏；美元顯示兩位小數，非零且低於 $0.01 時才顯示四位。主內容標頭顯示員工狀態、名稱、既有員工快照中的 runtime／偏好 model（不代表 fallback 後實際使用的模型），以及靠右分頁；目前分頁以淡底色膠囊標示。快捷鍵提示放主內容底部，閘道版本靠右，不再有全域頁首或頂部篩選列。`?` 提供完整 home 路徑。最低尺寸仍是 24×12；快照涵蓋 80×24、100×30、140×40、200×50 的 dark、light、ansi、NO_COLOR，另有 ASCII 與模糊字寬檢查。這些是畫面驗證，並非本次改版的原生終端驗收。

畫面內浮動通知在主區右下角顯示「完成／需要你／錯誤」，分別採成功、警告與危險色，同時最多兩則，最新在上。「完成」與「錯誤」約六秒後消失，「需要你」保留到看過或關閉。通知不搶焦點，也不蓋住決策卡；以 `F8` 主動聚焦通知，再用方向鍵選取、`x` 關閉。

`M` 開啟本次程序最近 100 則通知的信箱，`N` 保留建立目標用途。`Tab` 篩選全部、未讀或錯誤，方向鍵選取，`Enter` 跳到員工或收件匣項目，`Esc` 關閉。開啟信箱會把現有通知標為已讀並關閉其浮動通知，之後的新通知保持未讀，直到對通知按 `Enter`、開啟或標記相關收件匣項目已讀，或關閉再重開信箱。歷史與未讀狀態只留在記憶體，不改動 gateway 待處理事項。

`z` 放大目前區塊，隱藏側欄與內容標頭，頁尾保留還原提示；再按一次回復配置，決策卡與命令面板仍可使用。對話及紀錄分頁提供精簡活動時間軸，每個已有的工具步驟與回合結果各占一行。以 `t` 聚焦、方向鍵選取、`Enter` 展開或收合現有詳情。文字仍經清理並依顯示寬度處理，執行內容維持原本 `c` 的同意流程。這些畫面沿用已收到的資料，不新增 RPC；`tui watch` 行為不變。

`theme = "auto"` 使用 `COLORFGBG`，未設定或無效時採深色；淺色終端請明確設定 `theme = "light"`。`light` 與 `dark` 分別使用淺色與深色配色。`theme = "ansi"` 限用 16 個 ANSI 色，畫布與表面使用終端背景，並依 `COLORFGBG` 判定亮暗，否則採深色。任何主題都可設 `background = "terminal"`，讓全畫面底色與主內容畫布沿用終端背景，保留卡片及選取底色。其餘色彩能力依序採用 `COLORTERM=truecolor` 或 `24bit`、含 `256color` 的 `TERM`、16 色 ANSI。`NO_COLOR` 設為任何值（含空字串）都關閉色彩，仍保留選取與強調提示。

四層表面採儀表板的中性灰；琥珀色用於待審、暫停及鍵名，綠色表示執行中，品牌藍用於標誌。文字與所在底色不足 4.5:1 時，會以該色彩能力可用的最小前景調整補足；裝飾框線刻意維持低對比。測試涵蓋 truecolor／256／16 色參考配對。ANSI 實際對比仍取決於終端自訂色盤；終端背景使用 COLORFGBG 或備援值計算，背景未知時不能保證實際對比。

16 色對比計算採 ANSI 參考色盤，終端自行設定的 ANSI 色彩會決定實際顯示對比。

## 終端機

下表只記錄實際跑過的結果。沒列出的終端機可能可用，只是還沒檢查。

| 終端機 | 狀態 |
|---|---|
| macOS 上的 tmux | 全螢幕已在真實 gateway 測過，包含本機真實模型的回覆、回覆途中取消，以及滑鼠輸入送達終端區塊內的程式（X10、SGR、urxvt、SGR-Pixels 四種編碼與 `vim`）。tmux 允許時，通知走 tmux passthrough。 |
| macOS 上的 Terminal.app | 全螢幕已在真實 gateway 測過：繪製、中日韓字寬、`p` 與 `u`、中文與 emoji 輸入、終端區塊、正常退出。按鍵由測試程式送入，不是實體鍵盤。 |
| 自動測試中的 macOS、Linux 虛擬終端 | 畫面由快照涵蓋，寬度 60 欄以上，高度到 12 列。 |
| Windows，透過 SSH 執行 `tui inbox` | 已在原生 Windows 機器測過。 |
| Windows 11 全螢幕，於 ConPTY 下 | 已在原生 Windows 機器的真實 gateway 測過，由測試程式驅動真實 Pseudo Console：繪製、調整大小、視窗過小提示、`p` 與 `u` 在 gateway 端確認生效、中文輸入、正常退出。尚未在 Windows Terminal 本身操作。 |
| 實體機 Ubuntu 22.04，於 PTY 下全螢幕 | 已在真實 gateway 測過：繪製、調整大小、視窗過小提示、`p` 與 `u` 在 gateway 端確認生效、正常退出並還原終端。尚未在實體終端機程式上操作。 |

控制室至少需要 24 欄、12 列，視窗太小時會直接告訴你。UTF-8 語系且 `TERM` 不是 `linux` 或 `dumb` 時，狀態符號預設使用 Unicode，其他情況使用 ASCII。在 `tui.toml` 明確設定 `glyphs = 'ascii'` 或 `'unicode'` 可覆蓋偵測；Unicode 模式使用圓角框線。控制室處理了中日韓字寬和整字提交，但輸入法還沒有人工實測。
