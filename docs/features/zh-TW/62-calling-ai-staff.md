# 用 @ 呼叫 AI 員工

平常對話由一位預設的 AI 員工回覆。想把某一則訊息交給別位員工，就像在通訊軟體裡 @ 人一樣，打 `@` 加名字。從 v1.76.0 起，叫得到誰要看你是誰，而且每則訊息各自判斷。

## 一則訊息交給誰

1. 沒有叫任何人的訊息，交給這個對話的預設員工：綁定這個頻道或討論串的員工；沒有的話，`allowed_channels` 列了這個通道的員工；再沒有就是主員工。dashboard 的 WebChat 裡，目前選的員工就是預設員工。
2. 叫了某位員工的訊息，交給那位員工，**只有這一則**。下一則沒打名字的訊息就回到預設員工，不會黏著。
3. 可以用 `@觸發詞`（`[agent] trigger` 的值）、`@顯示名稱` 或 `@代號` 呼叫。不分大小寫；名字後面直接接中文也認得（`@財務小幫手幫我算帳`）。全形 `＠` 也可以。電子郵件地址（`ann@example.com`）永遠不算呼叫。
4. 好幾個名字都對得上時取最長的（有 `@財務小幫手` 就不會當成 `@財務`）。一則訊息提到好幾位員工時，取文字裡最先出現、而且你叫得到的那位。
5. 只打部分名字（`@財務`），或兩位員工同名時，不會默默交給某一位，而是回你可能的人選。
6. 沒打 `@` 就不切換。「財務小幫手，幫我算帳」會交給預設員工。

## 誰叫得到誰

| 發話者 | 叫得到 |
|---|---|
| dashboard 管理員 | 所有員工 |
| WebChat 裡的 dashboard 帳號 | 帳號綁定的員工（任何權限等級） |
| 綁定了 dashboard 帳號的通訊軟體使用者（已驗證的通道身分） | 帳號綁定的員工，加上這個對話的預設員工與開放給外部聯絡人的員工 |
| 其他人：LINE 好友、Telegram 使用者、網站聊天訪客 | 這個對話的預設員工與開放給外部聯絡人的員工 |

要開放某位員工給外部聯絡人，在員工編輯頁打開「允許外部聯絡人呼叫這位員工」（`agent.toml` 的 `[channels] public_trigger = true`）。預設關閉，只有管理員能改，員工自己改不了。

叫了沒有權限的員工，在呼叫模型之前就會被拒絕。回覆只說你沒有呼叫這位員工的權限，不寫出員工名字；但這也表示這個名字確實是某位員工（對不上任何人的名字會當成一般文字交給預設員工）。拒絕會記進安全稽核紀錄（`trigger_route_refused`），記的是 dashboard 帳號；沒綁帳號的發話者只記一段短雜湊，不記平台原始 ID。允許的切換記在 info 等級的日誌。

沒有綁定預設員工的 WebChat 帳號，送出沒叫任何人的訊息或聊天指令（`/goal`、`/status` 等）時會被拒絕，並提示先選員工或輸入 `@`。WebChat 裡被叫來的員工的回答，存在那位員工自己的對話紀錄，不寫進目前所選員工的紀錄。

同一位發話者重複叫同一位員工被拒，稽核每分鐘只記一筆。

## @ 名單

- **WebChat**：在輸入框打 `@` 會跳出你叫得到的員工（頭像、名字、部門），邊打邊篩選。方向鍵移動，Enter 或 Tab 插入 `@名字 `，Esc 關閉。回覆來自目前對話以外的員工時，泡泡上方會標示是誰回覆。
- **LINE**：單獨傳 `@`（或 `@` 加部分名字），bot 會用快速回覆按鈕列出名單，一次最多 13 個；超過時最後一個是「更多」，按了看下一頁。點名字會送出 `@名字`。
- **Telegram**（共用 bot）：同樣的名單，用訊息下方的按鈕呈現。
- 其他通道用文字列出名單。

名單、拒絕與「請說要交給…」的提示，和 AI 回覆一樣要先通過使用者存取管制（封鎖名單、配對）與真人接手檢查才會送出。

## 先點名，再說要做的事

在通訊軟體（LINE、Telegram、Discord、Slack 等）只傳 `@名字`，或在 LINE、Telegram 的名單點一位員工，bot 會回「請說要交給「名字」的事」。10 分鐘內，**只有你在這個對話的下一則訊息**會交給那位員工，之後恢復正常判斷。那則訊息到的時候會再檢查一次你的權限。同一個群組裡其他人的訊息不受影響。

這個等待狀態只存在記憶體。閘道重啟後就忘了，下一則訊息會交給預設員工。已經在等待狀態下收進來的 LINE 訊息會被隔離（`account_route_authorization_changed`），不會改由錯的員工回答。

## 群組「只回提及」

- **LINE**：開啟「只回提及」後，bot 只回應用 `@` 叫員工（或要 @ 名單）的訊息，以及被點名員工正在等的那一則。v1.76.0 之前這個設定會讓整個群組完全沒有回應。LINE 不會告訴 bot 被引用的是不是它自己的訊息，所以引用 bot 的訊息不算。
- **Telegram**：共用 bot 在只回提及的群組裡，除了自己的 `@帳號` 和回覆它的訊息，也接受員工名字。各員工專屬 bot 維持只認自己的 `@帳號`。

## 是誰回答的

- WebChat 的回覆框架（`assistant_done`）帶 `agent`（代號）與 `agent_name`。
- LINE 和 Telegram 上，不是預設員工的回覆開頭會加 `【名字】`；預設員工的回覆不加。LINE 泡泡的標題現在寫回答的那位員工（以前一律寫主員工）。
- 行為契約（`CONTRACT.toml`）檢查與機密還原，都以實際回答的員工身分進行。

## 還沒涵蓋的

- Discord、Slack 等其他通道套用同一套規則、文字名單與先點名再交辦，但沒有按鈕。端到端實測只做了 WebChat 和 LINE，Telegram 只有單元測試。
- 其他通道的發話者，只有透過通道登入流程驗證過的身分，才會對應到 dashboard 帳號。
