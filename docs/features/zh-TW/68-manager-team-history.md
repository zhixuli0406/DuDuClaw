# 主管唯讀查看團隊對話

尚未發版，目前提供後端 RPC；檢視頁面與職員端提示由後續變更加入。

企業版的有效主管或管理員，可以查看部屬負責的 AI 員工對話。條件是對方仍是有效帳號、在自己的直屬或隔級團隊內（最多八層），而且直接以操作者或擁有者綁定該員工。管理員身分本身不會跳過報告線。帳號被停權、改主管、移除綁定或被要求換密碼後，下一次請求就重新判斷；傳回內容前也會再查一次。

| 對話來源 | 看得到什麼 |
|---|---|
| 自己或範圍內部屬本人的登入 WebChat | 使用者和員工的文字全文，唯讀；附件只列檔名與類型 |
| 通訊軟體、網站訪客、Odoo 線上客服 | 雙方文字都遮蔽，附件只列類型 |
| 其他人的 WebChat、未知來源、未補值舊對話、排程或任務內部對話 | 不列出，也不提供隱藏筆數 |

只回目前生效時間窗內、可見且未撤回的使用者／員工訊息。舊標題、壓縮摘要、前文摘要、隱藏輪、思考與工具步驟都不回。列表標題取自時間窗內第一則可見使用者訊息。附件沒有路徑或下載連結。既有對話紀錄、匯出、下載和續聊權限不會因此放寬。

## 開關與生效時間

```toml
[people]
manager_team_history = true
```

有效設定檔的企業版預設開啟。設定檔不存在、讀不到、格式錯誤或值不是布林時視為關；個人版一律關。gateway 在通道開始接訊息前把生效時間存進 `users.db`，讀取與設定異動時重判，並每 60 秒同步版本變化。關掉再打開會開始新時間窗，前一段不會恢復。關閉時若稽核寫入失敗，會留下持久的重設旗標；修好稽核後重新開啟也不能沿用舊時間窗。

管理員使用 `users.org_settings.get` 與 `users.org_settings.update {manager_team_history: true|false}`，寫入沿用加鎖的設定儲存器。進階設定編輯器也會同步。直接改檔案則到下一次讀取或 watcher 才觀察得到；兩次觀察間完成的關／開無法偵測。關閉不會刪除原始對話。

## 遮蔽範圍

外部對話固定套用 `taiwan_strict`、`financial`、`general` 與自訂規則，模型端的遮蔽總開關和來源開關不會關掉這層保護。既有遮蔽 token 只轉成占位，不查 vault、不還原。相同電話即使標點不同，在同段對話得到相同類別與編號；不同對話重新編號。發話者平台 ID 改成「客戶 n」；已驗證且仍在團隊內的有效職員可顯示姓名。

所有原始規則命中的範圍都會遮住，包括低優先權的相交部分；優先權只決定占位類別。外部文字先做 NFKC 正規化，回傳的也是正規化後文字。有附件的整行一律改成附件片段，同一行的一般文字也不回，避免巢狀或跳脫括號留下檔名、路徑尾段。格式不完整的操作確認標記則從標記起剝到訊息結尾。

原文也會套用規則，避免全形自訂關鍵字或正規化後改變的字界漏遮。原文命中會保守對到完整字素；串接結果必須等於整段正規化文字，否則整段遮蔽。編號在記憶體內使用每次新種子的固定長度摘要，分裂的大型命中不會複製多份長個資；摘要不輸出、不落地，重新整理的可見編號仍一致。

沒有安裝本機 NER 模型時仍可讀，回應帶 `ner: false`：**只靠 regex，姓名與地址可能沒有遮住**。已安裝模型的推論錯誤、逾時、安裝不完整或規則無法編譯時，整段回 `masking_failed`。NER 使用會傳回錯誤的 API；遮蔽 worker 即使逾時仍占用 permit，避免故障時堆出無限背景工作。遮蔽副本不存磁碟或 vault。

這是產品讀取入口的保護。直接取得主機檔案或資料庫的人仍能繞過；regex 與 NER 也無法保證找出自由文字裡每一筆個資。

## RPC

| 方法 | 參數與回應 |
|---|---|
| `users.team_history.list` | 必填 `agent_id`；可選 `report_user_id`、`class`（`own`／`report_webchat`／`external`）、`limit`（預設 50、最多 200）、`before`。回 `sessions`、`next_before`、`since`、`ner`、`read_only: true`。 |
| `users.team_history.get` | 必填 `session_id`；`limit` 預設 200、最多 500。回類別、生效時間、`ner`、`read_only: true`、`messages`、`masked_counts`。 |
| `agents.callable` | 每筆加 `manager_may_read`：企業版與設定開啟、呼叫者直接為操作者以上、上方有有效主管時為真。 |
| `audit.resolve_session_digest` | 僅管理員；以 `{digest}` 把本機稽核中的 16 字元 HMAC 對回對話 ID。 |

訊息片段為 `{t:"text",v}`、`{t:"mask",cat,n}` 或 `{t:"attachment",kind,name?}`；外部類沒有 `name`。前端自行組語系占位，並在外部類 `ner: false` 時顯示未安裝智慧偵測的提醒。隱藏與不存在的對話都回 `session not found`。

分頁把 `next_before` 原樣傳回；第一頁也接受 RFC3339 時間作為 `before`。SQL 先套範圍再分頁，同一活動時間以對話 ID 區分。一頁最多掃 10,000 個已授權候選；一段時間窗最多 20,000 則／8 MiB，超出就拒絕，不默默略過。占位編號先用整個可見時間窗算，再取要求的最新訊息。每則顯示文字在遮蔽完成後才截到 20,000 字元。

一頁暫存的標題原文合計也最多 8 MiB，太大時請降低 `limit`。可選篩選參數必須是字串（或省略／null）；游標最多 4 KiB、部屬 ID 最多 128 bytes。發話者欄位優先用 AI 員工顯示名稱。

每次成功查看都要先完成 `team_history_viewed` 雜湊鏈稽核，不去重；列表與拒絕依檢視者、員工、篩選或原因每分鐘去重。稽核只放本機對話 HMAC 與計數，不放對話文字或外部平台 ID。寫不進去就回 `audit_unavailable`，不附內容。每人每行程查看上限 20 次／分鐘、120 次／小時，列表 300 次／小時；超過回 `rate_limited` 和可重試秒數。遮蔽期間若改報告線，傳回前會改成拒絕。

遮蔽計數只算選取與截斷後實際回傳的片段，編號仍依完整可見時間窗。開機時稽核失敗只封住團隊檢視，gateway 其他功能照常；修好後必須建立新時間窗。資料庫連重設旗標都寫不進去時，行程內仍保留封鎖狀態，直到能完成修復。遮蔽最多容納八個請求，等候入場最多三秒，實際 worker 維持一個。
