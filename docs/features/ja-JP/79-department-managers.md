# 部門マネージャーとメイン AI スタッフの利用者リスト

v1.86.0 から、エンタープライズ版の Admin は、有効な Manager に対し、指定部門の AI スタッフを管理する機能を個別に付与できます。Manager ロールやメンバー情報の部門名だけでは、この権限は付きません。

[English](../79-department-managers.md) · [繁體中文](../zh-TW/79-department-managers.md)

## 権限の付与

初期状態では誰にも付与されていません。Admin が Manager、部門、機能をそれぞれ選びます。機能はスケジュール、自動化ルール、スキル、使用量、外部送信データの審査です。

権限の追加・拡大には、リスク説明を読み、**理解しました**（「我了解」）にチェックする必要があります。取り消しにはチェックは不要です。付与と取り消しはすべて監査記録に残ります。ロール変更、停止、削除などにより有効な Manager でなくなると、部門権限は自動的に取り消されます。

部門権限はダッシュボードにログインしている間だけ有効です。個人 API キーやチャットアプリには適用されません。会話履歴、記憶、ファイル、スタッフ設定へのアクセスや、会話・通常業務の依頼権限は増えません。

## 機能ごとの範囲

### スケジュール

| 部門内でできること | この権限でできないこと |
|---|---|
| 定期業務、リマインダー、予約依頼の閲覧と管理。プロンプトのみの定期業務の作成と、対応する操作がある項目の編集、一時停止、再開、削除、即時実行。リマインダーの取り消し、予約依頼の一時停止、再開、削除。 | メイン AI スタッフの予約、コマンドやワークフローを使う定期業務の作成、既存の入力・スタッフの利用可否・実行チェックの回避。リマインダーや予約依頼の一覧に作成・編集操作を追加する権限ではありません。 |

### スキル

| 部門内でできること | この権限でできないこと |
|---|---|
| スキルの閲覧、有効化、無効化、削除、復元、スタッフ向けのインストール申請。インストールには Admin の承認が必要です。 | 直接のインストール、スキル内容の追加・編集、共有スキルの公開・採用。 |

### 使用量

| 部門内でできること | この権限でできないこと |
|---|---|
| スタッフ別の使用量、その合計、最近の記録の閲覧。部門使用量画面では７日、３０日、９０日を選べます。 | この表示から他部門を閲覧すること、予算の変更。 |

### 自動化ルール

| 権限のある部門でできること | この権限でできないこと |
|---|---|
| 部門ルールの一覧、作成、編集、有効化、無効化、削除、履歴の閲覧。業務の委任とスキル実行の対象は同じ部門のスタッフのみです。通知先はルール所有者の検証済みダイレクトメッセージ、または部門スタッフの通知先に限られます。 | ルールの部門変更、全社ルール・ブレーカー・定期監視ソースの管理、イベントシーケンスや自動帰納ルールの利用。メイン AI スタッフと個人専用スタッフは対象にできません。 |

部門ルールのトリガーは、タスク作成、タスク更新、タスクの状態変更の３種類のみです。ダッシュボードで行ったタスク変更だけが対象で、AI スタッフ自身が報告したイベントでは起動しません。新しい活動記録、チャネルメッセージ、アイドル状態、実行のリスク検出は対象外です。承認が必要な動作は、引き続き Admin が判断します。

ルールの起動時に部門の範囲を確認してから、条件の評価、スクリーニング、承認、動作へ進みます。各動作の直前と承認後も再確認します。他部門のイベントは通知せず無視します。対象や通知先が部門を離れていた場合は、「部門範圍不符，已略過」（部門の範囲に一致しないためスキップ）と記録してスキップします。キューに入った業務も、振り分け前と実行直前に、ルールがその部門で有効かどうかを含めて再確認します。所有者の検証済みダイレクトメッセージは、所有者が有効な Admin、またはその部門の自動化権限を持つ有効な Manager である間だけ通知先として認められます。資格を失うと対象外になります。実行結果や承認の通知前にも、ルールと受信者の資格を再確認します。

### 外部送信データの審査

Admin は、有効な Manager に部門ごとに外部送信データの審査権限を付与できます。Manager はダッシュボードでのみ、対象部門の AI スタッフの外部送信承認カードを開き、承認または拒否できます。そのカードでは Admin と同じ完全な引数を閲覧できます。自分の代理で提出された要求は決定できません。Manager 自身の個人専用スタッフを含め、個人専用スタッフはすべて部門権限の対象外です。

一覧、タイムライン、通知には要求内容を含まない固定の要約だけを表示します。権限のある審査者がカード表示を開くと、完全な内容を閲覧できます。Admin 以外が開くたびに、先に監査記録を書き込みます。書き込めない場合は開けません。決定の監査記録には審査者の種類を記録します。この記録の書き込みはベストエフォートで、承認レコードにも決定者を保持します。

カードの通知先は、有効な Admin と、そのスタッフの部門で審査権限を持つ有効な Manager だけです。初回と各リマインダーの送信直前に、現在のロールまたは権限と、検証済みダイレクトメッセージの正確な宛先を再確認します。不一致や読み取り不能の場合は、その受信者への送信を通知せずスキップします。チャットでの決定は引き続き Admin 専用です。この権限はチャットや個人 API キーでは使えません。[外部送信データの保護](69-egress-guard.md)も参照してください。

## 部門に含まれるスタッフ

正式な組織図の部門記録と、スタッフ自身の部門設定が一致している必要があります。不一致の場合、権限は適用されず、Admin による組織同期が必要と表示されます。スタッフ自身の設定変更だけで Manager の範囲が広がることはありません。メイン AI スタッフとすべての個人専用スタッフは部門権限の対象外です。所有者は既存の紐付けにより自分の個人専用スタッフを引き続き管理できます。

組織図の移動が Manager の管理範囲を変える場合、変更の要約に、誰がどの権限を得るか・失うかを表示します。承認時に再確認し、Admin が確認した後に影響が変わっていれば、再度の確認が必要です。組織同期でも影響を表示します。

## 取り消し後の既存業務

権限を取り消しても、Manager が作成した定期業務やルールは自動停止・削除されません。定期業務は既存の実行チェックに従って継続します。ルールの有効状態は保存され、上記の部門チェックに従って実行されます。不要な業務は Admin が別途無効にしてください。

定期業務と予約依頼の一覧には、確認できる場合に **作成者は権限を失っています**（「建立者已無權限」）の情報が付きます。ゲートウェイはこの情報を提供しますが、ダッシュボードでの表示は統合待ちです。自動化ルールには、まだ同等の表示はありません。

## メンバーによるルールの閲覧

ダッシュボードにログインしたメンバーは、自分が閲覧できるスタッフに業務を委任したりスキルを実行したりする全社・部門ルールを読み取り専用で閲覧できます。条件、表示可能な対象、プロンプトテンプレートまたはスキル名、承認の要否、直近２０件のトリガー時刻と結果を含みます。編集権限は付きません。通知先と通知文、他のスタッフ、履歴の詳細は表示しません。保護モードでは、他人の個人専用スタッフを指定するルール全体を非表示にします。

## メイン AI スタッフを利用できる人

エンタープライズ版の利用者リストは初期状態では空で、Admin だけが利用できます。Admin は有効なメンバーを追加し、会話と、予約ではない通常業務の依頼を許可できます。追加前にリスク説明を読み、**理解しました**にチェックします。変更は監査記録に残り、アカウントの停止・削除時にはリストから除かれます。

リストは、スタッフの処理を隔離実行する保護モードでのみ有効です。それ以外では、これらの入口から利用できるのは Admin だけです。設定の応答には、保存済みリストが無効な理由が表示されます。コマンドツールの削除だけでは有効になりません。個人 API キーでは、リストにある人も Admin もメイン AI スタッフを利用できません。

追加された人は、Admin との会話を含め、メイン AI スタッフが覚えている内容を質問できる可能性があります。追加前にこのリスクを確認してください。メインスタッフの予約、スタッフの作成、スタッフ設定の変更は Admin 専用です。リスト上の非 Admin メンバーのために働く際、管理用ツールは使えません。試行すると「この操作は管理者本人が行う必要があります。」（「這個動作需要管理員本人操作。」）と拒否します。

メインスタッフは、他のスタッフに仕事を渡すことがあります。その委任には、通常のスタッフ間委任ルールが適用されます。委任時に依頼者本人の権限も確認するため、`[delegation] human_principal = "enforce"` を推奨します。

## 既知の制限

- メイン利用者リストは保護された隔離実行環境だけで有効です。リストの保存で隔離が有効になることはありません。
- 全社の分析と請求の集計は、引き続きすべての Manager に表示されます。部門使用量権限で既存の集計範囲は狭まりません。
- 定期業務、スキル、部門使用量の画面は対応済みです。メンバー画面の部門権限編集、メインスタッフの「利用できる人」、部門ルールとメンバーの閲覧画面は、ダッシュボードへの統合待ちです。ゲートウェイは関連する権限と設定に対応しています。[ダッシュボード設定](../../guides/ja-JP/dashboard-settings.md)を参照してください。

## 開発者向け

部門設定：`users.dept_grants.list`、`users.dept_grants.set`、`users.dept_grants.options`、`users.dept_grants.mine`、`users.dept_grants.reach_preview`。メイン利用者リスト：`agents.main_access.get`、`agents.main_access.set`。部門使用量：`cost.department_summary`、`cost.department_recent`。メンバーのルール閲覧：`autopilot.affecting_me`。
