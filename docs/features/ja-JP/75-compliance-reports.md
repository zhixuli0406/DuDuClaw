# 企業版コンプライアンス報告

企業版の管理者は **監査ログ → コンプライアンス報告** から、外部送信ゲートの判断、承認、行動レビュー、記録済みのデータソースアクセスをダウンロードできます。台湾の個人資料保護法に関する内部点検の証拠整理を支援しますが、法令適合を認証・保証するものではありません。

## 報告を作成する

1. **監査ログ** で **コンプライアンス報告** を開きます。
2. 開始日と終了日を選びます。どちらも台北の日付で、終了日全体を含みます。報告の時刻は UTC、検索区間は `[from, until)` です。期間の上限は366日です。
3. CSV、Excel（`.xlsx`）、印刷用 HTML を選びます。PDF が必要な場合はダウンロードした HTML をブラウザーで開き、**印刷 → PDF に保存** を使います。項目名はダッシュボードの言語に合わせて繁体字中国語、英語、日本語で表示します。
4. 既定では **マスク前の個人情報を含める** はオフです。管理者が明示的に選択した場合のみ、元の記録に残っている値を含めます。マスクの有無にかかわらず出力を監査に記録し、記録に失敗するとファイルを返しません。
5. **作成してダウンロード** を選びます。10,000行の上限はすべての節の合計です。同じ承認が外部送信と承認の両方の節に表示される場合は2行として数えます。行数やデータ量の上限を超える場合は、切り捨てずに要求を拒否します。期間を短くして再試行してください。

管理者以外と個人版にはボタンを表示しません。ゲートウェイでも現在の管理者権限と解決済みの版を確認するため、URL の変更や RPC の直接呼び出しでも回避できません。従業員向けの報告生成 MCP ツールはありません。

## 証拠を読み取る

報告は集計件数と、外部送信判断、承認、行動レビュー、記録済みのデータソースツール呼び出しおよび検出・マスキングイベントの各節で構成されます。アクセスの節は完全なアクセス一覧ではありません。記録済みの `db_select`、`db_query`、`db_tables` 呼び出しはメタデータのみを含み、SQL や問い合わせ結果は含みません。外部送信の行には記録された時刻、従業員、宛先チャネルまたはホスト、データ分類、判断、承認者、理由を含みます。承認の行には種類、申請者、判断者、判断、時刻を含みます。記録されていない項目は空欄です。承認は現在の状態のスナップショットで、過去の状態は復元しません。判断時刻が選択期間外の場合は `decision_outside_range`、判断時刻が未記録の場合は `decision_time_unrecorded` と表示します。いずれも、その期間中に適用されていた判断を推測するものではありません。

**ゲートの判断は送信完了の証明ではありません。** 承認が失効したり、その後にツールが失敗したりする場合があります。拒否された要求も、データが外部に出たことを示しません。報告は欠けた履歴を復元せず、未記録のアクセスを補完せず、メッセージ本文から分類や承認者を推測しません。記録されなかった情報、ローテーション済みの情報、元の保存方針で削除された情報は表示できません。0件と判断する前に、報告のデータソースと保存に関する注記を確認してください。

既定では人物の項目に報告内で一貫した仮名を使い、宛先と理由は項目全体をマスクします。他のテキストには既存エンジンの `general` と `taiwan_strict` ルールを適用します。検出には限界があり、未知・変形された個人情報が残る場合があります。完全な値を選択した場合も認証情報はマスクし、保存前にマスクされた値は復元できません。当時の非公開データの元の内容を出力・復元する機能ではありません。

## 保存と取り扱い

報告には保存に関する注記を含みます。生成によって元の記録の保存期間を延長したり、新しい個人情報利用の根拠を設けたり、元の記録を削除したりしません。生成ファイルはブラウザーに直接ダウンロードされます。コピーには組織のアクセス制御、利用目的、保存方針を適用してください。マスクのない報告は元の個人情報と同様に保護してください。

管理者 RPC は `compliance.generate` です。RFC3339 の `from`、`until` と `format`（`csv`、`xlsx`、`html`）は必須で、`language`（`zh-TW`、`en`、`ja-JP`、既定 `zh-TW`）と `include_personal_data`（既定 `false`）は省略できます。上限時刻は含みません。成功応答はファイル名、コンテンツ型、base64 のファイル内容、件数を返し、永続的な共有添付は作成しません。

適用される保護範囲は [セキュリティ防御](05-security-defense.md) と [外部送信データ保護](69-egress-guard.md) を参照してください。

報告の読み取りと監査の書き込みは、ローテーションと追記を含むプロセス間ロックを共有し、出力中の世代切り替えによる読み落としを防ぎます。保持されたツール監査の両世代は、報告に使うサイズ制限付きの同じスナップショットでハッシュチェーンを検証します。チェーン破損、不正なレコード、読み取りやロックの失敗時は出力を拒否します。有効な旧形式の接頭レコードは読み取れますが、個別の真正性は検証できません。ハッシュチェーンは末尾の完全性や外部の信頼できる基準に対する真正性を証明しません。
