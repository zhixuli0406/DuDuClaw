# @ で AI スタッフを呼び出す

普段の会話は既定の AI スタッフが返信します。メッセージを 1 件だけ別のスタッフに渡したいときは、メッセージアプリで人をメンションするように `@` と名前を入力します。v1.76.0 から、呼び出せる相手は送信者によって決まり、メッセージは 1 件ずつ振り分けられます。

## メッセージの振り分け

1. 誰も呼んでいないメッセージは、その会話の既定のスタッフに届きます。チャンネルやスレッドに紐付いたスタッフ、なければ `allowed_channels` にそのチャネルを含むスタッフ、それもなければメインのスタッフです。ダッシュボードの WebChat では選択中のスタッフが既定です。
2. スタッフを呼んだメッセージは、そのスタッフに**その 1 件だけ**届きます。名前のない次のメッセージは既定のスタッフに戻ります。固定はされません。
3. `@トリガー`（`[agent] trigger` の値）、`@表示名`、`@ID` で呼び出せます。大文字小文字は区別せず、名前の直後に日本語や中国語が続いても認識します（`@財務小幫手幫我算帳`）。全角の `＠` も使えます。メールアドレス（`ann@example.com`）は呼び出しになりません。
4. 複数の名前が当てはまるときは最も長いものを採ります（`@財務小幫手` は `@財務` より優先）。複数のスタッフに触れているときは、本文で最初に出てくる、呼び出せるスタッフが選ばれます。
5. 名前の一部（`@財務`）や、同じ名前のスタッフが 2 人いる場合は、黙って誰かに渡さず候補の一覧を返します。
6. `@` がなければ切り替わりません。

## 誰が誰を呼び出せるか

| 送信者 | 呼び出せる相手 |
|---|---|
| ダッシュボード管理者 | 全員 |
| WebChat のダッシュボードアカウント | アカウントに紐付いたスタッフ（権限レベルは問わない） |
| ダッシュボードアカウントに紐付いたメッセージアプリの利用者（確認済みのチャネル ID） | 紐付いたスタッフ、その会話の既定のスタッフ、外部公開されたスタッフ |
| それ以外（LINE の友だち、Telegram ユーザー、サイトのチャット訪問者） | その会話の既定のスタッフと外部公開されたスタッフ |

スタッフを外部の連絡先に公開するには、編集ページで「外部の連絡先がこのスタッフを呼び出せるようにする」をオンにします（`agent.toml` の `[channels] public_trigger = true`）。既定はオフで、管理者だけが変更でき、スタッフ自身は変更できません。

呼び出す権限のないスタッフを呼ぶと、モデルを呼ぶ前に拒否されます。返信は権限がないことだけを伝え、スタッフ名は出しません。ただし、その名前がいずれかのスタッフのものであることは分かります（誰にも当てはまらない名前は普通の文として既定のスタッフに届きます）。拒否はセキュリティ監査ログ（`trigger_route_refused`）に記録されます。記録するのはダッシュボードアカウント、紐付けのない送信者は短いダイジェストだけで、プラットフォームの生の ID は残しません。許可された切り替えは info ログに出ます。

既定のスタッフに紐付いていない WebChat アカウントが誰も呼ばないメッセージやチャットコマンド（`/goal`、`/status` など）を送ると拒否され、スタッフを選ぶか `@` を入力するよう案内されます。WebChat で呼ばれたスタッフの回答は、選択中のスタッフではなく、そのスタッフ自身の会話履歴に残ります。

同じ送信者が同じスタッフへの拒否を繰り返しても、監査記録は 1 分に 1 件です。

## @ 一覧

- **WebChat**：入力欄で `@` を打つと、呼び出せるスタッフ（アバター・名前・部署）が表示され、入力に合わせて絞り込みます。矢印キーで移動、Enter または Tab で `@名前 ` を挿入、Esc で閉じます。今の相手以外のスタッフが答えた返信には、誰が答えたかが表示されます。
- **LINE**：`@` だけ（または `@` と名前の一部）を送ると、クイックリプライのボタンで一覧が返ります。一度に最大 13 個で、多いときは最後の「更多」で次のページを表示します。名前をタップすると `@名前` が送信されます。
- **Telegram**（共有 bot）：同じ一覧をインラインボタンで表示します。
- その他のチャネルはテキストで一覧を返します。

一覧・拒否・「用件を伝えて」の案内は、AI の返信と同じアクセス制御（ブロック・ペアリング）と有人対応のチェックを通ってから送られます。

## 先に呼んでから用件を伝える

メッセージアプリ（LINE、Telegram、Discord、Slack など）で `@名前` だけを送るか、LINE・Telegram の一覧で名前をタップすると、bot が「請說要交給「名前」的事」と返します。10 分以内の**その会話での次の 1 件だけ**がそのスタッフに届き、その後は通常の振り分けに戻ります。そのメッセージが届いた時点で権限を再確認します。同じグループの他のメンバーのメッセージには影響しません。

この待機状態はメモリにだけ保存されます。ゲートウェイを再起動すると消え、次のメッセージは既定のスタッフに届きます。待機中にすでに受け付けた LINE のメッセージは、別のスタッフが答えないよう隔離されます（`account_route_authorization_changed`）。

## グループの「メンションのみ」

- **LINE**：「メンションのみ」をオンにすると、`@` でスタッフを呼ぶメッセージ（または @ 一覧の要求）と、呼ばれたスタッフが待っている 1 件にだけ返信します。v1.76.0 より前はグループ全体が無反応になっていました。LINE は引用されたのが bot 自身のメッセージかを bot に知らせないため、bot のメッセージの引用は対象外です。
- **Telegram**：共有 bot はメンションのみのグループで、自分の `@ユーザー名` と返信に加え、スタッフ名も受け付けます。スタッフ専用 bot は自分の `@ユーザー名` のみです。

## 誰が答えたか

- WebChat の返信フレーム（`assistant_done`）に `agent`（ID）と `agent_name` が入ります。
- LINE と Telegram では、既定以外のスタッフの返信の先頭に `【名前】` が付きます。既定のスタッフには付きません。LINE の吹き出しの見出しは答えたスタッフの名前になりました（以前は常にメインのスタッフ）。
- 行動契約（`CONTRACT.toml`）のチェックと機密の復元は、実際に答えたスタッフとして行います。

## 対象外

- Discord・Slack などのチャネルも同じ規則・テキスト一覧・先に呼ぶ方式を使いますが、ボタンはありません。エンドツーエンドの実地テストは WebChat と LINE のみで、Telegram は単体テストだけです。
- その他のチャネルの送信者がダッシュボードアカウントに対応付けられるのは、チャネルのログインで確認済みの ID だけです。
