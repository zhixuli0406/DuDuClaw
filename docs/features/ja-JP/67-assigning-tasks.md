# チャットからタスクを任せる

LINE、Telegram、Discord、Slack、dashboard の WebChat の会話で `/交辦 @AIスタッフ 内容`（`/assign`、全角の `／交辦` も可）と送ると、gateway があなたの代わりにその AI スタッフの目標タスクを作成します。進捗と結果は同じ会話に届きます。v1.76.0 から。

`@名前 内容` でスタッフを呼ぶのはこれまでどおり通常の会話です（[`@` で AI スタッフを呼び出す](62-calling-ai-staff.md)）。タスクを作るのはこのコマンドだけです。

## コマンド

| 送る内容 | 結果 |
|---|---|
| `/交辦 @業務專員 整理報價單` | そのスタッフの目標タスクを作成し、返信にタスク番号が入ります。 |
| `/交辦 @業務專員 整理報價單 \|\| 含三家比價 \|\| 時限:24h` | `/goal` と同じ `\|\|` 区切り：受け入れ基準、`時限:`／`duration:`（1〜720 時間、`24h`、`3天` など）、`邊界:`／`risk:`（してはいけないこと）、`想一想`／`plan`（先に計画を作り、dashboard での承認を待つ）。基準を書かない場合はタスク内容がそのまま基準になります。 |
| `/交辦` | タスクを任せられるスタッフの一覧。LINE ではクイックリプライのボタンになり、押すと `/交辦 @名前` が送られます。 |
| `/交辦 @業務專員` | bot が内容を尋ねます。その会話での**あなたの次のメッセージだけ**がタスクになります（10 分以内）。その次からは通常の会話です。次のメッセージで `@` を使って別の人を呼ぶと待機は取り消されます。 |
| `/交辦 狀態`（`/assign status`） | 任せた未完了のタスク（最大 20 件、新しい順）を、スタッフ・状態・タイトル付きで表示します。 |
| `/交辦 @名前の一部 …` | 名前が途中まで、または複数に一致するときは、該当して任せられるスタッフを表示します。 |

Telegram のグループでは `/assign@あなたのBot …` が使えます。Slack のスラッシュコマンドは `/duduclaw assign …` で、返信は本人にだけ表示されます。

確認メッセージの例：

```
📌 已交辦給【業務專員】，任務 #1a2b3c4d
內容：整理報價單
（依組織關係交辦：王小明的 AI 員工）
進度和結果會回到這個對話。輸入「/交辦 狀態」查看你交辦的任務。
```

かっこの行は、任せる権限が組織関係から来ている場合だけ表示されます。メッセージアプリ側の文言は `[general] default_language`（繁体字中国語・英語・日本語）に従います。

## 誰が誰に任せられるか

| 送信者 | 任せられる相手 |
|---|---|
| dashboard 管理者 | 稼働中のすべてのスタッフ |
| dashboard アカウント（WebChat にログイン中、または検証済みのチャネル ID でアカウントに連携したメッセージアプリの送信者） | アカウントに Owner か Operator で紐付いたスタッフ。マネージャーは、部下経由の権限が Operator に達するチームのスタッフにも任せられます |
| 同じアカウントで、相手が Viewer で紐付いたスタッフ・会話の既定スタッフ・外部連絡先に公開されたスタッフの場合 | 任せられません。会話はでき、bot はタスクを任せる権限がないと答えます |
| それ以外（LINE の友だち、Telegram のユーザー、Web ウィジェットの訪問者） | 任せられません。どの名前を書いても、まず dashboard でメッセージアカウントを連携するよう案内します（**個人設定 → チャネル ID**）。返信からスタッフの有無はわかりません |

dashboard アカウントがまったく届かないスタッフを指定した場合は、`@` 呼び出しの拒否と同じ返信になります。権限はコマンドごとにその場で読み取り、`/交辦 @名前` のあとで待っていたメッセージが届いたときにも再確認するので、紐付けやマネージャーの変更はすぐ反映されます。

タスクは gateway が直接書き込み、AI モデルは介在しません。個人版には他のアカウントがないため、オーナー（管理者）は通常どおり `/交辦` を使えます。

## タスクに記録される内容

| 項目 | 値 |
|---|---|
| `assigned_to` | スタッフ |
| `on_behalf_of` | `user:<あなたの dashboard アカウント ID>`。検証済みの ID から取り、メッセージ本文からは取りません |
| `created_via` | チャネル（`line`、`telegram`、`webchat` など） |
| `created_by` | `assign:<チャネル>` |
| `source_channel`、`source_chat_id` | この会話。目標タスクの進捗（開始、各ラウンド、判断待ち、完了）がここに届きます |
| `kind` | `goal` |

以前のタスクには `on_behalf_of` がなく、後から埋めることもしません。dashboard で作成したタスク（`tasks.create`、目標の依頼）も `created_via = dashboard` で記録され、連携済みアカウントがチャットで送った `/goal` もアカウントを記録します（権限のルールは変わりません）。

スタッフが作業するとき、作業プロンプトには依頼者の表示名と部署だけが入り（例：`交辦人: 王小明（業務部）`）、アカウント ID は入りません。

LINE ではタスク ID を webhook のイベント ID から決めるため、LINE が webhook を再送しても、永続受信が同じメッセージを再実行しても、タスクが二重にできることはありません。

## 進捗の確認

- メッセージアプリでは進捗が会話に届き、`/交辦 狀態` で未完了のタスクを確認できます。
- WebChat では返信にタスクカードが付き、**進捗を見る** で「目標」ページの「自分が任せた」が開きます。WebChat には進捗の通知は届きません。
- 「目標 → 自分が任せた」（`tasks.list_page` に `on_behalf_of: "me"`）は、スタッフを問わず任せたタスクをすべて表示します。部下経由でしか届かないスタッフでも、タスクの内容（説明・基準・結果）を見られます。「me」はサーバーがログイン中の ID から決め、ここに他のアカウント ID を入れても無視されます。タスク詳細ページは引き続きそのスタッフへの直接の紐付けが必要です。

## グループ

グループでも任せられますが、連携済みアカウントに限られます。また**コマンド、確認メッセージ、すべての進捗通知がグループの全員に見えます**。LINE グループで「メンションのみ」がオンのとき、`/交辦` と `/assign` は bot への呼びかけとして扱われ（他のコマンドは引き続きメンションが必要）、`/交辦 @名前` のあとで待っている 1 件のメッセージも同様です。

## 監査ログ

- `human_assign`（Info）：タスクを作成するたびに、チャネル、送信者（`user:<アカウント ID>`）、タスク ID、権限の出どころ（`via`：`binding`、`team:<部下のアカウント ID>:<階層>`、`admin`）を記録。
- `human_assign_refused`（Warning）：拒否のたびに理由（`needs_identity`、`call_only`、`denied`）を記録。未連携の送信者はプラットフォーム ID の HMAC で記録します。同じ送信者・同じスタッフ・同じ理由の繰り返しは 1 分に 1 回だけ記録します。
- タスクの `goal_loop.created` アクティビティの metadata に `on_behalf_of`、`created_via`、`via` が入ります。

## 制限

- `/交辦 @名前` のあとの待機はメモリ上だけにあり、gateway を再起動すると消えます。LINE で次のメッセージを受け付けてから処理するまでの間に再起動した場合、そのメッセージは通常の会話として既定スタッフに渡ります。
- WebChat で任せたタスクの進捗はチャットに届きません。「目標」ページで確認してください。
- Discord、Slack、webhook チャネル（WhatsApp、Feishu、Teams、WeCom、Google Chat、DingTalk）はテキストのみで返します。エンドツーエンドで確認したのは LINE と WebChat だけです。
- 部下経由でしかスタッフに届かないマネージャーは、「自分が任せた」一覧と `/交辦 狀態` ではタスクの内容を見られますが、タスク詳細ページでは見られません。
