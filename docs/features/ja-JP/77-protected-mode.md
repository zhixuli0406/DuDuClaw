# ネイティブ Linux 保護モード（v1.82.0 で提供予定）

> **状態：v1.82.0 で提供予定。v1.81.0 では利用できません。** コードは v1.81.0 に含まれていますが、お客様のホストではまだインストールも有効化もできません。
>
> v1.81.0 での動作：`sudo duduclaw service install --protected-linux` は v1.80 と同じ単一実行ファイルの保護サービスをインストールし、`sudo /opt/duduclaw/bin/duduclaw service upgrade --protected-linux` で更新します。AI スタッフの作成と実行は v1.80 と同じです。詳しくは[単一実行ファイルの保護サービス](../../guides/ja-JP/linux-protected-service.md)を参照してください。
>
> 以下の内容（設定の管理ページ、個人用と共有のスタッフ、スタッフ専用のコネクタアカウント、退役と復元、v1.79.3 からの移行）は、提供予定のリリースについての説明です。

保護モードでは、ネイティブ Linux ホスト上の AI スタッフがそれぞれ専用のアカウントと独立した実行環境で動きます。会話、記憶、ファイル、接続、権限はそのスタッフの中に留まり、gateway 自身のアカウントは貸し出されません。隔離サービスや信頼できるポリシーが欠けている場合、スタッフの作業は拒否され、gateway アカウントでの実行に切り替わることはありません。

この機能は標準では無効で、Enterprise 版のみ利用できます。使用していないインストールの動作は変わりません。実際の Linux ホストでの検証はまだ完了していません（[実機が必要な項目](#実機が必要な項目)を参照）。

## 有効にする手順（v1.82.0 で提供予定）

以下の手順は、隔離コンポーネントをインストールできるようになってから使えます。v1.81.0 では手順 1 で止まります。インストーラーは単一実行ファイルの保護サービスだけを設定し、準備状況は隔離の準備完了を報告せず、管理ページも表示されません。

1. 対応ホスト（Ubuntu 22.04、Ubuntu 24.04、Debian 12。x86_64 または ARM64）で `sudo duduclaw service install --protected-linux` を実行して保護サービスをインストールします。手順は[保護サービスガイド](../../guides/ja-JP/linux-protected-service.md)にあります。
2. `sudo duduclaw service readiness --protected-linux` を実行します。ダッシュボードの準備状況バナーは、保護された作業を止めている原因（アカウントまたは接続の設定が未完了、認可の取り消し、サービスの一時停止）を示し、サポート参照番号を表示します。
3. システム状態が保護モードの準備完了を報告すると、Admin に「設定 › 保護モード」が表示されます。AI スタッフ、コネクタアカウント、Google テナントソース、記録の 4 つのタブがあります。
4. 既存のスタッフは Admin の移行確認ページから取り込みます。各提案はパスワードと二要素認証の確認後に承認、拒否、再試行でき、低リスクの提案は一括処理できます。

ホストを正式に採用する前に、[検証手順書](../../guides/ja-JP/linux-protected-acceptance.md)を実行してください。

## 個人用スタッフと共有スタッフ

| | 個人用 | 共有 |
|---|---|---|
| 所属 | 1 人の同僚（オーナー） | 1 つのテナント |
| 利用できる人 | オーナーのみ | テナントのメンバー（通常のロールに従う） |
| 作成方法 | 同僚が「マイアカウント」で申請（1 人あたり未処理は最大 3 件）。Admin がパスワードと二要素認証の確認後に設定を整え、承認カードで確定します。Admin が直接提案することもできます | Admin が提案し、承認カードで確定します |
| 接続 | オーナー自身のアカウント | テナントのアカウントと、許可されたホスト側の接続 |
| バックグラウンド作業（スケジュール、リマインダー、定期チェック） | 利用不可 | Admin の承認後に利用可（24 時間以内に判断、認可は最長 30 日） |
| 他の人からの呼び出しと割り当て | Admin を含め、他の人は作業を割り当てられません。オーナーが「公開呼び出し」を有効にした場合のみ `@` で呼び出せます | 通常の委任ルールに従う |
| Admin に見えるデータ | 基本情報のみ | 通常どおり |

保護モードでは AI スタッフを直接作成できません。すべてのスタッフは申請または提案と、その承認を経て作られます。

### 個人用スタッフのデータを見られる人

会話と実行記録、記憶、設定ファイル、スタッフ自身の Wiki、タスクの内容、ファイル、承認の内容はオーナーのものです。マネージャーは部下を通じてこれらを取得できません。オーナーでない Admin は、パスワードと二要素認証で本人確認をやり直した場合（5 分間有効）にのみ読み取れ、読み取りのたびに Admin、スタッフ、オーナー、データ種別が記録されます。スタッフをまたぐ一覧や検索にはこれらのスタッフは表示されず、他の AI スタッフが個人用スタッフの設定、スキル、Wiki、メールボックスを変更、削除、読み取りすることもできません。

## 退役、復元、引き継ぎ、消去、解放

| 手順 | 内容 |
|---|---|
| 退役 | Admin が個人用または共有スタッフを退役させます。スタッフは直ちに停止し、実行中の作業は中止され、コネクタアカウントは取り消され、データは隔離領域に 90 日間封印されます。スタッフ名もこの 90 日間は予約されたままです。 |
| 復元（個人用） | オーナーが、退役前から設定していた最も強い第二要素で申請します（検証の失敗はログインのロックアウトに数えられます）。Admin がパスワードと二要素認証の確認後に承認し、承認者は申請者とは別の、資格を満たす Admin でなければなりません。資格を満たす Admin が申請者本人だけの場合は、7 日間のクールダウン後に自分の申請を承認でき、承認は記録されます。第二要素を持たないオーナーは自分で申請できず、Admin が代わりに申請します。オーナー自身によるパスワード、メール、二要素認証の変更は本人の変更として扱われ、他の人が変更していた場合は復元が拒否されます。退役後にオーナーのセッションを取り消しても、復元は妨げられません。 |
| 復元（共有） | Admin が申請し、退役時のメンバー名簿から復元するメンバー（権限は維持または引き下げのみで、引き上げは不可。無効化または退職したメンバーはスキップされ一覧表示）と、再承認するテナント共有の接続を選びます。別の Admin が承認します。選ばれたメンバーと接続だけが有効になり、他のメンバーは再度バインドが必要で、スタッフ専用の接続は再設定が必要です。スケジュールとタスクは停止したままです。復元された各メンバーには通知が届きます。 |
| 復元後 | Web サイトの資格情報の認可と他のスタッフとの報告関係は一覧表示のみで、Admin が 1 件ずつ再認可します。自動では戻りません。 |
| 新しいスタッフへの引き継ぎ | 旧スタッフのリソースが消えたことをホストが確認した後、オーナー（個人用、自分自身にのみ）または Admin（共有、同じテナント内のみ）が、退役したスタッフから新しいスタッフを作れます。引き継がれるのは SOUL.md、CONTRACT.toml、agent.toml、SKILLS と、絞り込まれた設定（拒否リストと確認リスト、モデル）だけです。記憶、会話、タスク、スケジュールは隔離領域に残り、旧スタッフのトークンと認可は無効になり、ホストのワークスペースはコピーされません。途中で失敗した場合、ファイルは隔離領域に戻され再検証されます。 |
| 消去 | 90 日経過後、Admin はパスワードと二要素認証の確認後に隔離領域を消去できます。90 日未満の場合は確認にチェックを入れて「早期消去」を申請し、別の Admin が承認します。承認時に内容を再比較し、変更があれば再申請が必要です。消去すると、隔離領域のファイル、スタッフの記憶、会話、スケジュール、タスク、保持中の Web サイト資格情報の認可が削除されます。新しいスタッフが引き継いだデータには影響しません。 |
| ホストリソースの解放 | 消去後、Admin はホスト側を解放できます。ホストのワークスペースを消去し、アカウントを無効化し、スタッフコードを解放します。UID は再利用されません。解放は開始すると取り消せず、完了まで再試行するだけです。 |

申請や消去が行われると、オーナーと Admin に通知されます（オーナーまたはテナントごとに 1 日最大 5 件）。監査ログにはアーカイブのダイジェスト、ファイル数、サイズが残ります。中断された消去は次の操作または再起動で完了します。ホストに接続できない、記録が一致しない、作業がまだ実行中といった場合、その手順は拒否されるか後で再試行されます。

**アップグレード後の最初の 7 日間。** 承認資格は Admin の状態の 7 日分の記録で判断され、この記録はアップグレード時から始まります。この 7 日間は、復元、消去、解放のいずれも承認できません。

## 保護されたスタッフにできること

- 自分の環境内でプログラムの実行、コード分析、Office スクリプトの実行を行い、結果は同じ呼び出しで返ります。キャンセルや接続切断で終了するのはその呼び出しだけです。
- 認可された自分のワークスペースからファイルを読み取ります。
- 文書、スプレッドシート、画像、Web ページ、専門家 ZIP パックは、リソース上限のある別のサービスで解析され、出力を検証してから返されます。
- 公開 Web ページの取得と抽出は、Admin がスタッフの `agent.toml` の `[isolation]` に `public_web = true` を設定した場合のみ可能です（標準は無効、Admin のみ変更可、設定ファイルまたは Admin の設定エディタで変更）。到達できるのは公開 HTTPS サイトだけで、IP アドレス、URL 内の認証情報、標準以外のポート、内部名、リダイレクトは拒否されます。
- スキルハブからスキルをインストールし（保護された公開ネットワーク経由でダウンロード、隔離された解析サービスで展開してスキャンし、既存の承認を経る）、自分のモデル設定と予算で自分のイベントからスキルを合成します。スキルは自分のスキルフォルダにのみ書き込まれ、同名のスキルは上書きされません。グローバルスキルバンクへの公開には Admin の承認カードが必要です。
- 他のスタッフへの委任や一時アシスタントの作成を行えます。呼び出しごとにスタッフ本人の認可が再確認されます。個人用スタッフが共有スタッフのために働くにはオーナーの承認が必要です。一時アシスタントは元のスタッフとして、元の実行と同じツールだけを使い、元の実行が終わってから開始され、24 時間以内に開始されなければ失効します。
- 自分が提出した探索申請の閲覧と取り下げ、自分のブランチ試行の閲覧と比較ができます。ブランチ試行の作成、選択、終了は次のリリースで提供されます。コストは測定されるまで「取得不可」と表示され、0 とは表示されません。

## ブラウザ録画（標準で無効）

録画にはスイッチがあり、ホストが Chromium を helper サンドボックス内で起動できると実測で確認されるまで無効です。それまでは準備状況に `helper_recording_unsupported` と表示され、録画ツールと「録画からスキルを抽出」は表示されません。スタッフ側でも `public_web` を有効にする必要があります。録画が使えるようになると、成果物には録画終了時に記録されたハッシュが付き、変更されたファイルは読み取り時に拒否されます。生のトレースには機密性の高い画面が含まれる場合があります。停止要求を受けても、録画が終了したとは限りません。

## アップグレードの注意点

- 個人用スタッフ上で、作成者が記録されていない古いスケジュールとリマインダーは、実行時に停止します。オーナーが作り直してください。
- このバージョンより前に承認されたバックグラウンド作業は Admin の再承認が必要で、申請が 1 件自動的に提出されます。
- Admin は他の人の個人用スタッフに暗黙的にアクセスできなくなります。
- 非表示の個人用スタッフが存在する間は、ライブログの追跡を使えません。
- アップグレード前に提出された探索申請は、スタッフからは見えません（Admin には見えます）。
- 録画は標準で無効です。

## 実機が必要な項目

コンポーネント単位のテストは Ubuntu 22.04、Ubuntu 24.04、Debian 12 で root として実行済みですが、全体のフローは未実施です。未完了の項目は、各ディストリビューションでの検証手順書（Ubuntu 24.04 のカーネル 7.0、Landlock ABI 8 の環境を含む）、Google、Notion、GitHub、Odoo の実際のプロバイダーアカウント、録画を有効にする Chromium の実測、退役と解放で root が必要な確認です。これらが通るまでは、保護モードを本番環境の隔離保証として頼らないでください。
