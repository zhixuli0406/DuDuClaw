# ドキュメントナレッジベース

社内文書（就業規則、見積表、製品 FAQ など）を**コレクション**に入れ、コレクションごとに誰が読めるかを決めます。AI 社員はそれを検索し、答えの出典（ページ、スライド、ワークシートの行）を示せます。

現在含まれるもの：保存、取り込み、キーワード検索、`knowledge.*` RPC、アップロード用ルート、読み取り専用の MCP ツール 3 つ、`duduclaw knowledge eval` コマンド、ダッシュボードのドキュメントライブラリ画面と AI エージェントへの割り当て設定。ベクトル（意味）検索、チャネル返信への自動挿入と引用フッターは今後のリリースで提供します。既存の Wiki には影響しません。

---

## ダッシュボードでの操作

サイドバー「会社」グループの**ドキュメントライブラリ**（個人版ではメインの一覧、「メモリ」の次）に、見られるコレクションが並びます。名前、機密度、自分の役割、資料の数と処理中の数を表示します。

1. **コレクションの作成**：マネージャー以上が「コレクションを作成」を押し、名前・説明・機密度を入力します。コードは空欄なら自動で作られます（AI エージェントの設定で使うコードです）。作成直後は自分だけが見られます。
2. **資料の追加**：「資料」タブの「資料を追加」から、ファイルのドラッグ＆ドロップまたは選択（一度に 20 件まで。アップロード中は進み具合を表示し、終わると 1 件ずつ追加済み・既存・拒否の理由を表示）、テキストの貼り付け、公開 Web ページの追加ができます。各資料のラベルが状態を示します：待機中、読み取り中、索引作成中、完了（語句一致）、承認待ち、失敗（理由つき）。処理中の資料がある間は一覧が 3 秒ごとに更新されます。各資料のメニューから元ファイルのダウンロード、読み直し、削除ができます（後の 2 つは編集者以上）。
3. **検索を試す**：質問を入力すると、このコレクションのどの段落がどの順で返るか、それぞれのページや章とともに表示します。結果を開くとサイドの引き出しに元の文章が開き、該当段落が強調され、前後の段落へ移れます。
4. **共有**（オーナーのみ）：右側の選択欄は「メンバー・部署・AI エージェント・チャネル」に分かれ、共有できる相手だけを表示します。メンバーと部署は企業版のみ、AI エージェントは自分が管理するもの（管理者は全員）、チャネルはチャネル全体か、ID を入れて特定のトークルームだけに共有できます。役割メニューはその種類が持てない役割を無効にし、最後のオーナーは外せません。チャネル全体に共有すると警告が出ます。「共有設定を保存」でまとめて保存し、途中で他の人が保存していた場合は再読み込みを求めます。ゲートウェイも保存時に同じルールで確認し、共有できない相手を新しく追加した場合は拒否します（もともと一覧にある相手はそのまま）。
5. **閲覧記録**（オーナー）：日時、誰が（メンバー、誰の代理の AI エージェントか、チャネル上のアカウント未連携の人）、何をしたか、何を質問したか、何段落返ったか。
6. **設定**（オーナー）：名前、説明、部署ラベル、機密度、「このコンピューター内だけで処理」（今後の意味検索でこのコレクションを外部サービスへ送らない）、名前を入力して確認したうえでのコレクション削除。

管理者にはドキュメントライブラリのページ右上に「拒否された閲覧」があり、全コレクションで拒否された閲覧を一覧できます。

**AI エージェントにコレクションを使わせる**：まずコレクションの共有タブでその AI エージェント（または部署）に共有し、「Agent 管理 → 設定を編集 → ツールと権限 → ドキュメントライブラリ」で、共有されたすべて・チェックしたものだけ・使わない、から選びます。ここで書き込むのが `agent.toml` の `[knowledge] collections` です。共有されたコレクションしかチェックできないため、この設定は範囲を狭めるだけです。変更できるのはその AI エージェントのオーナーと管理者です。

## コレクションと権限

権限はコレクション単位です。各付与は対象とロールを指定します。

| 対象 | ID | 付与できるロール | 範囲 |
|---|---|---|---|
| user | ダッシュボードのユーザー ID | 閲覧者・編集者・オーナー | その人 |
| department | 部門名（完全一致） | 閲覧者・編集者 | その部門に属するアカウントと、`[agent] department` がその部門の AI 社員 |
| agent | AI 社員 ID | 閲覧者 | その AI 社員 |
| channel | `line`（チャネル全体）または `line:<チャット ID>` | 閲覧者 | そのチャネルやチャットで話す**全員**（ダッシュボードのアカウントがない人を含む） |

- **閲覧者**は検索、段落の閲覧、原本のダウンロード、ソース一覧の表示ができます。**編集者**はさらにソースの追加・削除・再インデックス、**オーナー**は権限と設定の変更、コレクションの削除ができます。
- 管理者はすべてのコレクションのオーナー扱いです。マネージャーはコレクションを作成でき、作成者がオーナーになります。一般社員は作成できません。
- 新しいコレクションは作成者だけが見えます。読めない・壊れた付与は無効として扱います。ユーザーのオーナーを最低 1 人残す必要があります。
- `channel` 付与は FAQ のような公開資料向けです。公式アカウントを友だち追加した人なら誰でも読めます。

### 1 回の検索で読める範囲

ダッシュボードのユーザー：何らかのロールを持つコレクション（管理者はすべて）。

AI 社員が誰かに答えるときは、次の共通部分です。

1. **社員側**：その社員またはその部門に付与されたコレクションを、`agent.toml` で絞り込んだもの。

   ```toml
   [knowledge]
   collections = ["hr-handbook", "product-faq"]   # コレクションのスラッグ。[] でツールを無効化
   ```

   `[knowledge]` がなければ付与されたすべてのコレクション。知らないスラッグは無視します。ゲートウェイが解析できないセクションは `[]` として扱います。社員自身はこのセクションを編集できません。オーナーと管理者がダッシュボードで設定します（上の「AI エージェントにコレクションを使わせる」）。

2. **人側**：そのターンが誰のためか。ログイン済みユーザーは本人と部門の付与、身元不明のメッセージアプリ送信者は `channel` 付与だけ、ゲートウェイが人のいないターンとして登録したもの（スケジュール、ハートビート、ディスパッチ）は社員に付与された public／internal のコレクションを使えます。ゲートウェイが登録していない呼び出し（ターン ID がない、または一致しない）は何も読めません。

3. **機密度**：`public`、`internal`（既定）、`personal`、`restricted`。1 対 1 でない会話（グループ、および非公開と証明できないすべての場合）では `personal` と `restricted` を除外します。

4. **絞り込み**：`knowledge_search` の `collections` 引数は範囲を狭めることしかできません。

このリリースでは、WebChat やチャネルのターンがどのログイン済みユーザーのものかをゲートウェイはまだ把握していません（トリガー経路の作業で対応予定）。スケジュール、ハートビート、ディスパッチのターンもまだ登録されません。それまでは、進行中のチャネル／WebChat ターン中のツール呼び出し（どのランタイムでも）はそのチャットの身元不明の送信者（`channel` 付与のみ）として扱い、それ以外の呼び出しは何も読めません。最終的な挙動より狭く、広くなることはありません。

## 文書の追加

| 方法 | 権限 | 説明 |
|---|---|---|
| `POST /api/knowledge/upload` | 編集者 | multipart：先に `collection_id` フィールド、続いて 1〜20 個の `file`。ダッシュボードユーザーの Bearer トークン |
| `knowledge.sources.add` `{kind: "paste"}` | 編集者 | 貼り付けたテキスト（`.txt` ソースとして保存） |
| `knowledge.sources.add` `{kind: "url"}` | 編集者 | 公開の `http`／`https` ページ。処理時に取得し、キャッシュしません。宣言された文字コード（Big5、GBK など）で読み、URL は正規化（`#` 以降を除去、ホストを小文字、末尾の `/` を除去）するため同じページは重複になります |

対応形式：テキスト層のある PDF、Word `.docx`、Excel `.xlsx`／`.xls`、PowerPoint `.pptx`、CSV、プレーンテキスト、Markdown。URL ソースは Web ページ。旧形式 `.doc`／`.ppt`、パスワード付きファイル、画像、音声は変換方法を示して拒否します。スキャン PDF はテキスト層がないため拒否します（OCR は未対応）。読める PDF の中のテキストのないページは警告に列挙します。

同じファイルを同じコレクションに再度アップロードすると「既存」として既存のソースを返します。別のコレクションには同じファイルを置けます。

ソースの状態は `queued → extracting → indexing → ready` と進みます。ベクトルモデルがない間は `ready` に `status_detail = "keyword_only"` が付きます。失敗時は固定のコードとアップロードした人向けのメッセージを残します。

| コード | 意味 |
|---|---|
| `too_large`、`too_many_chars` | `max_source_bytes` または `max_source_chars` を超過。切り詰めずに全体を拒否 |
| `quota_sources`、`quota_chunks`、`quota_collections`、`quota_bytes` | 設定上限に到達 |
| `unsupported_format`、`legacy_office`、`encrypted`、`no_text_layer`、`empty_text`、`encoding_unknown` | テキストとして読めない |
| `document_limits` | Office ファイルが zip ボムとネスト深さの検査に不合格 |
| `extract_timeout`、`extract_crashed`、`extract_oom` | 解析プロセスの時間切れ・クラッシュ・メモリ不足 |
| `url_blocked`、`url_fetch_failed`、`url_too_large` | 内部アドレス、到達不可、HTML／テキスト以外、5 MB 超 |
| `sandbox_unavailable` | このホストでは解析用の OS サンドボックスが使えない（下記） |
| `retry_exhausted` | 処理中にゲートウェイが 3 回停止 |

再インデックスに失敗しても、以前のインデックスは検索でき、エラーが併記されます。

### ファイルの読み取り方

解析はゲートウェイ内では行いません。各ファイルは子プロセス `duduclaw knowledge-extract`（同じバイナリ、空の環境変数）が読みます。

- 実時間の上限（`extract_timeout_secs`、既定 180 秒）。超えるとプロセスグループごと終了；
- macOS と Linux では CPU 時間の上限とコアダンプ無効、Linux ではアドレス空間の上限（`extract_memory_mb`、既定 2048）；
- macOS（Seatbelt）と Linux（Landlock）の OS サンドボックスで書き込みとネットワークを禁止し、読み取りはそのファイル自体、解析プログラム、システムライブラリのディレクトリに限定；
- Office ファイルは先に既存の zip ボム／XML 深さ検査を通過；
- 出力が `max_source_chars × 4` バイトを超えると打ち切って拒否。

サンドボックスが使えない場合（Windows、または適用に失敗した場合）は `sandbox_unavailable` で拒否します。リスクを受け入れる管理者は `extract_when_unavailable = "run_unsandboxed"` を設定でき、その場合も時間上限は残り（macOS と Windows にメモリ上限はありません）、ソースに `extract_unsandboxed` 警告が付きます。`.xlsx` のシートはセル単位で読み、空でないセルは 200 万個までなので、巨大な範囲を宣言したシートでメモリを使い切ることはできません。解析は同時に 1 つだけ実行します。

段落は文書の元の文字を保ちます（全角の句読点は全角のまま）。照合用にだけ、各段落の NFKC＋小文字の写しを別に保存します（全角英数字や PDF フォントの康熙部首を通常の文字に）。そのため「ＨＲ」と「HR」は互いに見つかります。テキストは約 500 字ずつ少し重なる段落に分けます。PDF はページをまたがず（短いページ末尾は次ページの最初の段落に合流）、ワークシートは行の境目だけで分け、各段落にヘッダー行を付けます。各段落はプロンプトインジェクションらしい文言を検査し、該当したものは印を付けて警告を表示します。

## 検索

このリリースはキーワード検索だけです。

- 3 文字以上の語は SQLite FTS5 の trigram インデックスを使います。中国語のクエリは「的、了、嗎」などの助詞で区切るため、「請假的規定」でも「請假規定」が見つかります。
- 2 文字の語（「請假」、`HR`）は最大 2 万段落までの部分文字列走査を使います。上限に達すると結果に `scan_capped` が付きます。
- trigram で 3 段落未満しか見つからない場合は、長い語の 2 文字片も部分文字列走査に加えます。
- 複数のリストは reciprocal rank fusion で統合し、1 ソースあたり最大 3 段落です。

結果には毎回、検索モードとベクトル検索が無効な理由を示します。文書と異なる言い回し（「薪資」を「薪水」で尋ねるなど）は、ベクトル検索の提供まで見つかりません。

## AI 社員向け

読み取り専用の MCP ツール 3 つ。スコープは `knowledge:read`（外部 MCP キーには付与できません）。

| ツール | 引数 | 返答 |
|---|---|---|
| `knowledge_search` | `query`、`collections`（スラッグ、絞り込みのみ）、`limit`（1〜20、既定 5） | `[n] タイトル · 位置（コレクション） chunk_id=…` と段落本文。文書の内容であることを明示 |
| `knowledge_get_passage` | `chunk_id`、`context`（0〜2） | 段落と前後の文 |
| `knowledge_list_collections` | — | このターンで読めるコレクションとソース数・段落数 |

ナレッジベースが有効で、社員側に少なくとも 1 つのコレクション（その社員または部門への付与を `[knowledge]` で絞り込んだもの）があるときだけ、これらのツールが存在します。一覧と呼び出しは同じ判定を使い、コレクションの付与や取り消しは開いているセッションにも反映されます（`notifications/tools/list_changed`）。結果の各段落、コレクション名、説明は印の付いたブロックに入り、各行は `│ ` で始まるため、文書内の文字が結果の見出しを装ったりブロックを終わらせたりできません。ツールはゲートウェイの署名付きローカルルートを使い、ゲートウェイが止まっているときはその旨を返し、データベースを直接読むことはありません。

## 監査

- 検索、段落の閲覧、一覧、ダウンロードのたびに `knowledge.db` のアクセスログへ 1 行書きます：誰が（ダッシュボードユーザー、社員、チャネル）、クエリ（先頭 500 字）、読めるコレクション、結果の ID。段落本文は保存しません。`access_log_retention_days` を過ぎた行は 10 分ごとに削除します。
- コレクションの作成・変更・削除、権限変更、ソース削除は `security_audit.jsonl` にも記録します。
- コレクションのオーナーは `knowledge.access_log.list` でアクセスログを確認できます：誰が、いつ、どの社員やチャネルで、何件得たか、質問の短いハッシュ。質問の本文は管理者と質問した本人にだけ表示します。
- 管理者は `knowledge.access_log.denied` で全コレクションの拒否された閲覧を一覧できます。
- 共有の選択欄は `knowledge.principals.search`（表示名と部署だけを返し、メールアドレスは返しません）、社員の編集画面は `knowledge.agent.collections` で、その社員に共有されたコレクションを読みます。

## 設定（`config.toml`）

```toml
[knowledge]
enabled = true
max_source_bytes = 104857600     # 1 ファイル 100 MB。1 MB〜200 MB（アップロード上限の変更は再起動が必要）
max_source_chars = 500000
max_sources_per_collection = 300
max_collections = 200
max_chunks_total = 200000
extract_timeout_secs = 180
extract_memory_mb = 2048         # Linux のみ
access_log_retention_days = 180
max_collection_bytes = 2147483648 # コレクションごとの原本合計 2 GB
max_total_bytes = 21474836480     # 全体で 20 GB
extract_when_unavailable = "refuse"  # または "run_unsandboxed"
```

範囲外の値は境界に丸めます。`enabled = false` ではツールを表示せず、すべての RPC とアップロードを拒否します。

## 検索品質の確認

```
duduclaw knowledge eval --docs <フォルダー> --questions <questions.jsonl> [--k 5] [--min-recall 0.85] [--report out.json]
```

一時フォルダーに使い捨てのデータベースを作り、ゲートウェイと同じ解析プロセスとインデックス処理でフォルダー内の文書を取り込み、質問タイプ別の Recall@1／5／10、MRR@10、回答不能な質問で結果が空だった割合、クエリ遅延を報告します。Recall@k が `--min-recall` を下回ると終了コード 1 です。質問は 1 行ずつ次の形式です。

```json
{"id":"q01","question":"到職滿一年的特休有幾天？","type":"factoid","gold":[{"source":"員工手冊.md","contains":"特別休假七日"}]}
{"id":"q13","question":"公司有員工宿舍嗎？","type":"unanswerable","answerable":false}
```

gold には `page`、`slide`、`sheet`、`row` も書けます。`crates/duduclaw-knowledge/tests/fixtures/eval/` に架空の小さな問題集があります。顧客の実文書と質問はリポジトリに入れないでください。

## データと削除

すべて `<home>/knowledge/` にあります：`knowledge.db` と、`blobs/` 以下に SHA-256 名で保存した原本。ソースを削除すると段落・インデックス・ベクトルを 1 トランザクションで削除し、他のコレクションが使っていない原本も削除します（直近 10 分以内にアップロードされたファイルは、同じファイルのアップロードが進行中の可能性があるため、次の整理で削除します。最長で約 20 分後）。データベースは `secure_delete` を有効にしています。コレクションの削除には名前の入力が必要です。
