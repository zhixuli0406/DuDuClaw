# 会話の認証情報監査

Admin は「システム → セキュリティ → 認証情報の監査」で、検出された認証情報の種類、マスク済みアカウント、サービス、出所、提供者、保持者、最後に確認した使用と状態を確認できます。台帳と CSV はメタデータのみを扱い、秘密の値を保存しません。検出は固定ルールを使い、分類のためにメッセージをモデルへ送りません。

## モードと制限

```toml
[security]
chat_credentials = "audit" # audit（既定）または mask
```

**audit** は会話履歴と現在のプロンプトに平文を残します。派生する要約、Wiki 抽出、エピソード記憶、スキル記録、診断・ツールログでは、検出された値をマスクします。**mask** は新しいメッセージを社員に渡す前に、検出された値を `[已遮罩的密碼 cred_xxx]` のような参照へ置き換えます。モード変更は過去の会話、バックアップ、外部ランタイムの記録を書き換えません。不明な設定値は `mask` として扱います。

文脈のない単独のパスワードは検出できません。英語・繁体字中国語の文脈ルールと既知のキー、トークン、PEM、接続文字列の形式を使いますが、すべての秘密を検出する保証はありません。遅延を重視する走査は 64 KiB に制限し、Wiki 文書は 512 KiB のページ上限まで全体を走査します。検出失敗時は派生ストアへ汎用のプレースホルダーを渡します。台帳への書き込み失敗はメッセージを止めず、値をログに残しません。ツール呼び出しへの実値の自動代入は計画段階で、リリース時期は未定です。

## 身元と重複排除

パスワードと接続文字列には**指紋を計算しません**。出所参照、種類、メッセージ内の検出位置で重複を排除します。同じメッセージの再試行は既存の行を使い、時間枠の割当を再消費しません。保持者は実際のルーティングからのみ記録します。同じパスワードだからといって保持関係を推定しません。文脈だけの検出（任意の `api key:` や `token:` の値を含む）には指紋を計算しません。厳密なプロバイダー形式または完全な PEM 構造に一致し、鍵の保護が強化された **AppBound** の場合だけ鍵付き指紋を計算します。Windows と強化されていない macOS の **UserStore**、保護が利用できない場合、JWT／Bearer 形状だけの値には計算せず、鍵なしハッシュにも切り替えません。アップグレード時に従来の指紋を消去します。アカウント表示は先頭文字とドメインのみです（例：`a***@example.com`）。

登録上限はメッセージごとに 5 件、安定した制限対象ごとに毎時 50 件、認証情報全体で 100,000 件です。認証済み WebChat は利用者、チャネルはチャネルと会話、匿名 widget は再接続をまたぐ共有枠を使い、一時的な利用者を保持者として保存しません。保持者は認証情報ごとに 32 件、全体で 200,000 件までです。既存認証情報への追加も同じトランザクションで制限し、割当行は一時間後に失効します。超過は集約した `credential_detection_throttled` イベントに記録します。上限は登録に適用され、検出された値のマスクには適用されません。

システム設定の認証情報は隣の一覧に読み取り専用で表示されます。Remote MCP、個人 Google 接続、MCP 環境変数名、ブラウザプロファイル、MCP クライアント識別子の値は返しません。

最後に確認した使用は、gateway のツールループが保持済みの高エントロピー指紋を照合できた場合に限ります。パスワードと接続文字列には指紋がなく、外部 CLI のツール呼び出しは信頼できる使用関連情報を報告しない場合があるため、「未確認」と表示します。時刻の空欄は未使用の証明ではありません。

## 確認とエクスポート

種類、状態、サービスで絞り込めます。Admin はサービスの編集と誤検出の指定ができます。誤検出の指定は台帳の注記であり、マスク済みの文字を戻しません。「このページを CSV で出力」は現在のページだけを最大 100 件出力します。`credential_exported` を記録し、表計算ソフトの数式プレフィックスを処理します。監査記録の書き込み失敗時は出力を拒否します。

Admin RPC は `credentials.audit_list`、`credentials.audit_get`、`credentials.audit_update`、`security.audit_verify` です。doctor にも監査チェーン検査があります。検出、保持者追加、サービス設定、ツール内の出現、状態変更、出力を記録し、秘密の値やアカウント平文は含めません。成功は「現在の区間の内部整合性を確認」（current segment internally consistent）のみを意味します。ローテーション後は現在の区間だけを検証し、アーカイブや外部コピー、末尾の完全性は保証しません。正常な旧形式行は最初のチェーン行の前だけ許可され、不正な行やそれ以降の未連結行は検証失敗になります。

社員用の `credential_declare` は `credential_id` と `service` だけを受け取ります。サービスは `^[a-z0-9][a-z0-9._-]{0,63}$` に一致し、認証情報の検出も通過する必要があります。社員のメモ指定は拒否します。署名付き gateway ルートで自身の保持する認証情報だけを宣言できます。サービスとメモの権限は個別に管理され、Admin のメモだけの編集も保護され、Admin のサービス設定を上書きできません。宣言の引数、結果、拒否の詳細は監査保存時に除去します。

台帳は gateway が管理する `<home>/credentials/ledger.db` に保存します（Unix 権限 0600）。ファイルガードの Read 経路は `credentials/` の読み取りを拒否します。これは製品内のガードで、無制限のホストアクセスを持つプロセスに対する OS 隔離ではありません。

LINE の永続キューは両モードとも postback、ファイル名、拡張フィールドを含めマスク済みテキストだけを保存し、原文もその暗号文も保存しません。アップグレード時に旧 ingress 暗号文を取り除き、配信用トークンとイベント ID を保持してマスク済みテキストで再試行します。保存前にメタデータを登録し、ルート検証済みのワーカーが社員の保持関係を追加します。登録はベストエフォートであり、失敗やタイムアウトでは行や保持関係が欠ける場合があります。待機は 250 ミリ秒までで、タイムアウト時に配信許可を解放し、中断できない OS 呼び出しは別途最大 4 件に制限します。過負荷やタイムアウトでは audit モードでもマスク済みテキストを配信します。ソースは保存済み会話メッセージ ID、LINE ingress またはキュー／タスク参照です。

## 派生ストアの範囲

両モードとも各保存先でマスクします：固定指示、タイトル、要約・圧縮、意味／エピソード記憶、三つ組、key facts、メタデータと FTS、自動・社員・共有 Wiki（索引／FTS を含む）、スキル記録・キャッシュと抽出監査、全体／社員別 RL JSONL、予測メトリクス・学習トピック／bigrams・進化コンテキスト、作業状態と履歴、委任キューの本文／結果／エラー、タスク・活動・コメント・計画・目標・レビュー、軌跡異常・因果証拠・診断ログ、SFT／選好学習および CSV／XLSX 出力。凍結済みの実行・承認データに認証情報が含まれる場合は意味を書き換えず保存を拒否します。全 11 チャネルのメッセージログは切り詰め前にマスクし、整形されたファイル／stderr と配信ログも出力時にマスクします。

audit モードで検出された平文を保持するのは `sessions.db` の会話メッセージと現在のプロンプトだけです。LINE の永続配信は常にマスクします。固定ルールでは未知・変換済みの秘密をすべて検出できません。既存の派生履歴や外部ランタイムの transcript は遡及消去しません。LINE ingress 関連行はメタデータだけを保存し、上限 100,000 行、期限は七日です。

512 KiB のページ上限内の Wiki ページは全体をスキャンして保存前にマスクします。スキャンに失敗した場合は書き込みを拒否します。64 KiB のスキャン上限は、遅延が重視されるチャットとログでは引き続き使用します。
