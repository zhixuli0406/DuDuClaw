# 会話の認証情報監査

未リリース。Admin は「システム → セキュリティ → 認証情報の監査」で、検出された認証情報の種類、マスク済みアカウント、サービス、出所、提供者、保持者、最後に確認した使用と状態を確認できます。台帳と CSV はメタデータのみを扱い、秘密の値を保存しません。検出は固定ルールを使い、分類のためにメッセージをモデルへ送りません。

## モードと制限

```toml
[security]
chat_credentials = "audit" # audit（既定）または mask
```

**audit** は会話履歴と現在のプロンプトに平文を残します。派生する要約、Wiki 抽出、エピソード記憶、スキル記録、診断・ツールログでは、検出された値をマスクします。**mask** は新しいメッセージを社員に渡す前に、検出された値を `[已遮罩的密碼 cred_xxx]` のような参照へ置き換えます。モード変更は過去の会話、バックアップ、外部ランタイムの記録を書き換えません。不明な設定値は `mask` として扱います。

文脈のない単独のパスワードは検出できません。英語・繁体字中国語の文脈ルールと既知のキー、トークン、PEM、接続文字列の形式を使いますが、すべての秘密を検出する保証はありません。走査上限は 64 KiB です。検出失敗時は派生ストアへ汎用のプレースホルダーを渡します。台帳への書き込み失敗はメッセージを止めず、値をログに残しません。ツール呼び出しへの実値の自動代入は計画段階で、リリース時期は未定です。

## 身元と重複排除

パスワードと接続文字列には**指紋を計算しません**。出所参照と種類で重複を排除し、保持者は実際のルーティングからのみ記録します。同じパスワードだからといって保持関係を推定しません。API キー、トークン、PEM は認証情報の保護機構を通じて鍵付き指紋を使えます。保護機構が利用できない場合は指紋を計算せず、鍵なしハッシュに切り替えません。アカウント表示は先頭文字とドメインのみです（例：`a***@example.com`）。

登録上限はメッセージごとに 5 件、送信者ごとに毎時 50 件、認証情報全体で 100,000 件です。超過は集約した `credential_detection_throttled` イベントに記録します。上限は登録に適用され、検出された値のマスクには適用されません。

システム設定の認証情報は隣の一覧に読み取り専用で表示されます。Remote MCP、個人 Google 接続、MCP 環境変数名、ブラウザプロファイル、MCP クライアント識別子の値は返しません。

最後に確認した使用は、gateway のツールループが保持済みの高エントロピー指紋を照合できた場合に限ります。パスワードと接続文字列には指紋がなく、外部 CLI のツール呼び出しは信頼できる使用関連情報を報告しない場合があるため、「未確認」と表示します。時刻の空欄は未使用の証明ではありません。

## 確認とエクスポート

種類、状態、サービスで絞り込めます。Admin はサービスの編集と誤検出の指定ができます。誤検出の指定は台帳の注記であり、マスク済みの文字を戻しません。「このページを CSV で出力」は現在のページだけを最大 100 件出力します。`credential_exported` を記録し、表計算ソフトの数式プレフィックスを処理します。監査記録の書き込み失敗時は出力を拒否します。

Admin RPC は `credentials.audit_list`、`credentials.audit_get`、`credentials.audit_update`、`security.audit_verify` です。doctor にも監査チェーン検査があります。検出、保持者追加、サービス設定、ツール内の出現、状態変更、出力を記録し、秘密の値やアカウント平文は含めません。チェーン検証は現存する記録の検査であり、外部のコピーや削除済み記録の完全性を保証しません。

社員用の `credential_declare` は `credential_id`、`service`、`note` だけを受け取り、値は受け取りません。署名付き gateway ルートを通じて自身が保持する認証情報だけを宣言でき、Admin が設定したサービスを上書きできません。サービス名やメモに認証情報の値を入力しないでください。

台帳は gateway が管理する `<home>/credentials/ledger.db` に保存します（Unix 権限 0600）。ファイルガードの Read 経路は `credentials/` の読み取りを拒否します。これは製品内のガードで、無制限のホストアクセスを持つプロセスに対する OS 隔離ではありません。

LINE の永続キューにはマスク済みテキストを保存し、転送用の原文をメッセージ ID に結び付けて暗号化します。復元するのは配信ワーカーだけです。転送キーが使えない場合はマスク済みテキストで配信を続けるため、後段では原文を登録できません。既存のキュー行は書き換えません。台帳とキー保管庫の処理は同時に 4 件、待機は 250 ミリ秒までとし、過負荷やタイムアウトでは audit モードでもマスク済みテキストを配信します。ソースは保存済み会話メッセージ ID またはキュー／タスクの参照です。
