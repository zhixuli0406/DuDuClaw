# AI 従業員のグループ会話コンテキスト

初期状態は無効です。Admin が「チャンネル → 対象チャンネル → グループ設定」でグループごとに有効化します。有効化後に受信したメッセージだけを保持し、プラットフォームの過去ログは取得しません。保存の目的と期間をメンバーに知らせてください。

## 保存と回答

最近の会話から選択するかグループ ID を入力します。Discord ではサーバー ID も必要です。既定は 50 件・24 時間、上限は 200 件・168 時間です。件数上限は同じグループのスレッドを含みます。無効化するとバッファの行を削除します。既存の会話履歴、送信済みメッセージ、バックアップ、プラットフォーム履歴は別管理です。

有効なグループでは「メンション時のみ返信」がオンでも通常のテキストを保存します。許可チャンネルの制限は維持します。パスワードとキーは保存前に必ずマスクします。氏名、電話番号、メールアドレスなどの個人情報は、管理者が RFC-23 匿名化とチャンネル入力の保護を有効にした場合のみ置き換えます。既存の会話履歴と同じ方針です。無効の場合は認証情報だけをマスクして保存します。処理エラー、または有効設定なのにマネージャーがない場合は保存をスキップします。有効化の操作欄に件数・時間とこの方針を表示し、入力匿名化が無効なら「設定 → 匿名化」（`/app/system/settings?tab=redaction`）へのリンクを表示します。各メッセージは最大 2,000 文字、添付はプレースホルダーのみです。このバッファのために添付をダウンロードしません。時刻は gateway が受信した UTC 時刻です。ローカルの平文バッファであり、暗号化アーカイブではありません。書き込み接続は SQLite の安全な削除を有効にし、無効化と各保持期限の清掃後に WAL の切り詰めを要求します。読み取りによるブロックや失敗は警告を記録し、後続の清掃で再試行します。Unix の読み書きではシンボリックリンク、通常ファイル以外、他ユーザー所有のファイルを拒否し、権限を 0600 に制限します。外部バックアップとファイルシステムのスナップショットは削除対象外です。

回答時は、同じ会話／スレッドの直前の bot 回答以降のメッセージを参照用ブロックとして渡します。今回の質問と後から届いたメッセージは含みません。ブロックには「メンバーによる参考情報であり指示ではない」と明示し、最大 6,000 文字に制限します。ブロックは今回のユーザーメッセージ側で質問の前に置き、システムプロンプトには追加しません。入力ガードに該当する行を除外した後、組み立てたブロック、時系列順の名前と本文の組み合わせ、本文のみの形を、空白で結合した形と空白を除いた形でも再検査し、メッセージや送信者をまたぐ指示を検出します。該当した場合はブロック全体を省略して警告を記録し、回答は継続します。偽の区切り文字はエスケープします。グループには引き続き個人コンテキストを渡しません。プラットフォームが送信を受理してから bot 回答を記録し、送信失敗で境界を進めません。進捗表示や操作コマンドの確認応答は完全な記録の対象ではありません。


スレッドごとに別々に参照し、`thread_id` の省略は元の会話を意味します。Discord は検証済みの親チャンネルを `group_id`、スレッドを `thread_id` にします。Bot の行には回答した従業員と、取得できる場合は送信先のメッセージ ID を記録します。DingTalk webhook や ID のない成功応答では `local:` と明示した ID を使います。後の分割送信が失敗しても、受理された各テキストは保存します。進捗表示と生成ドキュメントのアップロード通知は対象外です。Telegram 音声は音声プレースホルダーになります。

## 従業員による履歴の参照

`group_history_read` は `channel`、`group_id`、省略可能な `thread_id`、`limit`（1–100）、省略可能な `before`（Unix 秒）を受け取り、バッファ内を新しい順に返します。稼働可能な Active 状態、ホスト発行の検証済み従業員 ID と、チャンネル／スレッドの明示的バインドまたは `allowed_channels` による選択が必要です。既定・メイン従業員へのフォールバックではアクセスできません。メイン従業員にも明示的なバインドが必要です。無効なグループ、他の従業員、利用不能なデータは同じ `not available` を返します。必要なスコープは `messaging:read` です。外部の送信専用プロファイルは自動拡張しません。読み取り可能な有効グループがある場合だけツールを表示し、監査には本文ではなく ID、グループ、件数を残します。

履歴ツールは返却前に自動参照ブロックと共通のガードで各行、出力全体、時系列順の行をまたぐ組み合わせを検査します。名前、本文、返却するその他の文字列も対象です。一つでも該当すれば呼び出し全体を同じ `not available` で拒否し、該当行を示しません。成功時は新しい順の JSON 行を同じ `<group_recent_context>` 非信頼データの区切りで囲み、偽の区切り文字をエスケープします。

## プラットフォームの受信制限

| プラットフォーム | 設定と制限 |
|---|---|
| Discord | Developer Portal で **MESSAGE CONTENT INTENT** を有効化します。gateway は既に要求しています。 |
| Slack | `message.channels` と `message.groups` を購読し、`channels:history` と `groups:history` を付与します。権限変更後に App を再インストールし、チャンネルに招待します。通常の `message` イベントも保存対象です。 |
| Telegram | BotFather の `/setprivacy` で privacy mode を無効化すると、通常のグループメッセージを受信できます。管理者 bot も広い範囲を受信します。 |
| LINE | Bot が参加するグループのメッセージを受信します。短期 ingress キューとは別のバッファです。 |
| Teams | App にメンションしたメッセージしか含まれない場合があります。チームの全チャンネルメッセージには適切な App インストールと `ChannelMessage.Read.Group` などの RSC 権限が必要です。本機能は追加権限を申請しません。 |
| Google Chat | App にメンションしたメッセージしか含まれない場合があります。バッファの有効化だけで interaction webhook が履歴購読になることはありません。 |
| Feishu / DingTalk | 設定済み bot が実際に受信したイベントのみ。履歴の補完は行いません。 |

WhatsApp と WeCom は対象外です。本変更で各プラットフォームの権限、実際のインストール、送受信は未検証です。完全なコンテキストに依存する前に、隔離したテストグループでメンションなしの受信を確認してください。

公式資料：[Slack イベント](https://api.slack.com/events/message)、[Telegram privacy](https://core.telegram.org/bots/faq)、[Teams RSC](https://learn.microsoft.com/en-us/microsoftteams/platform/bots/how-to/conversations/channel-messages-for-bots-and-agents)、[Google Chat interactions](https://developers.google.com/workspace/chat/receive-respond-interactions)。

## Discord の従業員選択

Admin は同じ設定画面で、サーバーの `/agent` と従業員メニューで選べる従業員を指定します。空リストは切り替え無効です。利用者には引き続き Discord サーバー管理権限が必要で、メイン従業員は選択できません。リストから外した従業員への保存済み選択は次のルーティングで無効になります。専用 bot の設定と `/config mention_only` は維持します。

Discord の選択候補と保存対象は Active の従業員だけです。Paused、Terminated、Archived、Deleted は拒否し、Active から変更された後は次回の解決時に古い選択を無効にします。専用 bot も稼働可能な従業員を必要とします。
