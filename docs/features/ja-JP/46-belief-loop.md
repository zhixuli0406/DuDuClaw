# 信念ループ(Belief Loop)

> エージェントに、外の世界に対する人間らしい信念サイクルを与える：予測を宣言し、
> 現実に照らして採点され、次の機会に自分のキャリブレーションを目にする。

## これは何か

タスクフォワードモデル(v1.53/v1.54)が予測するのは、エージェント*自身の実行*
です(どのツールを使うか、何回呼び出すか、ジャッジが通すか)。信念ループは
欠けていた外側の層を追加します：**外部世界**に対する構造化された予測——対象は
市場に限らず何でも——を観測された現実に対して決定論的に決済し、エージェントの
キャリブレーション記録を次の意思決定プロンプトに注入して返します。

ループの全体像(すべてのフックはプログラム的です：信念と現実の差分はすべて
プラットフォームが計算して注入し、エージェントに自分が何を予測したかを
*思い出す*ことを求めることは決してありません。arXiv:2605.29463 の
リフレクション虚構化の証拠によって強制された設計です)：

```
belief_submit (MCP) ──▶ belief_log (prediction.db)
      ▲                        │
      │ 次のディスパッチの     │ tick 起動時に1行の対照を添付：
      │ プロンプトに校正       │ 「70%で上昇と言ったが、1.2%下落」
      │ セクションを注入       ▼
      │ (n<30 は件数のみ) belief_settle (MCP) ─▶ 決定論的な3方向 Brier
      └────────────────────────┘   (ライブ観測とのクロスチェック、許容誤差 ±1%)
```

## 使い方

エージェントには3つの MCP ツールが与えられます：

- `belief_submit` — subject(予測対象となる外部の何か。銘柄コード `2317` や
  `trial_conversion_rate` のような KPI など)、horizon(いつ決済するかを表す
  自由形式のラベル。例：`今日の終値` や `今週金曜`、40文字以内)、
  direction(`up`/`down`/`flat`)、probability(0〜1)、短い根拠、そして
  方向の判定基準となる参照値。
- `belief_settle` — 信念の id と実現値。決済は決定論的です：参照値に対する
  方向判定、設定可能なフラットバンド(`[belief] flat_band_pct`、デフォルト
  0.3%)、3方向 Brier スコアリング。ゲートウェイがその subject のライブ tick
  観測を持っている場合、報告された値をクロスチェックします(許容誤差 1%、
  乖離時は拒否——エージェントは現実を自己申告できません)。tick フィールドと
  subject の対応付けは、プラットフォームの `zXXXX → XXXX` 命名規則、または
  規則に従わないソース向けに `config.toml` の `[belief] tick_subject_map`
  エントリ(キー = tick フィールド名、値 = subject)で行います。
- `belief_stats` — エージェント自身のキャリブレーション記録。

ダッシュボード：Foresight ページに**信念と検証**タブが追加されます。
予測リスト(方向+信頼度と実現結果の対照、的中/外れ)、Wilson 下限の的中率、
平均 Brier、過信度を表示します。決済済みの信念が30件未満の間は件数のみを
表示し、その旨を明記します。「効いていそう」とは決して表示しません。

## 2つの例

- **投資**(最初に検証されたユースケース)：subject = 銘柄コード、horizon =
  `今日の終値`、参照値 = 提出時点の価格、実現値 = 終値。ライブ tick フィードが
  設定されていれば、決済時にクロスチェックされます。
- **ビジネス KPI**：subject = `trial_conversion_rate`、horizon = `今週金曜`、
  参照値 = 今週開始時のコンバージョン率。エージェントは毎週月曜に、どちらの
  方向へ動くかの信念を提出し、週末に CRM の実際の数値で決済します。tick
  フィードは不要で、スケジュールされたゴールタスクで決済を駆動できます。

## 誠実な境界線

- エージェントのキャリブレーション履歴をプロンプトに注入することは、
  実証済みのメカニズムではなく**実験**です。2026-08 の文献調査では
  どちらの方向にも一次証拠が見つからなかったため、すべての信念行に
  統計が注入されたかどうか(`stats_injected`)を記録し、この問いに
  自分自身のデータで答えられるようにしています。
- キャリブレーションはタスク成果とは別に採点され、両者は乖離することが
  知られています(arXiv:2607.03015)。よく校正されたエージェントが自動的に
  高性能なエージェントであるとは限らず、ダッシュボードも両者を決して
  混同しません。
- 決済済みサンプルが30件未満の間は、いかなる数値も結論として提示されません
  (全体を通して Wilson 下限と件数のみの表示)。
