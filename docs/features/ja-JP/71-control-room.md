# ターミナルコントロールルーム

[English](../71-control-room.md) · [繁體中文](../zh-TW/71-control-room.md)

`duduclaw tui` は、見ていない間に AI スタッフが何をしているかをターミナルに表示し、止めたり方向を変えたりできるようにします。Gateway のクライアントであり、すべての操作はダッシュボードと同じ認可を通ります。コントロールルーム自体は権限を持ちません。

キー操作とコマンドは[ガイド](../../guides/ja-JP/tui.md)を参照してください。このページでは用途と限界を説明します。

## 何のためのものか

スタッフは目標、スケジュール、職責に沿って自律的に働きます。すると、いま何が動いているか、何が自分を待っているか、どう止めるかという三つの疑問が生まれます。コントロールルームはこの三つを一つの画面で答え、SSH 経由でも使えます。

| 疑問 | 場所 |
|---|---|
| 何が自分を待っているか | 受信箱：承認と返信待ちの目標。各行に誰がなぜ上げたかが出ます。ブレーカー通知も情報として表示されます。対応待ちの件数やデスクトップ通知の対象には含めませんが、アプリ内のエラートーストは表示できます。 |
| いま何が動いているか | スタッフ一覧、実行とタスクのブロック、次回スケジュール、`duduclaw tui watch`。 |
| どう止めるか | `p` で選択中のスタッフの自律作業を一時停止し、`u` で再開します。Admin はパレットから全員を止められます。 |

## 作業を止める

似た操作が三つあり、それぞれ動作が異なります。

| 操作 | 止まるもの | 続くもの |
|---|---|---|
| 自律一時停止（`p`） | そのスタッフの目標ラウンド、cron、ハートビート、職責、Autopilot の動作、割り当てスケジュール。緊急停止は待てないため、確認なしで即座に送信します。 | 現在のターンは最後まで実行します。スタッフとの会話は引き続きできます。 |
| スタッフ状態の一時停止（パレット） | スタッフ自身の状態を変更します。確認カードがあります。 | 状態が稼働可能でない間、自律作業は動きません。 |
| チャットターンの取消 | そのターン。委任した作業がまだ動いていれば、一緒に止めるか尋ねます。 | 止めなかった作業は完了します。ただしそのターンの下でさらに委任はできません。 |

ステータス行に一時停止中のスタッフが表示されます。一時停止の状態を読めない場合、Gateway は自律作業を停止中として扱い、コントロールルームもそう表示します。変更が確認できるまでは推測せず「待確認」と表示します。

## 行わないこと

- 常設の権限付与や全体設定の変更は行いません。フォーム全体を確認できるダッシュボードで行います。
- 本人の在席が必要な承認はブラウザで開きます。
- すでに実行された外部操作は、実行を止めても取り消せません。
- ターンを取り消しても、そのターンが作成したタスクボードのタスクや目標は追跡しません。

## 信頼の境界

スタッフ由来のテキストは信頼しません。名前、タスクのタイトル、ツール出力、チャット返信は描画前に端末制御シーケンスを除去し、リンクもクリック可能にしません。デスクトップ通知は固定文言と数字のみで、名前や内容を含まず、既定で無効です。アプリ内トーストと通知メールボックスは固定文言と無害化したスタッフ表示名だけを使い、メッセージ、タスク、ツールの内容を含みません。

内蔵ターミナルブロックはあなたのものであり、Gateway を経由しません。そこからの「待機中」マーカーは表示のみで、何も認可せず、何にも応答しません。Windows では利用できません。

コントロールルームは Gateway のホスト上で実行し、リモートなら SSH を使ってください。Gateway のポートを転送すると、ローカルログイン経路が転送元ホストに露出します。

## 表示

サイドバー型ワークスペースを使います。スタッフカードは要対応、エラー、作業中、待機、一時停止の順で、二行目に待機項目、目標ラウンド、次のハートビート、停止理由から最も有用な既知の情報を表示します。未読受信項目は強調色の線、選択は背景色で示します。100 桁未満では記号と短い名前だけです。`I` で受信箱、Manager／Admin は `S` で完全な予定一覧をメイン領域に開けます。入口の件数は情報行を含み、対応待ちの件数とは区別します。

メイン領域のチャット・タスク・記録タブは `Tab`／`Shift-Tab` で切り替え、`[`／`]` は前後レコードに使います。既存の分割、PTY、意思決定カード、自律作業ブロックも利用できます。一行のヘッダーに接続、バージョン、費用を表示します（小数二桁、ゼロ以外で $0.01 未満のみ四桁）。ヘルプには完全な home パスを表示し、未実行の予定は `尚未執行` と示します。明暗の配色、状態色、フォーカス枠、読みやすいローカル時刻も維持します。

アプリ内トーストはメイン領域の右下に `完成 / 需要你 / 錯誤` を成功・警告・危険色で表示します。最大二件で新しいものが上です。完了とエラーは約六秒で消え、要対応は閲覧または消去まで残ります。フォーカスを奪わず、意思決定カードにも重なりません。`F8` で明示的に通知へフォーカスし、矢印で選択、`x` で消去します。

`M` でこのプロセスの最新 100 件の通知メールボックスを開きます。`N` は目標作成のままです。`Tab` は全件・未読・エラーの絞り込み、矢印は選択、`Enter` はスタッフまたは受信項目への移動、`Esc` は閉じる操作です。開くと現在の通知を既読にしてトーストを消し、その後の新着は、通知で `Enter` を押す、関連受信項目を開くか既読にする、またはメールボックスを閉じて開き直すまで未読です。履歴と未読状態はメモリ内だけに保持し、Gateway の保留要求は変えません。

`z` は現在のブロックを拡大し、サイドバーとヘッダーを隠して、フッターに復元の案内を残します。もう一度押すと元の配置に戻り、意思決定カードとパレットも利用できます。チャットと記録タブはコンパクトなタイムラインを持ち、取得済みの各ツール手順とラウンド結果を一行に表示します。`t` でフォーカス、矢印で選択、`Enter` で既存の詳細を展開／折りたたみます。文字は無害化し表示幅で処理し、実行内容は従来の `c` による同意が必要です。受信済みのデータを使うため RPC は追加せず、`tui watch` も変わりません。

`tui.toml` の既定値は `theme = 'auto'` です。起動時に約 150 ミリ秒の期限で OSC 11 の背景を問い合わせ、有効な応答がなければ `COLORFGBG`、暗い配色の順に使います。`light` または `dark` を指定すると検出を省略します。色は端末に応じて truecolor、256 色、16 色を使います。`NO_COLOR` は空文字を含む任意の値で色を無効にし、太字と反転の手掛かりは残します。

Windows のネイティブ console、非 TTY 入力、`TERM=linux` または `dumb`、`NO_COLOR` 設定時は OSC 11 を省略し、フォールバック順に使います。[ガイド](../../guides/ja-JP/tui.md#ローカルファイル) に入力復元の時間制限と参照パレットのコントラストを記載しています。

## ターミナル

次の表は実際に実行した結果だけを記録しています。載っていないターミナルが動かないとは限りませんが、未確認です。

| ターミナル | 状態 |
|---|---|
| macOS 上の tmux | 実 Gateway でフルスクリーンを確認済み。ローカルの実モデルによる返信、返信途中のキャンセル、ターミナルブロック内のプログラムへのマウス入力（X10、SGR、urxvt、SGR-Pixels の各エンコーディングと `vim`）を含みます。tmux が許可する場合、通知は tmux パススルーを使います。 |
| macOS 上の Terminal.app | 実 Gateway でフルスクリーンを確認済み：描画、CJK 文字幅、`p` と `u`、中国語と絵文字の入力、ターミナルブロック、正常終了。キー入力はテストプログラムから送信しており、物理キーボードではありません。 |
| 自動テスト内の macOS・Linux 疑似端末 | 幅 60 桁以上、高さ 12 行までをスナップショットで確認。 |
| Windows、SSH 経由の `tui inbox` | ネイティブ Windows 機で確認済み。 |
| Windows 11 フルスクリーン（ConPTY） | ネイティブ Windows 機の実 Gateway で確認済み。テストプログラムが実際の Pseudo Console を操作しました：描画、リサイズ、画面不足の表示、`p` と `u` の Gateway 側での反映、中国語入力、正常終了。Windows Terminal 自体では未確認です。 |
| 実機の Ubuntu 22.04、PTY 上のフルスクリーン | 実 Gateway で確認済み：描画、リサイズ、画面不足の表示、`p` と `u` の Gateway 側での反映、正常終了と端末の復元。物理的な端末エミュレータでの操作は未確認です。 |

最小で 24 桁、12 行が必要で、それより小さいとその旨を表示します。UTF-8 ロケールで `TERM` が `linux`、`dumb` 以外なら状態記号の既定は Unicode、それ以外は ASCII です。`tui.toml` の `glyphs = 'ascii'` または `'unicode'` の明示指定が優先され、Unicode モードでは角丸の枠線を使います。CJK の文字幅と確定済み文字の入力には対応していますが、入力メソッドの手動確認はまだです。
