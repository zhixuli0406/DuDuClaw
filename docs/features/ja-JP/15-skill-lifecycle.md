# スキルライフサイクルエンジン

> 生の会話から洗練された再利用可能なスキルへの6段階。

---

## たとえ話：弟子から達人へ

武道の弟子は段階的に学びます：

1. **活性化** — 師範が道場を開く。弟子が現れる。
2. **圧縮** — 一つの技を三通りの長さで書く：技の名前、一行の口訣、完全な分解。思い出せる最短の版で足りる。
3. **抽出** — 各組手の後、弟子は何がうまくいき何がいかなかったかを振り返る。
4. **蒸留** — 何年もの修練が、他者に教えられる少数の原則に圧縮される。
5. **診断** — 師範が見るのは一度の*失敗*であり、その原因を言い当てる。構えの問題か、それともその返し技をそもそも習っていないのか。
6. **ギャップ分析** — 「防御は強いが、カウンターが弱い。そこを鍛えよう。」

DuDuClawのスキルライフサイクルはこの過程を反映します——生の会話経験を構造化され、再利用可能で、共有可能なスキルに変換します。

## 仕組み

### ステージ1：活性化

エージェント起動時、スキルローダーが`SKILLS/`ディレクトリを読み込み、インストール済みスキルを有効化：

```
Agent起動
     |
     v
SKILLS/ディレクトリをスキャン
     |
     v
各スキルファイルについて：
  - スキル定義を解析
  - フォーマットと依存関係を検証
  - SkillRegistryに登録
     |
     v
スキルがAgentのruntimeで利用可能に
```

### ステージ2：圧縮（3層のプログレッシブ読み込み）

圧縮が扱うのは*注入コスト*であり、重複排除ではありません。各スキルは3つの層で保持され、プロンプト構築時には「まだ用を成す一番安い層」が注入されます：

```
スキルファイル（SKILLS/complaint-handling.md）
     |
     v
Layer 0 — 名前タグのみ        約5トークン
Layer 1 — 1〜2行の要約        約30トークン
Layer 2 — 完全なmarkdown      約200+トークン
     |
     v
どの層がプロンプトに届くかは関連度が決める
```

そのターンでおそらく不要なスキルを視界に残すコストは200ではなく5トークンです。スキルの充実したエージェントが毎ターン蔵書全体の代金を払わずに済むのは、これによります。

### ステージ3：抽出

成功した会話の後、新しいスキルになりうるパターンを自動抽出：

```
会話が成功裏に完了
     |
     v
会話パターンを分析：
  - これは新規のアプローチか？
  - ユーザーは満足を表明したか？
  - このパターンは再現可能か？
     |
  +--+--+
  |     |
 はい   いいえ → スキル抽出なし
  |
  v
候補スキルを生成：
  - トリガー条件を特定
  - レスポンスパターンを抽出
  - 成功基準を定義
     |
     v
書き込み前にセキュリティスキャンとvettingゲートを通す
```

> **2026-09に削除：「ステージ4——再構築」。** 本ページの旧版には、雑然としたスキルの意図をリバースエンジニアリングして原則から作り直すステージが書かれていました。それを担うはずだったモジュール（`skill_lifecycle/reconstruction.rs`）には呼び出し元が一つもなく——自身のテストからすら呼ばれず——何一つ再構築したことがありませんでした。約束として残すのではなく、コードごと削除しました。スキルが壊れた場合の正直な答えは、それを引退させ、抽出に新しいものを作らせることです。同じ理由で姉妹モジュール2つ（`recommender.rs`、`dependency_resolver.rs`、いずれも呼び出し元ゼロ）も一緒に削除されました。スキル一覧に「おすすめ」面がなく、スキル同士に宣言された依存関係がないのはそのためです。

### ステージ4：蒸留

スキルを本質的なルールに圧縮——効果的に適用するために必要な最小限の知識：

```
完全なスキル（500行、詳細な例）
     |
     v
本質的ルールを特定：
  - コア原則（5-10ルール）
  - 重要な制約
  - 重要な判断ポイント
     |
     v
蒸留されたスキル（50行、純粋な原則）
```

### ステージ5：診断

診断師はスキルを採点しません。読むのは**予測誤差**であり、その原因を言い当てます——LLMコストゼロ、`PredictionError`シグナルに対する純粋なルールです：

```
PredictionError（Significant / Critical）
     |
     v
原因を分類：
  - StyleMismatch       — 口調・長さがユーザーに合わない
  - DomainGap           — このトピックの知識がない
  - PrecisionIssue      — 回答が十分に正確でない
  - ExpectationMismatch — ユーザーは別の振る舞いを期待していた
  - Unknown             — 判定不能
     |
     v
DomainGapかつ、合致するインストール済みスキルが無い
     |
     v
SkillGap { suggested_name, suggested_description, evidence } を生成
```

`SkillGap`になるのは「既存スキルがどれも覆っていないDomainGap」だけです。この記録がステージ6の蓄積対象になります。

### ステージ6：ギャップ分析

最終ステージ。エージェントの全体的なスキルポートフォリオを調査し、欠けている部分を特定：

```
会話履歴を分析
     |
     v
Agentが苦戦したパターンを特定：
  - 満足度スコアの低いトピック
  - クラウドAPIへのフォールバックが必要だったクエリ
  - 放棄された会話
     |
     v
ギャップレポート：
  「Agentはクレーム処理は得意（対応スキルあり）だが、
   技術的な製品質問で苦戦。
   推奨：先週の5つの成功した技術会話からスキルを抽出。」
```

## スキルマーケットプレイス

自己生成スキルに加え、コミュニティからスキルを発見・インストール可能：

### GitHubライブインデックス

GitHub Search APIでリアルタイムにスキルリポジトリを検索：

```
検索クエリ："customer-support skill duduclaw"
     |
     v
GitHub Search API → 結果（24時間キャッシュ）
     |
     v
加重ランキング：Stars、活動頻度、フォーマット有効性、セキュリティスキャン結果
```

### セキュリティスキャン

インストール前に、すべてのスキルが Rust ネイティブの **Skill セキュリティスキャナー**（`skill_lifecycle::security_scanner`）を通過：プロンプトインジェクションパターン、システムファイル変更、外部URL参照、難読化コンテンツをチェック。

### どこを検索するか

スキルの出どころは3つ — GitHub、キュレーション済みのスキルハブ、そしてこの環境が自分で学習したスキルバンク — ですが、検索するツールは1つです。`skill_search` は `source` パラメータを取ります。

| `source` | 検索対象 | 使いどころ |
|---|---|---|
| `all`（既定） | ハブ **と** 学習済みスキルバンク。スキル名で重複排除 | そのスキルがどこにあるか分からないとき。**ルールは一言: 分かっている場合を除き `source` は触らない。** |
| `github` | GitHub ハブのみ | 公開 GitHub リポジトリにあると見込まれるとき |
| `hub` | キュレーション済みレジストリ（anthropic-skills / clawhub / lobehub / skills-sh） | 審査済み・ランキング付きの結果だけが欲しいとき |
| `bank` | 学習済みスキルバンク | この環境が自分で学習したものを探しているとき |

学習済みスキルバンクはまだ空のインメモリスタブなので、`source="bank"` は正直に「空である」と返します。ハブの結果でごまかすことはありません。`skill_bank_search` は `source="bank"` の非推奨エイリアスとして引き続き使え、v1.68.0 で削除されます — [非推奨となった名称](../../guides/ja-JP/deprecations.md)を参照。

### MCPツール

| ツール | 用途 |
|--------|------|
| `skill_search` | すべてのスキルソース（ハブ＋学習済みバンク）を加重ランキングで検索。`source` で絞り込み |
| `skill_list` | エージェントごとのインストール済みスキルを一覧表示 |

## なぜ重要か

### 複合学習

各会話がエージェントに何かを教えます。スキルライフサイクルがその学びをキャプチャし形式化します。

### 知識転送

スキルはエージェント間で共有可能。サポートエージェントから抽出されたスキルを営業エージェントにインストールできます。

### 品質管理

診断とギャップ分析が、スキルの蓄積だけでなく*改善*を支えます。ディスクに書き込まれるmarkdownはセキュリティスキャンとvettingゲートを通ります。

### コミュニティ

マーケットプレイスにより、ゼロからスタートする必要はありません。他者の実戦テスト済みスキルが数分でエージェントをブートストラップできます。

## 他システムとの連携

- **進化エンジン**：スキルが予測エンジンに情報を提供。スキルが充実したAgentは予測エラーが少ない。
- **GVUループ**：成功したGVUサイクル後にスキル抽出がトリガーされることが多い。
- **メモリシステム**：スキルはメモリを補完——メモリは*何が起きたか*を覚え、スキルは*何をすべきか*を覚える。
- **CONTRACT.toml**：スキルは契約境界内で動作する必要がある。実際にディスクへ書かれるmarkdownはセキュリティスキャンとvettingゲートを通る。
- **Dashboard**：スキルマーケットプレイス、インストール済みスキル、ギャップ分析レポートがWebインターフェースで閲覧可能。

---

## まとめ

スキルは生の経験と信頼できる能力の間の架け橋です。6段階のライフサイクルは、成功した会話を再利用可能なスキルに、繰り返す失敗を名前の付いたギャップに変えます——抽出し、スキャンし、共有する。エージェントは今日の会話を処理するだけでなく、明日の会話をより良く処理するために成長します。
