# データ送信の保護

v1.77.0 から提供。AI スタッフが非公開データを読んだターンでは、後続の MCP 送信を実行前にプログラムで検査します。判断はモデルの外で行います。

## 動作を選ぶ

**セキュリティ → データ送信の保護** を開きます。既定の「記録のみ」（`shadow`）は実行を許可し、ツール呼び出し監査に `would_ask` と読み取り元のツール名を記録します。「送信前に確認」（`ask`）は承認を要求し、「送信を拒否」（`block`）は拒否します。「無効」（`off`）はこの検査を無効にします。

```toml
# config.toml
[security]
egress_guard = "ask"

# agent.toml
[capabilities]
egress_guard = "block"
```

全体設定とスタッフ設定の厳しい方を適用します：`off < shadow < ask < block`。個別設定で全体設定を緩めることはできません。全体設定ファイルがない場合は `shadow`、スタッフ設定がない場合は全体設定を継承します。それ以外の読み取りエラーや無効な値は、その呼び出しを拒否します。既存の禁止リスト、権限、アクションルールは引き続き適用されます。

## 対象

非公開データを読む前に gateway で予約し、実行中も全 MCP プロセスが読み取り済みとして扱います。モデルに渡すデータがあれば、エラー応答でも読み取り元として確定します。データのない失敗だけが予約を解除し、キャンセルや完了不明の場合はフラグを残します。メモリ、Wiki、ナレッジベース、ローカルファイル、データベース、メール、Google データ、タスク、活動、作業状態などが対象です。すべてのサードパーティー MCP ツールも非公開データの読み取りとして扱います。ツール名は完全一致で分類し、未分類の名前は非公開とみなします。公開ツール一覧との網羅性をテストします。

`wiki_write` の最終引数が `scope="shared"` なら Publish、非公開スコープは Modify です。ポリシー変更後の引数を使用します。

読み取り後は、プラットフォームの **Send、Publish、Purchase** と、引数を URL や送信先へ送れるツール（ウェブ取得を含む）を検査します。読み取りでも URL に非公開情報を含められるためです。完全一致の対象表には、Google・Notion・GitHub・Odoo・データベースへの検索やクエリ、ブラウザーの移動と入力、リモート音声処理、モデル・スキルの検索とダウンロード、タスクやスケジュール更新の通知先も含まれます。サードパーティー MCP プロキシでは非読み取りの決定を検査します。

Gateway は `DUDUCLAW_TURN_ID` をキーに、六時間の TTL を持つメモリ内台帳を管理します。MCP プロセスは署名付きループバック要求で接続し、六時間のキャッシュ期間中は読み取り済みフラグを解除しません。一件あたり最大 512 情報源とし、超過分は `additional_private_sources` にまとめ、期限切れを削除します。Gateway が登録した有効なターンだけが未読み取りと報告できます。ターン ID の欠落・未知、台帳の期限切れ、gateway の再起動・接続失敗、検証できない応答は読み取り済みとして扱います。

外部 API キーと HTTP MCP の呼び出しにも全体設定を適用します。Gateway が登録したターンを持たないため、常に読み取り済みとして扱い、MCP プロセスのスタッフの未読み取り状態を引き継ぎません。

認証済みスタッフは、ターン ID が欠落・未知・偽造の場合も gateway の検査を受けます。`ask`／`block` では同じスタッフに有効な sink lease が一つでもあれば、別の有効なターンを含め、非公開データの読み取りを拒否します。lease ストアを読めて有効な lease がなければ、未知・ID なしの読み取りは予約せず実行し、情報源を監査に記録します。独立した `duduclaw mcp init` と外部 API キーは別の外部 ID を使用し、引き続き読み取りできます。送信は読み取り済みとして `ask` で承認、`block` で拒否します。スタッフが gateway に接続できない、または応答を検証できない場合は、ターン ID がなくても強制モードで読み取りを拒否します。`shadow` は許可して監査します。

送信 lease は呼び出し元への許可前に gateway 管理の `<home>/egress_leases.db` へ保存します（SQLite WAL、synchronous FULL、Unix のデータベースと sidecar は 0600）。各行は lease ID、認証済みスタッフ ID、ターン ID、段階、UTC 取得時刻を持ちます。呼び出し元は許可を受けると直ちに送信できるため、ディスク上では許可前に `Dispatched` とします。伝送側は安全なキャンセルのためローカルの未送信状態を保持します。解放はディスクの行を削除してからメモリの fence を解除します。追加失敗時は `ask`／`block` で送信を拒否し、`shadow` は許可して監査します。削除失敗時は fence を保持します。

Gateway は loopback ルートの公開前に、有効な全行を「送信済み・終端不明」として復元します。復元された lease は期限切れでのみ解除し、生き残った旧プロセスからの release でも解除しません。再起動のたびに、復元行は UTC 時刻や時計の変動に関係なく、単調時計で新たに六時間保護します。行の削除は実行中の lease の終端確認、または連続稼働中の単調時計による期限切れに限ります。再起動を繰り返すと保護期間が延びますが、スタッフ別・全体の上限は維持します。HTTP の許可判定と定期メンテナンスは blocking pool で実行し、同じ台帳 mutex を共有します。待機中と実行中を合わせて最大 64 件です。非 loopback の接続元は blocking 処理の予約前に拒否し、容量超過時は直ちに HTTP 503 を返します。強制モードの呼び出し元はこれを拒否として扱います。ストアのオープン・読み取り・移行に失敗した場合、`ask`／`block` は全スタッフの非公開読み取り（登録済み・未知のターンを含む）と新規送信を拒否し、`shadow` は許可して監査します。五秒ごとに再試行し、エラーログは一分に一回までです。固定の 300 秒の再起動ウィンドウは廃止しました。ターンの情報源はメモリ内のままで、再起動後の未知のターンは読み取り済みと扱います。

Store は存続中に `<home>/egress_leases.lock` の排他ファイルロック（Unix 0600）を保持します。同じ home を使う二つ目の gateway は強制モードで読み取りと新規送信を拒否して再試行し、取得後に全 lease を復元してから読み取りを許可します。`shadow` は許可して監査します。Gateway の実行中はロックファイルを削除しないでください。有効な lease ID の重複は挿入前に拒否し、他のスタッフを停止しません。

登録履歴はスタッフごとの容量固定 Bloom filter に保持し、同じ gateway プロセスの存続中は消去しません。削除済み・期限切れのターンを再登録してもクリーンには戻りません。ハッシュ衝突や filter の飽和により、そのスタッフの新しいターンを保守的に読み取り済みと判定する場合があります。最大 1,024 スタッフ、各 32 KiB、合計 32 MiB です。上限を超えるスタッフのターンは常に読み取り済みとします。履歴は再起動後には保持されません。

## 復旧

Gateway ログの `egress lease store unavailable; private reads fenced` と `error` フィールドを確認してください。容量超過は `egress agent lease store over capacity` または `egress lease store over capacity`、不正な行は `invalid egress lease row` と表示されます。SQLite ファイルの破損ではデータベースエラーが出る場合があります。五秒ごとに再試行し、ログは一分に一回までです。`ask`／`block` では非公開読み取りと新規送信が拒否されます。Gateway の拒否理由は「外送防護紀錄無法讀取，暫停私人讀取及對外動作；請稍後重試。」ですが、呼び出し元では一般的な再試行メッセージになる場合もあります。現在、ダッシュボードと `doctor` に lease ストア専用の健全性表示はありません。

送信アクション（sink）が実行中の可能性がある間は、データベースを削除しないでください。並行する非公開読み取りを防ぐ唯一の fence が、その行に残っている場合があります。復元できない場合は、次の手順をオフラインで行います。

1. この home を使うすべての gateway を停止し、自動再起動も停止します。
2. 既存の `<home>/egress_leases.db*` を WAL／SHM sidecar とともに非公開の場所へバックアップし、権限を保持します。
3. スタッフの CLI プロセスと MCP／ツールの子プロセスがすべて停止し、送信アクションも終了したことを確認します。確認できなければ gateway を停止したままにし、ストアをリセットしないでください。
4. データベースと対応するすべての sidecar をまとめて別の場所へ移動し、バックアップを保持します。`egress_leases.lock` は削除しません。
5. Gateway を起動すると空の lease ストアが作成されます。**以前の送信 fence はすべて失われます。** 古いアクションが生き残っていると並行読み取りに対する保護がなくなるため、手順 3 の確認後にのみ再起動してください。ログのエラーが消え、読み取りと送信の許可判定が正常に動くことを確認します。

サポート対象のオフライン復旧コマンドを今後提供する予定です。本リリースには復旧 CLI はありません。

## 承認する前に

送信承認はワークフローの紐付けがなくても、現在の Admin だけが決定できます。チャネルからの承認は拒否します。管理者だけが閲覧できるダッシュボードの送信承認には宛先、展開済みでスクロール可能な完全な引数、読み取り元、有効期限が表示されます。Send、Publish、Purchase の承認も完全な引数を表示します。承認はスタッフ、ツール、正規化した完全な引数のハッシュに結び付けられ、一回だけ使えます。アクションルールも承認を求める場合、理由を同じ要求に追加します。

アクションルールによる承認には、一致したツールまたは効果のルールを表示します。読み取り・下書きツールも対象です。Purchase と Delete に常設の機能付与やワークフロー付与を新規作成することはできません。既存の付与は記録を変更せず無視します。ほかの検査と個別承認は引き続き必要です。

## CLI 組み込みツール（未リリース E1）

Claude と Grok に `PreToolUse` hook を追加し、`WebFetch`、`WebSearch`、Bash のリテラルなネットワークコマンドを検査します。Grok の別名は `Fetch`、`Shell`、`web_fetch`、`web_search`、`run_terminal_command`。実際の matcher と環境継承は実 CLI での検証待ちです。通常の非ネットワーク Bash は gateway に接続せず許可します。対象は `curl wget nc ncat netcat socat ssh scp sftp rsync ftp telnet http httpie aria2c lftp` と `git push/fetch/clone/pull/ls-remote`。Shell `-c`、`eval`、echo/printf 引数は最大二段、各 64 KiB まで再解析します。echo/printf のコマンド風データも保守的に対象になる場合があります。

| モード | 未読のターン | 非公開データを読み取り済み | 台帳を読めない／不明なターン |
|---|---|---|---|
| `off` | 許可 | 許可 | 許可 |
| `shadow` | 許可 | 許可し `would_ask` | 許可し `would_refuse_ledger_unavailable` |
| `ask` | 許可 | 承認カードを作成し再試行まで拒否 | 拒否 |
| `block` | 許可 | 拒否 | 拒否 |

Hook は元の引数を `/api/internal/egress-guard/hook-check` に送り、gateway が正規化、ハッシュ計算、カード生成を行います。クライアントの digest や要約は受け付けません。要求と応答に署名し、ポートは `config.toml` から読みます。Hook 専用のスタッフごと毎分 120 回の枠を使用します。依頼者は gateway に登録済みの実行コンテキストから復元し、確認できなければ承認を作成しません。

`ask` は先にカードを作成して拒否します。現在の Admin がダッシュボードで承認した後、同じターンで完全に同じ引数を再試行してください。スタッフ、ターン、ツール、全引数、読み取り元を紐付け、`WebFetch` はクエリを含む完全な URL を対象とします。同じ保留要求はカードを再利用し、読み取り元が増えたら旧カードを失効させます。承認は一回限りです。Bash の承認は直接実行する単純な一コマンド、一ネットワーク動詞のみ。展開、置換、パイプ、リダイレクト、`@file`、ラッパー、インタープリターは承認対象外で、理由を示して拒否します。紐付くのは文字列で、DNS、実行ファイル、設定ファイル、symlink の実体ではありません。

`ask`／`block` では捕捉できる hook エラーと panic は exit 2、インストール失敗はアカウント／runtime を切り替えず起動を停止します。`shadow` は警告して続行します。Claude の強制モードは `--setting-sources "" --settings <file>` で身分の `.claude/settings.json` だけを読み、他の project/local/user 設定を併合しません。cwd が別でも同じです。強制モードでは hook を省略する `cli_bare_mode` を拒否します。Grok は `--disable-web-search` を追加します。強制モードでは共有・借用 cwd や他スタッフの guard が残った hook ディレクトリを拒否します。独立したスタッフディレクトリ、または Claude/Codex を使用してください。

Codex の強制モードは `-c sandbox_workspace_write.network_access=false -c web_search="disabled"` を追加し、FullAccess を WorkspaceWrite に制限します。ReadOnly と MCP 自動承認器は保持します。個別コマンドの承認ではなく起動時の制限です。汎用 CLI は対象外のまま `would_refuse_unsupported_runtime` を記録します。Antigravity は変更せず、OpenAI 互換のツールループは既存の MCP 検査を使います。

Cron、dispatch、reminder、mail、heartbeat、ephemeral はチャネル requester と独立して host ターンを登録し、`DUDUCLAW_TURN_ID` を渡します。`default` の実際のスタッフ名も登録します。既存の読み取り済み状態は消さず、不明なクライアントターンは読み取り済みのままです。

**Bash hook は減速帯とテレメトリであり、隔離境界ではありません。** 組み込み `Read` と Bash のファイル読み取りは情報源を記録しません。インタープリター、スクリプト、別名、改名バイナリ、`/dev/tcp`、動的コマンドは検出を回避できます。hook が存在しない、終了させられた、タイムアウトした場合、上流 CLI が無視する可能性があります。同一 OS ユーザーの hook・鍵・環境へのアクセスは署名では隔離できません。ネイティブ事前検査は実行完了まで MCP sink lease を保持せず、検査後の並行読み取りも止めません。隔離が必要なら Bash を許可しないか、委任タスクの sandbox を使ってください。sandbox は全チャネル／CLI を覆うものではありません。Security ページは強制モードで Bash がありタスク sandbox が無効なスタッフを表示します。

E1 の検証状況：テストは作成済み、未実行です。この作業ではコンパイルも実 CLI プローブも行っていません。Claude/Grok の matcher、ターン／依頼者コンテキストの継承、承認と一回限りの再試行、gateway 障害、Claude の別 cwd、Codex 0.164.0 のネットワーク・検索制限と MCP 利用を後続で検証してください。

## 既知の制限

API ツールループへ `[[mcp.external]]` で直接登録したツール（stdio、HTTP、Google の閉じたブリッジ）も検査します。この経路のツール登録には MCP annotations が保持されないため、すべて保守的に **Modify** として扱います。サーバーが読み取り専用と説明していても、非公開データを読んだ後は送信承認が必要になり得ます。完全一致のツール別アクションルールは引き続き適用されます。MCP プロキシとリモートブリッジは annotations と `trusted_read_hint_servers` による既存の判定を使います。

情報源はターン単位で追跡し、実行中の送信 fence はスタッフ単位で適用します。この MCP 検査はネットワークサンドボックスを提供しません。未リリース E1 は上記の CLI 検査を追加しますが、runtime 全体のネットワーク隔離は提供しません。プロンプト内のデータや対象外の経路で読んだ情報は自動分類されません。新しいターンには新しいキーを使い、ターンをまたぐコピーは追跡しません。ターンの情報源は gateway 再起動後に保持されませんが、保存された送信 lease は復元します。記録のみのモードでは送信は許可されます。

[セキュリティ防御](05-security-defense.md)と[ダッシュボード設定](../../guides/dashboard-settings.md)も参照してください。

検証範囲：自動テストは分類、ゲート、承認の動作を対象とします。実際のスタッフと外部サービスを使ったエンドツーエンド検証は未実施です。

直接接続する外部 scoped／closed 操作は、承認カードより先に期限切れになる場合があります。その後の承認で呼び出しが再実行されることはありません。新しい呼び出しが必要です。古いカードは表示された期限まで承認待ちのまま残る場合があります。

サードパーティーの待機中呼び出しはプロセスごとに 512 件、期限は五分で、重複する実行中 ID は拒否します。終了時に対応表を消去しますが、キャンセルやタイムアウトの gateway フラグは残します。一度キャッシュした読み取り済み状態も保守的に維持します。

スタッフの送信呼び出しは実行直前に gateway 所有の sink lease を取得し、承認後にも情報源を再確認します。fence は認証済みスタッフに結び付き、そのスタッフの全ターンに適用されます。他のスタッフには影響しません。保持中は `ask`／`block` で非公開データの読み取りを即時拒否し、`shadow` では許可して `would_refuse_read_during_sink` を記録します。lease は未送信と送信済みの二段階で、部分書き込み前に送信済みにします。送信前のキャンセルは解放できます。送信後は対応する終端応答か確認済みの上流キャンセルだけが解放を許可します。ローカルのタイムアウト、キャンセル、タスク中止、panic、部分書き込み失敗、切断では **lease 取得から六時間**保持し、ターンの期限には依存しません。一スタッフ最大 512 件、gateway 全体で最大 65,536 件です。ターンの削除や容量不足で既存 lease は削除しません。lease 台帳が満杯なら強制モードで新規 lease を拒否します。ターンはスタッフごとに 4,096 件、全体で 65,536 件までです。登録を拒否する前に、保留中の読み取り・lease・情報源のないクリーンなターンを削除できます。削除または登録拒否されたターンは読み取り済みのままです。ターン容量不足で他のスタッフの lease を拒否しません。承認後に情報源が増えた場合は新しい呼び出しと承認が必要です。

プロキシの応答マスキング対応表も 512 件・五分に制限し、重複 ID は元の情報を上書きせず拒否します。ローカルで拒否した呼び出しは削除します。上流には固有 ID を送り、遅延応答が新しい呼び出しのルールを使わないようにします。期限切れの応答は渡しません。完了タスクを継続的に回収し、同時実行は最大 512 件です。

組み込みツールの完了は、確認済みのハンドラー契約を完全一致の名前一覧で判定します。ローカルのメール下書き、タスク・スタッフキュー、提案は永続化の完了を指し、後続作業の終了は意味しません。エラーでは保守的に fence を保持します。`model_search`、`model_download`、`skill_search`、`codrive_run`、`browser_record_start`、`os_open` は見かけ上成功してもlease の期限まで保持します。集約レポート、代替ダウンロード、バックグラウンド処理では、すべての送信の終了を確認できないためです。

リモートブリッジは呼び出しごとの generation wire ID を使用し、期限切れ応答を破棄します。元の ID が再利用されても、古い応答が新しい送信 lease を終了させることはありません。呼び出し側が予約済みの `duduclaw-egress:` ID 名前空間を使うと、明示的に拒否します。
