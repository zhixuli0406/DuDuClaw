# 保存瀏覽器登入

v1.76.0 新增的功能，適用於 Unix 主機上的容器瀏覽器，不使用你平常的瀏覽器設定檔。

管理員先到「設定 → 系統」開啟「允許保存瀏覽器登入」，再到員工權限開啟
「保存這位員工的登入」。兩個開關預設都關閉。設定檔的對應寫法：

```toml
# config.toml
[computer_use.profiles]
enabled = true
max_bytes = 67108864
retention_days = 30 # 0 表示不自動清除
```

```toml
# agent.toml
[capabilities]
computer_use = true
[capabilities.computer_use_config]
persist_login = true
```

需要先安裝含登入封存 helper 的容器映像，不會自動下載；舊映像會拒絕開啟保存功能。
主機既有的加密金鑰不可缺少，缺少時不會改寫明文。`duduclaw doctor` 會說明設定問題。

工作階段正常結束時，先關閉 Chromium，再封存 Cookies、Local Storage、IndexedDB。
gateway 以 AES-256-GCM 加密原始封存資料，綁定這台主機的資料目錄、員工實例與設定檔
身分，主機不解開封存檔。不保存偏好設定、密碼庫、擴充套件、快取、Service Worker。
每位員工預設最多 64 MiB，硬上限 128 MiB；保存失敗保留上一份快照。
整段保存限時 10 秒。新密文與索引分開提交；索引成功前，上一代快照仍可使用。
RED、緊急停止或注入暫停後結束時不保存目前登入；接手權限的人可在暫停後
結束的對話框明確勾選「保留登入」。紅色威脅與緊急停止仍會拒絕保存。

下次開啟時，容器先還原，再啟動 Chromium。白名單少了一個網站就清除整份快照，
只增加網站則保留。同名員工重建、負責人或主要負責人變更、負責人停權，都不能沿用
舊負責人的快照。刪除或封存員工會清除保存資料。「清除登入狀態」會先結束目前的
瀏覽器、不匯出，再清除快照，權限與接手瀏覽器相同。
`duduclaw ops computer-profiles list` 只能列出中繼資料。

保存登入後，遭網頁操控的員工也可能以該帳號操作。請縮小網站白名單，並為點擊、
輸入設定需要審核的操作規則。人可以透過接手登入；剪貼簿貼上維持停用。
當機、緊急移除容器或 gateway 關閉，可能丟掉上次成功保存之後的變動。
部分網站仍會要求重新登入或裝置驗證。匯出、手動備份與排程備份都排除這些快照。

驗證範圍：封存白名單、連結、路徑與大小限制測試已在本機執行；最終 Rust、
dashboard、真容器還原、真網站登入與跨平台驗證仍待完成。即時畫面與本機桌面
瀏覽器屬於另外的工作包。
