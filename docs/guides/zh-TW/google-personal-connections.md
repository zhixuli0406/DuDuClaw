# 連結自己的 Google（企業版，未發布）

讓 AI 員工使用你自己的 Google，不必更動公司共用帳號。哪些員工可以用，要由你本人決定；你隨時可以收回。

## 連結前

請管理員先在「整合 → Google」設定 Google 應用程式，適時開啟 Google 整合，並把憑證保護改放支援的系統金鑰圈。個人憑證會用這把保護金鑰封存；只有密碼保護、金鑰圈不可用或紀錄無法讀取時，一律拒絕個人存取。Linux 與 Docker 目前沒有支援的系統金鑰圈。

管理員必須在 Google 應用程式登記「我的連線」顯示的完整返回網址，路徑結尾為 `/api/me/google/callback`。允許清單內的 HTTPS 控制台使用原網址；其他網址改用同連接埠的 HTTP 本機回送位址，並提供貼上完成。完整路徑與連接埠必須符合 Google 登記值。遇到返回網址錯誤，請修正登記，不要放寬登入或公開本機回呼。

Google 的「外部」應用程式若處於「測試」狀態，更新憑證會在七天後到期；Google 列出的純基本身分權限例外，不適用於這裡要求的工作服務。Workspace 內部應用程式與個人 Gmail 的正式審核是不同情境，受限 Gmail 權限可能另須 Google 驗證與安全評估。正式使用前請管理員完成適用程序。參考 [Google 憑證規則](https://developers.google.com/identity/protocols/oauth2#expiration)及[網頁應用程式授權說明](https://developers.google.com/identity/protocols/oauth2/web-server)。

## 連結帳號

1. 登入企業版控制台，打開「我的連線」，按「連結我的 Google」。舊的登入憑證必須先重新登入。
2. 在新視窗完成 Google 授權。你可以取消某些服務，只會保存 Google 實際回傳的開放範圍；沒開放的服務不能用。
3. 瀏覽器回到「我的連線」。如果最後的本機回送頁面無法載入，將網址列的完整網址貼回原控制台；不要把該網址傳給別人。
4. 核對已連結的 Google 信箱。它可以和 DuDuClaw 登入信箱不同，畫面會明確提醒。
5. 管理員尚未開啟 Google 整合時，連線先保存；個人連結不會自動打開全機開關。

返回代碼本身不能完成連結。系統會要求同一位使用者、同一次已驗證的控制台登入，且十分鐘內完成；已用過、過期、被新操作取代或已中斷的流程不能重用。存取與更新憑證不會出現在控制台回應、網址、使用紀錄或員工設定。

## 允許員工使用

管理員可在員工的「連線」選「跟著負責人」或「指定同事」。指定人必須是有效、直接綁定的 Owner。多位 Owner 時優先使用明確指定的主要負責人；舊的多 Owner 資料沒有指定者，必須由管理員選擇。新增第二位 Owner 時保留原本唯一的 Owner 為主要負責人；主要負責人被移除或降權後不保留該身分，若只剩一位 Owner，則自動解析為那位。

變更主要負責人前，畫面會要求確認：系統先停止這位員工進行中的瀏覽器工作階段，並清除儲存的瀏覽器登入，再套用新負責人。清除失敗時不變更主要負責人。最後寫入的同一筆交易會重新確認管理員仍有效、具管理權限且沒有必須變更密碼的要求，因此等待瀏覽器清理期間被撤銷的權限不能用來完成變更。即使從 A 換成 B 再換回 A，也不會恢復 A 原本的瀏覽器登入。

主要負責人變更的同一筆交易也會遞增這位員工的負責人版本。儲存的瀏覽器登入會在同一份資料庫快照核對版本與 Owner 資料，因此兩次重疊的 A→B→A 變更，也不能恢復在清理後、寫入前建立的登入；其他員工各自維持自己的版本。這次更新後，舊格式儲存的瀏覽器登入會在下次使用時清除，需要重新登入以建立新狀態。

Owner 可以選「用我的 Google」或「不使用」，也能縮小發問者範圍、關閉公司帳號備援；不能擴大範圍或選別人的帳號。儲存自己的帳號前，畫面要求確認誰也能透過員工使用。

管理員設定不等於本人同意。帳號本人要到「我的連線」逐位允許或拒絕；決定前會顯示綁定同事、允許通道與發問者規則。公開訪客一律拒絕。排程工作仍須通過員工、人員狀態及同意檢查；`owner_only` 的工作若帶有真人發問者，只能是帳號本人。

本人關閉後，後續呼叫立即拒絕，管理員也不能代為同意。一般員工編輯器不能新增自己的帳號選擇，請走「連線」，讓本人同意與稽核一起記錄。

員工專屬外部連線金鑰不會識別真人發問者。預設拒絕個人帳號使用；管理員可明確設 `requesters = "anyone"`，允許這類已授權外部工具，但仍需要帳號本人同意。公開網站訪客即使在 `anyone` 下也一律拒絕。

## 管理與中斷

- Google 失效或需要額外服務時按「重新連結」。每次呼叫都重查有效人員、Owner、同意、Google 應用程式、已開放服務與連線版本；更新憑證只在 gateway 執行，同一人的並行更新會排隊。
- 「中斷連結」先刪除本機連線並取消待完成流程，再嘗試撤銷 Google 授權。管理員也可在「整合 → Google」中斷指定人；離職與移除帳號會清除個人連線。即使清除失敗，停用人員仍然不能使用。
- Google 撤銷可能影響整份授權。其他個人紀錄使用同一 Google 識別或信箱、或公司共用帳號相同時，只刪本機。紀錄讀不懂、橋接帳號未知、公司憑證過期或帳號查詢失敗，也不撤銷 Google 端。若你要撤銷整份授權，請自行到 Google 已連結應用程式檢查。
- 公司授權代表與個人連線分開，中斷個人連線不會刪除公司網域委派。
- 最近三十天紀錄最多顯示目前保留的五百筆時間、員工、工具名稱及成功狀態，不回傳輸入、輸出或信件內容。舊紀錄可能已輪替移除。
- 個人來信逐封過濾；有效本人可讀自己的已連結帳號來信。共用、舊資料與放入資料夾的信仍採較嚴權限；讀取權限不會開放寄信或核准外寄。

## 撤銷結果不明與離線復原

取得授權、核對帳號到保存連線，和撤銷判斷及供應商請求共用跨行程協調鎖，涵蓋公司共用 OAuth 回呼、CLI／原生工具共用的更新路徑，以及動態遠端 OAuth 交換與更新。本機中斷與持久版本守門一定先完成，才等鎖。升級時請重啟所有 gateway／CLI 行程，避免舊行程繞過新協調。

只把可信 Google 撤銷端點對「這次請求」的同步 HTTP 200 回覆視為確認。其他回覆、網路錯誤、逾時、取消，或送出後當機，都保留 `<home>/locks/google-grant-revoke-uncertain.json`；此檔在請求前已寫入並同步落盤。檔案存在時拒絕新的 Google／遠端授權，已中斷者的本機使用權持續停止。遠端帳號不明、其他公司 OAuth 紀錄無法確認或帳號查詢失敗時，僅中斷本機，回傳 `provider_revoked=false` 並稽核原因。

沒有線上清除介面，也不會等一段時間自動放行。再次撤銷成功、換用戶端 ID、Google 帳號設定頁面，都不能證明先前逾時的請求已停止。復原是**依賴外部人工查證的安全例外**，不是程式能確認已解除風險：

1. 保持新連線停用，保存不確定紀錄、操作代號、相關稽核與事件紀錄。
2. 在 Google 端撤銷舊應用程式授權，並取得先前請求已結束的外部確認。無法確認就保留守門，向供應商查證，不猜等待時間。
3. 停止使用此資料目錄的所有 gateway／CLI。只有完成外部查證後，離線操作人員才能將該檔移出作用中的檔名，保留操作代號與理由供稽核；不要刪其他憑證或鎖檔。
4. 重啟後由帳號本人重新連結，事件紀錄註明此次放行依賴外部證據、由操作人員執行；產品並未程式驗證遠端晚到請求風險已消失。

不同 OAuth 用戶端可能仍屬同一 Google Cloud 專案，因此換用戶端 ID 不能作為自動復原的證明。

Unix 必須成功同步守門檔、locks 目錄及 home 父目錄後才送撤銷。Windows 目前缺少所需的目錄持久化實作，因此個人中斷只刪本機；正常連結及更新仍可用。Unix 測試不能視為 Windows 耐斷電證據。動態遠端 OAuth 一律只中斷本機，不依當下是否存在個人／公司憑證檔判斷；那些應用程式請本人到服務商撤銷。

## 管理員參考

```toml
# config.toml
[integrations.google_identity]
allowed_domains = ["example.com"] # 留空不限
# agent.toml
[google]
identity = "owner"               # 或 "user:<直接 Owner 的 id>"
fallback = "none"                # 管理員可明確改為 "home"
requesters = "bound_people"      # 或 "owner_only"；"anyone" 須明確確認
```

`allowed_domains` 優先核對 Google 回傳的組織網域，否則核對信箱網域；它限制帳號網域，不是獨立的 Workspace 成員資格證明。無法辨識的設定一律拒絕。

本人操作介面為 `me.google.status`、`connect_start`、`connect_finish`、`connect_paste`、`disconnect`、`consents.set`（後五者同屬 `me.google`）。使用者代號由已驗證登入決定；`users.google_disconnect`、`agents.primary_owner_set` 限管理員。個人連線入口僅企業版提供，個人版沿用既有共用／home 連線。

封存紀錄在 `<home>/person_credentials/store.json`，目錄及檔案只限系統使用者存取，並保存版本守門；不搬動既有公司 OAuth 紀錄。備份或搬機時請保留支援的系統金鑰圈；使用個人連線期間不支援降版。

這些平台守門不會隔離與 gateway 使用相同 OS 帳號、又有不受限 Bash 的員工；它仍可能繞過產品路徑或改寫本機資料。請只給必要能力。另外，Google 的 Gmail 草稿權限本身也能寄信，雖然原生草稿工具不會寄出。

另見：[原生 Google Workspace](google-workspace.md)、[Google PKCE 說明](https://developers.google.com/identity/protocols/oauth2/native-app#step1-code-verifier)、[OpenID 帳號資訊](https://developers.google.com/identity/openid-connect/openid-connect#obtaininguserprofileinformation)、[Google 撤銷授權](https://developers.google.com/identity/protocols/oauth2/web-server#tokenrevoke)。
