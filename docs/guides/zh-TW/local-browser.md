# 本機專用瀏覽器

原有工具封鎖、階段性授權、動作規則與動作審查仍會生效。若規則要求核准截圖或捲動，只能由本機原生 app 決定。導覽會保留原本 Modify 規則，並額外檢查 Send 規則。停止不等待核准。遮罩後的本機畫面只透過記憶體回傳當下回合，不存成稽核截圖。

這裡的「不落盤」只限 DuDuClaw 本機 viewport 與核准內容的稽核路徑。傳給模型的圖文、網址與按鍵仍可能留在外部執行器的對話紀錄、供應商快取或模型回覆；回覆也可能成為一般對話紀錄。專用 Chrome profile 會保存網站狀態。這項功能不保證頁面內容不被模型或其他系統留存。

本功能預設關閉。只有 macOS 本機桌面 app 自己啟動的 gateway，能開啟獨立的 Chrome 或 Edge 視窗與專用 profile。個人版與企業版使用相同守門；Windows、Linux、遠端或僅附掛的 gateway 均拒絕使用。

管理員必須同時開啟 `config.toml [computer_use.local_browser] enabled = true`，以及員工 `[capabilities.computer_use_config] local_browser = true`。儀表板開啟全域開關前需明確勾選風險說明。員工原有的 `computer_use = true` 與容器模式仍需保留；已移除的桌面 native 模式不會恢復。網站沿用員工 `allowed_domains`，只接受精確 HTTPS 主機名稱，不接受萬用字元、本機或私有 IP。

呼叫 `computer_session_start` 時指定 `target: "local_browser"`；未指定時仍為 `container`。其餘電腦工具作用於該員工唯一的 session。本機操作還需要正在處理的已驗證人類對話，以及桌面 app 的原生在場通道。排程、派工、goal 背景回合、heartbeat、公開訪客，以及繼承的上游 turn ID 或代辦身分，都不能冒充當下的人類呼叫。尚未接上可信入站證明的通道維持拒絕；失敗不會自動改開容器。

也可從 macOS app 的原生選單按「讓 AI 開瀏覽器…」，在系統對話框輸入員工代號。啟動意圖有效六十秒、只能使用一次，並重新核對原生配對、設定與有效負責人綁定。稽核來源為「本機原生使用者（平台身分未驗證）」；這個操作不代表具名負責人，也不建立聊天身分或授予 AI 讀取權。選單列圖示在瀏覽器運作時變色，並提供停止。

AI 第一次讀取現有頁面時，須取得本機原生同意。這份同意只在記憶體保留，綁定確切的人類回合及目前呼叫連線，最長六十秒。新回合、重建連線、請求人變更、負責人交接（含 A→B→A）、設定變更或原回合結束，都需要重新核准。這適用於遮罩截圖、頁面文字及標題；桌面按鈕啟動本身不會預先授權讀取。

核准卡提供可捲動的完整動作明細，包括輸入文字、按鍵、導覽網址、點擊座標與網頁宣稱的目標描述。目標描述本身不可信，請一起核對縮圖。明細過長時會拒絕，不會截斷後要求核准。操作核准若同時更新目前回合的六十秒讀取同意，卡片會明確告知。

控制器仍在線與人在場是兩件事。gateway 只依收到已簽原生心跳的本機時間維持本機 session，讓手動登入或 2FA 不會被一般容器的 120 秒工具閒置期限中斷；原本的 session 時間上限仍有效。這不建立身分、人在場證明或讀寫同意，螢幕鎖定、閒置、人類操作及回合／連線失效仍各自拒絕 AI 讀寫。控制器失聯三十秒仍會結束 session。

請親手在專用視窗登入。AI 不能在密碼、檔案或已辨識的憑證欄位輸入。每次點擊、輸入、按鍵與導覽，都必須經原生對話框核准。捲動與遮罩後的 viewport 截圖不會放寬這個規則。選單列提供停止與繼續；螢幕鎖定、閒置，或人在瀏覽器操作時，AI 會凍結，需本人從原生選單按繼續。桌面 app 心跳超過三秒未到即拒絕操作，三十秒結束。關閉專用視窗也會結束。所有儀表板帳號（包括 Admin）只提供狀態與停止，不能取得頁面快照、VNC、接管、重置或核准。

狀態保存在 `<home>/local_browser/<員工>/profile`，不匯入平常的瀏覽器資料。Chrome 使用作業系統憑證儲存區；CDP 只走繼承的 pipe，沒有 TCP debug 入口，也不關閉 Chrome 原生沙箱。連線經隨機帳密的 CONNECT proxy，只放白名單主機、公有 IP，並連到已核對的 IP。WebRTC 必須實際套用專用 profile 設定，只有旗標不足以防止 UDP 旁路。下載、上傳、新 target、非 HTTPS 導覽、網站權限及瀏覽器／剪貼簿快捷鍵均拒絕。備份必須排除此目錄。交接或刪除員工會使 profile 失效，白名單縮小後重新使用前會整份重置。

這是原生宿主的信任邊界，沒有另建 OS 帳號或虛擬機。同一個 OS 使用者若能執行不限權限的程式，仍可繞過產品守門。出貨時必須重新驗證瀏覽器版本與連線行為，不能把旗標或 mock 結果當成旁路已被阻擋。

瀏覽器啟動前會持久記錄「退出尚未證實」，只有核對專用行程全部結束後才清除。gateway 當機、初始行程盤點失敗或清理不確定，都會阻止下一次本機啟動。`duduclaw doctor` 會提供租約檔位置。復原須由離線操作者先停止 app／gateway，保留稽核與租約檔副本，依稽核的 PID、出生時間與執行檔核對所有專用行程已退出；不確定時不要清除，也不要依 Chrome 名稱批次終止。確認後只截短 doctor 指定的原租約檔為零長度，不刪除／換掉檔案，也不清平常的瀏覽器 profile。產品不自動解除此封鎖。

目前驗證界線：Chrome 156 的合成 native pipe／proxy／UDP／下載 spike 已通過，先前 STUN 漏包與清理無效的執行結果仍保留。完整 backend／桌面 app 整合、實際鎖屏、本人登入供應商，以及出貨放行，仍是獨立關卡；spike 不代表產品已驗收。
