# 外部系統查詢 AI 員工狀態

讓公司的業務系統（例如 Odoo 首頁的「我的 AI 助理」卡片）讀取 AI 員工目前的工作狀態：進行中幾件、等你確認幾件、今天與近 7 天完成幾件，以及最近完成的一件工作標題。外部系統只拿得到數字與狀態，拿不到任何對話內容或任務說明。

英文版：[External systems: query AI employee status](../external-status.md) · 日本語：[外部システムから AI 社員の状況を照会する](../ja-JP/external-status.md)

## 會看到哪些員工

看到的員工，就是建立憑證那位同仁「帳號上直接綁定」的 AI 員工，每次查詢都即時重新讀取：

- 管理員解除綁定，下一次查詢就不再出現那位員工。
- 帳號被停用或刪除，憑證立即失效；帳號被離職處理（offboard）時，憑證會永久撤銷。
- 主管透過部屬取得的「團隊」權限不算在內，只看本人直接綁定的員工。
- 已封存或已刪除的 AI 員工不會出現。

## 1. 管理員開啟功能

功能預設關閉。關閉時，所有查詢一律回應與「網址不存在」相同的 `404`，也不能建立新憑證；已建立的憑證會保留（暫停運作），重新開啟後，尚未撤銷的憑證即可繼續使用。

**在儀表板開啟：** 管理員到「設定 → 進階 → 安全與紀錄」，展開「外部系統查詢」並打開開關。開啟前請先閱讀頁面上黃色的「開啟前請先了解」提示：外部系統只拿得到件數與最近完成一件事的標題（個人資料已遮蔽）、拿到憑證的人就能看到這些資訊、每人最多 5 組憑證、關閉後所有憑證立即暫停。同一區的「所有同仁的憑證」表格列出每個人的憑證（不含憑證本身），管理員可按「撤銷」（會先跳出確認視窗；立即生效且無法復原）。被管理員撤銷的憑證，在該同仁的「外部系統存取」頁會顯示為「已撤銷」。

或在 `config.toml` 加入：

```toml
[external_status]
enabled = true
```

或由管理員呼叫 `system.update_config`，參數 `{"external_status_enabled": true}`。不需要重啟 gateway：在儀表板變更，下一次查詢即生效；直接修改 `config.toml` 則在 2 秒內生效（設定最多快取 2 秒）。

## 2. 同仁建立自己的唯讀憑證

每位同仁在儀表板的「外部系統存取」頁（左側選單「設定」群組；員工帳號從左下角的帳號選單進入）替自己的帳號建立、撤銷憑證：

- 管理員尚未開啟時，頁面顯示「管理員尚未開啟這項功能」，「建立憑證」無法按。
- 清單顯示名稱、建立時間、最近使用與狀態（使用中／已撤銷）。
- 「外部系統會拿到的資料」卡片說明外部系統會收到的五項資料：進行中、等待確認、今日完成、7 日完成、最近完成一件事。
- 按「建立憑證」輸入名稱後，會出現只顯示一次的憑證視窗：請按「複製」貼到外部系統，確認後按「我已複製，關閉」。視窗關閉後就再也看不到憑證；弄丟的話請撤銷後重建。
- 使用中的憑證達 5 組時，「建立憑證」會停用並顯示提示。

頁面背後呼叫的 RPC，也可由其他用戶端直接使用：

| RPC | 參數 | 說明 |
| --- | --- | --- |
| `me.status_tokens.create` | `{"name": "Odoo 卡片"}` | 建立憑證。名稱 1–60 個字。回應中的 `secret`（`ddc_status_…`）**只顯示這一次**，請立刻貼到外部系統。 |
| `me.status_tokens.list` | `{}` | 列出自己的憑證（名稱、建立時間、最後使用時間、是否已撤銷），永遠不含憑證本身。 |
| `me.status_tokens.revoke` | `{"id": "…"}` | 撤銷自己的一組憑證，立即生效。 |

每個帳號最多同時保有 5 組有效憑證，已撤銷的不計入。管理員可用 `status_tokens.admin_list` 查看所有人的憑證（不含憑證本身），用 `status_tokens.admin_revoke {"id": "…"}` 撤銷任何一組。

這些 RPC 的錯誤碼（儀表板會顯示對應的繁體中文、英文或日文訊息）：

| 錯誤碼 | 意思 |
| --- | --- |
| `external_status_disabled` | 管理員尚未開啟這項功能。 |
| `status_token_invalid_name` | 名稱必須是 1–60 個字。 |
| `status_token_limit_reached` | 已有 5 組有效憑證，請先撤銷一組。 |
| `status_token_account_inactive` | 帳號未啟用，不能建立或使用憑證。 |
| `status_token_not_found` | 找不到這組憑證（或不屬於你）。 |
| `status_token_unavailable` | 暫時無法處理，請稍後再試。 |

伺服器只保存憑證的 SHA-256 雜湊值；遺失憑證時無法找回，請撤銷後重新建立。

## 3. 外部系統查詢

網址是 **儀表板 gateway** 的位址（與登入儀表板相同，例如 `https://ai.example.com`，本機預設 `http://127.0.0.1:18789`），不是 MCP 伺服器的位址。

```bash
curl -s https://ai.example.com/api/v1/status/employees \
  -H "Authorization: Bearer ddc_status_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"
```

只看其中一位員工：

```bash
curl -s "https://ai.example.com/api/v1/status/employees?agent_id=sales" \
  -H "Authorization: Bearer ddc_status_…"
```

回應：

```json
{
  "generated_at": "2026-11-08T09:30:00.000000000+00:00",
  "employees": [
    {
      "agent_id": "sales",
      "display_name": "業務小幫手",
      "in_progress": 3,
      "awaiting_confirmation": 1,
      "done_today": 2,
      "done_7d": 9,
      "latest_done": { "title": "整理第四季客戶報價", "completed_at": "2026-11-08T08:12:45+00:00" }
    }
  ]
}
```

| 欄位 | 意思 |
| --- | --- |
| `in_progress` | 進行中與排隊中的任務（待辦、排隊、執行中、修改中）。 |
| `awaiting_confirmation` | 等人處理的任務（待審查、需要人工確認、待核准），加上這位員工尚未決定的核准請求；核准請求只計入這位同仁在儀表板核准中心看得到的部分（主管〔Manager〕以上）。 |
| `done_today` | 今天（gateway 主機時區）完成的任務數。 |
| `done_7d` | 最近 7 天完成的任務數。 |
| `latest_done` | 這位同仁看得到的最近完成任務：標題與完成時間；沒有就是 `null`。**只有安裝了本機個資偵測模型時才會給標題**（資料遮蔽規則組「AI 智慧偵測」的模型，即在本機執行的 OpenAI Privacy Filter；勾選該規則組時可從卡片下載，詳見[資料遮蔽說明](../../features/55-data-sources.md)），而且模型必須成功掃過這個標題；否則 `title` 一律為 `null`，只給 `completed_at`。偵測前會先移除看不見的字元、零寬字元與雙向控制字元，並做 NFKC 正規化；若同一個詞混用外觀相似的字母系統（例如拉丁字母的電子郵件裡夾了一個西里爾字母 `а`），`title` 為 `null`。接著標題會先遮蔽、再截成最多 60 個字：模型找到的姓名、地址、電子郵件、電話與帳號，以及憑證類字串、電子郵件、電話號碼（含全形數字與 `+886`）、身分證／居留證號、連續 8 位以上的數字（帳號、客戶、卡號）、有標籤的識別資料（「帳號」「客戶編號」、`account no.`）、帶稱謂的姓名（「王先生」、`Mr. Smith`）以及共用 wiki 人員名錄中的姓名，都會變成 `＊＊＊`；截短後的結果會再檢查一次。模型執行失敗或任何部分無法安全遮蔽時，`title` 為 `null`。模型能降低、但無法保證完全沒有個人資料。 |

所有數字都以這位同仁在儀表板看到的範圍為準：其他帳號透過 A2A 發起的任務、團隊交接對象不含這位同仁的任務、以及他無權讀取的核准請求都不會計入，所以綁定同一位員工的兩個人，看到的數字可能不同。

回應不含對話內容、任務說明、任務 id 或任何其他 id，只有 `agent_id`。

### 錯誤回應

| 狀態碼 | 何時 |
| --- | --- |
| `404 {"error":"not_found"}` | 功能未開啟；或 `agent_id` 不是這位同仁綁定的員工。 |
| `401 {"error":"unauthorized"}` | 沒帶憑證、憑證錯誤、已撤銷，或帳號已停用。 |
| `400 {"error":"bad_request"}` | 帶了 `agent_id` 以外的查詢參數，或 `agent_id` 重複、格式不對。 |
| `405 {"error":"method_not_allowed"}` | 不是 `GET`。 |
| `429 {"error":"rate_limited"}` | 同一組憑證每分鐘超過 60 次、同一來源位址每分鐘超過 240 次（IPv6 以 /64 計），或全部合計每分鐘超過 600 次。等 `Retry-After` 秒數後再試。 |
| `503 {"error":"unavailable"}` | 暫時讀不到任務、核准、身分或存取資料（不會用 0 代替），或 gateway 已在處理 4 個狀態查詢、2 秒內都沒完成（`Retry-After: 5`）。 |

在儀表板關閉功能，下一次查詢即生效；直接修改 `config.toml` 則在 2 秒內生效。

## 安全說明

- 這是獨立的憑證類型，只能呼叫這一個網址。儀表板登入、`/api/*`、MCP 伺服器（`/mcp`、`/mcp/v1/call`、`/ingest/transcript`）一律拒絕 `ddc_status_` 開頭的憑證；它也不是 MCP API 金鑰（v1.82 起存在 `mcp_keys.db`），不受 MCP scope 設定影響。
- 回應沒有 CORS 標頭，只供伺服器對伺服器呼叫，不要放在瀏覽器前端程式碼裡；回應帶 `Cache-Control: no-store`。
- 每次可辨識的呼叫都會稽核（憑證 id、帳號 id、結果、員工數），不記錄回應內容。呼叫依「憑證、結果、每 10 分鐘」彙總：該時段第一次呼叫寫入一筆 `status_token.used`／`status_token.refused` 稽核紀錄，同時段之後的呼叫只累加次數與最後時間，所以每秒輪詢一次的整合，每種結果每小時最多 6 筆。憑證的最後使用時間每 10 分鐘最多更新一次。這些稽核紀錄與次數保留 90 天，之後分小批自動刪除；其他稽核紀錄不受影響。
- 建議走 HTTPS；憑證外流時立即撤銷。

## Odoo 注意事項

- 現有的 DuDuClaw Connector 模組把「Gateway URL」用於 `/ingest/transcript`（MCP 伺服器）並使用 MCP API Key。查詢員工狀態需要的是 **儀表板 gateway 網址** 與同仁自己的 `ddc_status_` 憑證，兩者不能互換。
- 每位同仁的卡片應使用他自己的憑證，才只會看到自己綁定的員工；不要讓全公司共用一組。
- Odoo 主機需要能連到儀表板 gateway。卡片的實作（Odoo 端模組更新）不在本次範圍。
