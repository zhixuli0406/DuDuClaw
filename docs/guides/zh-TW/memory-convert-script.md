# 把簡體字記憶轉成繁體字（v1.84.0）

v1.84.0 以前，AI 員工自己寫下的記憶（重點事實、對話記憶）用的是模型輸出時的字體，所以平常用繁體中文的安裝，也可能存了一些簡體字的記憶。從 v1.84.0 起，新記憶的語言由「記憶語言」設定決定（見[儀表板設定對照](dashboard-settings.md#記憶語言與背景工作v1840)），繁體中文的輸出在存入前也會再做一次字體校正。升級前存下的記憶維持原樣，要轉換這些既有記憶，請用 `duduclaw memory convert-script`。

這個指令給管理者在執行 DuDuClaw 的那台機器上使用。它不會出現在 `duduclaw --help` 裡（`memory` 這組指令是隱藏的），但可以照下面的方式直接執行。

## 會改什麼、不會改什麼

- 只轉換 `<home>/memory.db` 裡的兩種文字：重點事實與記憶條目。wiki 與知識頁面、對話摘要、已固定的指示都不會動。
- 條目裡有簡體字才會轉換。台灣慣用的繁體中文內容完全不會被改動。
- 轉換使用 DuDuClaw 內建的 OpenCC 詞組字典（簡體轉台灣繁體），會依詞組判斷字形，所以「头发」轉成「頭髮」，「发现」轉成「發現」。不呼叫模型，也不翻譯：用詞不會被替換（「软件」轉成「軟件」，不會變成「軟體」；「信息」維持「信息」），英文或日文的記憶維持原本的語言。
- 採用台灣字形「台」「帳」「濕」。條目本身已經寫了「臺」「賬」「溼」時，保留原本的寫法，被轉換的部分也跟著用這個字形。
- 含有日文假名的條目整筆略過，計入 `skipped_japanese`。
- 網址（`scheme://…`、`mailto:`、`www.`）、Markdown 連結的目標、行內程式碼、程式碼區塊，以及明確的檔案路徑（以 `/`、`./`、`../`、`~/`、`\\` 或 `C:\` 這類磁碟代號開頭）都原樣保留。
- 只有內建的 n-gram 雜湊嵌入器產生的向量會重新產生。其他嵌入模型產生的向量會被清除，這些記憶在重新建立向量之前不參與相似度比對（發生時輸出會提醒）。

範例（取自轉換程式的測試）：

| 轉換前 | 轉換後 |
|---|---|
| 用户要求：这个项目的预算是三万元，负责人是张经理 | 用戶要求：這個項目的預算是三萬元，負責人是張經理 |
| 账户资料 | 帳戶資料 |
| 头发、发现、软件、信息 | 頭髮、發現、軟件、信息 |
| 用户预算三万元 `回复` /tmp/预算.txt | 用戶預算三萬元 `回复` /tmp/预算.txt |

## 會轉換哪些 AI 員工

| 指定方式 | 行為 |
|---|---|
| `--all` | 記憶語言判定結果正好是 `zh-TW` 的每位員工。其他員工會列為略過，並寫出判定到的語言。找不到員工資料夾的記憶空間也會略過（這種情況請改用 `--agent`）。 |
| `--agent <id>` | 轉換這位員工的記憶。判定結果是 `zh-CN` 或日文時會拒絕，除非加上 `--force-language-mismatch`（只能和 `--agent` 一起用）。設定為 `en` 或沒有判定出語言的員工，不需要額外參數就會轉換。 |

判定語言的順序和新記憶相同：員工自己的記憶語言 → 全域記憶語言 → 員工的回覆語言（或全域預設語言）。

## 步驟

1. 先預覽。沒有加 `--yes` 時只會計數，並列出最多十筆轉換前後的範例：

   ```bash
   duduclaw memory convert-script --all
   ```

   每位員工一行，例如 `alice: preview key_facts=12, memories=40, changed=52, skipped_japanese=1, embeddings_cleared=0`。

2. 確定要轉換時：

   ```bash
   duduclaw memory convert-script --all --yes
   ```

   動到第一筆資料之前，指令會先寫好還原檔並印出路徑（`Restore file: …`）。檔案位置是 `<home>/backups/memory-convert-script-<UTC 時間>-<員工>.jsonl`，只有擁有者能讀。每位員工各自在一個交易裡完成；其中一位失敗時，其他人照常繼續，指令最後回報錯誤。

3. 需要復原時：

   ```bash
   duduclaw memory convert-script --restore <home>/backups/memory-convert-script-…jsonl
   ```

   還原是整個檔案一起還原，要嘛全部成功、要嘛完全不動。轉換之後只要有任何一筆被改過，還原就會被拒絕。

## 參數

| 參數 | 用途 |
|---|---|
| `--agent <ID>` | 只轉換這位員工的條目。 |
| `--all` | 記憶語言判定為繁體中文的每位員工。 |
| `--restore <FILE>` | 復原先前的轉換。不能和 `--agent`、`--all`、`--dry-run`、`--yes`、`--force-language-mismatch` 一起用。 |
| `--force-language-mismatch` | 只能搭配 `--agent`（和 `--all` 或 `--restore` 一起用會被拒絕）：員工設定為簡體中文或日文時仍然轉換。使用 `--all` 時，記憶語言不是繁體中文的員工一律略過。 |
| `--dry-run` | 只預覽。和 `--yes` 同時給時以預覽為準。 |
| `--yes` | 實際轉換。 |

`--agent`、`--all`、`--restore` 三者必須剛好指定一個。

## 限制

- 在 AI 員工的工作階段裡執行會被拒絕，並在安全稽核紀錄留下 `memory_script_conversion_refused`；員工也無法透過自己的指令列工具啟動它。實際轉換與還原分別記為 `memory_script_converted`、`memory_script_restored`。
- 用詞不會被改寫，大陸用語轉成繁體字後仍是大陸用語（软件 → 軟件、信息、项目 → 項目）。
- 同一筆條目混用兩種字體時，兩種字體共用的字會依詞組判斷，可能改變字形，例如「了解」會變成「瞭解」。詞組判斷可能出錯，套用前請先看預覽的範例。
- 內建字典無法載入時，會改用舊的對照表，要看上下文才能決定寫法的字維持不變。
- 頁面與摘要不會被轉換。v1.84.0 之後新產生的頁面與摘要會依記憶語言設定書寫。
