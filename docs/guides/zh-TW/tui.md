# 終端控制室

[English](../tui.md) · [日本語](../ja-JP/tui.md)

`duduclaw tui` 集中顯示待審核事項、等待你回覆的目標任務，以及員工狀態。選取一列即可查看詳情；閘道有提供下次自主執行時間時，管理員也能看到排程。關閉控制室不會停止員工。

全螢幕控制室已提供審核與目標決策卡。已提供聊天區塊、輸入焦點、`tui watch` 與選用通知；暫停／恢復員工狀態沿用既有權限檢查與確認卡。終端介面使用繁體中文。

## 啟動

先啟動閘道，再於同一台主機執行：

```sh
duduclaw tui
duduclaw tui inbox
duduclaw tui inbox --follow
duduclaw tui inbox --follow --json
duduclaw tui watch adu
```

全螢幕模式需要終端機。`inbox` 列出一次快照後離開；`--follow` 在資料改變時輸出完整新快照；`--json` 在 stdout 每行輸出一個 JSON 物件，包含 `type`、`stale`、`count`、`error`、`items`。輸出本身不需要 TTY，但需要帳號登入時仍須互動終端。沒有 token 參數或憑證檔供無人值守登入。

CLI 連線至 `127.0.0.1`，連接埠依序取自 `DUDUCLAW_PORT`、`<home>/config.toml [gateway] port`、閘道預設值。Home 使用 `DUDUCLAW_HOME`，未設定時為 `~/.duduclaw`。這一版沒有遠端網址參數。

**遠端使用時，請先 SSH 登入閘道所在主機，再於該主機執行控制室；不要轉送閘道連接埠。** 連接埠轉送會讓轉送端主機上的程式也能接觸僅限回環介面的本機登入路徑。

## 內嵌本機終端

清單焦點按 `P`，或在命令面板搜尋 `pty`，即可在目前區塊開啟操作者自己的終端。預設執行 `$SHELL`，未設定時用 `/bin/sh`；繼承操作者環境並移除所有 `DUDUCLAW_*` 變數。控制室 JWT 留在記憶體，不加入子行程環境。既有 AI 工作階段拒絕啟動規則繼續生效。閘道回應不能指定本機命令。

終端輸入焦點下，**`Ctrl-\` 或 `F12` 返回控制室**（舊式終端會將 `Ctrl-\` 解析為 `Ctrl-4`，兩者皆接受）；`Esc`、`Ctrl-C`、`Ctrl-P`、方向鍵、功能鍵與換頁鍵等一般終端按鍵都送給子行程。按 `Enter`／`i` 可再進入終端輸入。返回控制室後，`PgUp`／`PgDn` 捲動最多 5,000 行的終端歷史。貼上以文字傳入，保留換行與 Tab，移除能跳出 bracketed paste 包裝的控制字元；子行程啟用 bracketed paste 時才加上包裝。同批按鍵合併後由專用 writer 依序送出。即使子行程停止讀取，仍持續讀取主終端事件，返回鍵、控制室退出與尺寸調整仍可操作；終端焦點下先按 `F12`／`Ctrl-\`，再按 `q` 即可退出。排隊中與寫入中的位元組合計上限為 1 MiB，超過時整段拒絕並顯示訊息。只有 PTY 輸入焦點下、游標位於該區塊內且子行程已啟用回報時，才轉送滑鼠；支援傳統、UTF-8（1005）、urxvt（1015）與 SGR（1006）編碼，座標依區塊與實際顯示字寬換算。SGR-Pixels（1016）依主終端的字格尺寸估算區塊內從 1 起算的像素座標；無尺寸資訊時，每格採 8×16 像素，無法取得格內的精確游標位置。編碼優先序為 1016 > 1006 > 1015 > 1005 > 傳統。未聚焦區塊不接收滑鼠。狀態列會顯示焦點與返回按鍵。

區塊只啟動開啟控制室者環境中的 shell：Unix 使用 `$SHELL`（未設定時用 `/bin/sh`），Windows 使用 `%ComSpec%`（未設定時用 `cmd.exe`；Windows PTY 目前仍停用）。其他程式請從該 shell 執行。`tui.toml` 不是可信任的執行邊界，已移除 `[pty] command` 設定；舊鍵會被忽略並顯示設定通知，其他有效設定仍會生效。

獨立解析執行緒更新 VT 畫面模型，發布大小受限的可見儲存格快照；繪製與決策卡不等待解析。固定空間的前置過濾器丟棄 7-bit OSC、DCS、APC、PM、SOS 字串控制；OSC 最多暫存 256 bytes，僅辨識顯示用途的等待訊號，內容絕不轉送；CAN／SUB 取消序列，ESC 重新開始跳脫解析。未構成有效 UTF-8 的原始 8-bit C1 位元組會被丟棄；UTF-8 字元驗證完整後才傳遞。ESC 只在白名單短序列、字元集指定序列或 CSI 完整後輸出。CSI 在引導符後最多 128 bytes、32 個參數（含子參數），超長即丟棄；僅計數與位置參數限制為 `max(列數, 欄數, 1)`，捲動區域則限制在畫面列數內。過濾器會暫存長度受限的 CSI，直到收到結尾位元組，跨讀取區塊也適用。SGR 色彩、私有序列、模式、回報、視窗操作與游標保存序列原樣通過。繪製清理過的文字、顏色與粗體；不把 OSC 剪貼簿、標題、超連結、DCS、sixel 或終端模式序列傳給外層終端。配置變更會調整 PTY 尺寸，上限為 200 列 × 500 欄。CJK 雙寬字與組合符號支援兩種字寬設定。parser 採 ambiguous 字元窄寬座標；寬字設定會在繪製時展開並於區塊邊界裁切，依賴 ambiguous 寬座標的全螢幕子程式仍待驗收。

關閉或取代仍有待啟動／執行中子行程的區塊，須按 `y` 確認，`Esc` 取消。退出控制室會停止本機 PTY 行程，閘道員工繼續執行。Unix 使用既有行程群組 helper，並在回收 shell 前盤點同一 session 的其他工作群組；刻意脫離的行程（例如使用 `setsid`）會繼續執行，與一般終端相同。即使同一 session 的清理成功，也不能證明所有後代行程都已停止，因此仍顯示清理未完整確認；盤點或送出訊號失敗也一樣。Windows 因 ConPTY 行程樹清理尚未驗證而停用，既有 Job Object helper 供其他啟動路徑使用。本階段未加入從終端文字推測的「等待你」徽章，終端內容不會核准任何操作。

正常退出時，RPC `/ws` 與 WebChat `/ws/chat` 會傳送 Close，最多等待一秒完成對端關閉握手；控制室、inbox 與 watch 入口會等待關閉流程。


## 命令面板與離開摘要

在清單、說明或輸入焦點按 `Ctrl-P` 開啟命令面板，輸入模糊搜尋（繁體中文名稱或 `stop`、`steer`、`log` 等英文別名），方向鍵選取、`Enter` 執行顯示的快捷鍵，`Esc` 回到原焦點並保留對話草稿。`Ctrl-K` 保留。清單依目前區塊、角色、員工操作綁定與資料有效性重新篩選。自主工作暫停／恢復立即送出；其他控制命令沿用原本確認卡，不會代為核准。決策卡與內容警告開啟時不提供命令面板。

`F1`／`?` 只在目前焦點區塊顯示說明，其他區塊照常顯示。過長的 home 路徑保留尾端，前面以刪節號表示。在最低支援的 12 列高度，收件匣與員工清單各保留至少一列內容；排程面板可能隱藏。兩種字形模式都使用 ASCII 框線，所有操作均可不用滑鼠；Windows 的放開按鍵事件不會執行命令。

控制室提供停止工作或讓工作向前推進一步的控制，不提供常設權限；Admin 可暫停或恢復全部自主工作。`cron run now`、`heartbeat trigger` 與任務停止都是單向操作，必須透過確認卡執行；控制操作不一定可逆。

離開並還原終端後，標準輸出會列出待處理收件匣件數（包含本機稍後提醒的項目）、執行中的員工名稱，以及返回相同 home 的完整指令。件數或員工資料過期時顯示 `?`。名稱會清理並限制長度，不印收件匣、任務、對話或工具內容。Unix 的返回指令使用 Bash／Zsh ANSI-C 引號；Windows 使用 PowerShell。關閉控制室不會停止員工。Windows 傾印抑制仍未實作；交叉編譯不代表原生終端驗收。

## 登入方式

| 版本或狀態 | 行為 |
|---|---|
| Personal，已啟用本機自動登入 | 閘道允許時直接取得帳號工作階段，無須輸入。 |
| Personal，關閉自動登入、已設密碼 | 選擇帳號密碼，輸入帳號電子郵件與密碼。 |
| Personal，關閉自動登入、尚未完成初始設定 | 先到儀表板設定密碼，或啟用本機自動登入。 |
| Team / Enterprise | 選擇密碼**或**帳號電子郵件驗證碼，已設定 MFA 的帳號接著需輸入驗證器驗證碼或復原碼。閘道不允許這兩個版本使用本機自動登入。 |
| 帳號要求變更密碼 | 先到儀表板改密碼，再啟動控制室。 |
| 工作階段到期 | 在記憶體中更新 token 並重新連線；更新失敗時重新要求帳號登入，不退回自動登入。 |
| 非管理員 | 只讀取帳號有權限的員工與收件匣；管理員面板會說明所需權限。 |

密碼與通道驗證碼是兩種可選的第一步登入方式。帳號已設定雙因素驗證時，任一方式通過後，都需再輸入驗證器的六位數驗證碼或復原碼。輸入錯誤可在閘道允許的次數內重試（終端另設最多五次）；驗證逾期或達上限後須重新登入。若帳號必須先設定雙因素驗證，請到儀表板完成，終端不使用設定權杖。

通道驗證碼依輸入的帳號電子郵件申請，透過閘道已設定、已綁定的通道送達，請先確認儀表板的驗證碼登入可用。密碼、驗證碼與復原碼輸入不回顯；提示與固定錯誤訊息輸出至 stderr。沒有互動終端卻需要驗證碼時，會直接顯示錯誤，`tui inbox --json` 也一樣。不支援 MFA 的閘道維持原有登入流程。

## 按鍵與資料更新

| 按鍵 | 操作 |
|---|---|
| 方向鍵 / `j` / `k` | 移動選取 |
| `Enter` | 開啟詳情或決策卡 |
| `r` | 將項目或有識別碼的已完成執行標為本機已讀 |
| `PgUp` / `PgDn` | 捲動詳情 |
| `?` / `F1` | 開關說明 |
| `q` / `Ctrl-C` | 離開 |

新項目不會搶走選取。已讀只記在這個客戶端，不會關閉閘道的待處理事項。完成徽章採用最近的執行紀錄，並非完整的歷史未讀清冊。

斷線、事件遺失或重新讀取尚未完成時，清單顯示「資料可能過期」，計數變為 `?`；JSON 為 `stale: true`、`count: null`，保留上次完整清單。一次重新讀取共用 2,000 筆與 4 MiB 編碼回應內容上限，包含所有員工、收件匣、最近執行與排程。任一超限就停止該次讀取並保持 stale，不會把部分清單標成完整。WebSocket 單一訊息／frame 上限為 256 KiB，事件佇列為 16 筆；大型安裝可改用儀表板。

## 聊天與輸入焦點

狀態列始終顯示焦點模式。清單焦點下，`1`–`4` 切換區塊、`C` 開啟聊天；選取員工後按 `i` 輸入，或按 `/` 以斜線開始。`Esc` 返回清單並保留草稿。輸入時，單字母快捷鍵都是文字；支援中文、IME 提交及整段貼上。`Enter` 傳送，`Ctrl-C` 離開。

開頭的 `@name ` 由客戶端轉成 WebChat 的 `agent` 欄位，訊息本文不含這段提及；沒有提及時，收件人是進入輸入模式時選取的員工。`/goal`、`/status`、`/cost` 原樣交給閘道。輸入 `/pause`、`/stop`、`/resume` 時會提示這是電腦操作指令，**不會暫停員工**。

右側最多平鋪四個區塊，操作見下節。不同聊天區塊可同時執行回合，同一對話一次一個。各區塊分別保留員工、對話、草稿、歷史、捲動位置與取消提示；閘道的回合上限顯示在對應區塊。未知或識別欄位互相衝突的訊框會被忽略。思考與工具步驟收合為一行，ASCII 模式也有旋轉指示。清單焦點下以 `PgUp`／`PgDn` 捲動聊天，歷史最多保留 2,000 行，每行最多 512 字元。新輸出不移動焦點；員工文字經 `TerminalText` 清理，不產生 OSC 8 可點擊連結。

僅一條 `/ws/chat` 連線，共用 `/ws` 客戶端的記憶體權杖更新，斷線後退避重連。不自動重送結果未確認的訊息；已完成的對話可在重連後繼續，換員工會開始新對話。閘道曾傳回帶 `msg_id` 的 frame 後，清單焦點下才可按 `X` 取消當次回覆；否則顯示無法取消。`cancel_accepted` 僅表示接受請求；取消完成時收到的是 `type: error`、`code: cancelled` 訊框。若已開始交付，最終回覆也可能先結束回合。

若該回合交辦給其他員工的工作仍在執行，閘道只提供件數與一次性識別值，控制室顯示：「還有 N 位員工的工作還在跑，要一起停嗎？ y 停止／n 讓它們跑完」。在**清單焦點**按 `y`，只送出一次停止請求；`n` 或 `Esc` 關閉詢問。在**輸入焦點**，`y`、`n` 都是普通文字，狀態列會說明如何回到清單作答；新輸出不會移動焦點。識別值不會顯示。詢問有效 10 分鐘，斷線時清除，gateway 重啟後也會失效。不回答或關閉詢問不傳送請求，交辦工作繼續執行。

結果顯示「已停止 N 項」，還有工作在收尾時加上「M 項還在收尾」，不把收尾中的工作算成已停止。若詢問已不能使用，顯示「這個詢問已失效，下游工作不受影響」，表示這次請求沒有停止任何工作。公開 Widget 訪客不能控制員工工作，不會收到詢問。憑證撤銷時的自動停止，適用於仍在執行的回合，或撤銷後才收到停止請求的情況。已完成回合的工作，以及無人回答的詢問，都不會因此自動停止。

停止只追蹤帶有相同來源對話與回合的交辦執行，排除歸屬其他人的工作。已執行的外部動作無法追回；本回合建立的任務板任務與目標不會跟著停止，請使用各自的控制。遺失來源資訊的執行也找不到。留下來的工作可以繼續完成；帶有該取消回合來源的資料列會被 fence 封鎖，不能再交辦或新增核准。刻意丟棄或偽造 lineage 的執行不會被追蹤。這項操作不會暫停整位員工，也不影響其他對話。

「已停止」表示受管理的行程群組與使用中的任務沙箱容器已消失。刻意用 `setsid` 等方式離開行程群組的程序，除非員工在任務沙箱內執行，否則不在這項檢查範圍。Unix 上的本機子行程要等受管理的行程群組消失，才算停止，不能只看父行程結束；任務沙箱還會等待容器清理確認。等待期間無法確認停止的工作，仍列為「還在收尾」。Windows 目前的行程管理介面無法確認所有子行程都已離開，因此即使已要求終止，遭取消的子行程工作仍保守列為「還在收尾」。已送到外部服務的請求，不能靠停止本機執行追回。Gemini CLI 與 Antigravity runtime 已移除，沒有這裡的派工路徑；Gemini API 供應者不受此移除影響。以上說明的是實作的回報邊界，不代表已完成原生平台或外部服務驗收。

## 區塊與任務控制

右側可容納一到四個區塊。`v` 左右分割、`x` 上下分割、`1`–`4` 切換焦點，`Ctrl-W` 只關閉本機區塊，不會停止任務或取消聊天。縮放終端不會改動配置；右側小於 64 欄或 16 列時，只顯示焦點區塊與隱藏數量，放大後恢復原配置。配置目前不跨程式重啟保存。

`D`／`C`／`R`／`T`／`L` 分別開啟詳情、聊天、執行、任務、日誌。先在左側選取員工，再按 `R` 或 `T`；區塊固定該員工，左側移動不會換人。`C` 開啟另一段聊天（使用詳情區塊或新增區塊，總數最多四個）。`i` 使用目前聊天；從其他類型區塊進入時，開啟現有聊天或建立一個。輸入與 `X` 取消只作用於焦點聊天，下游停止詢問也留在該區塊。`[`／`]` 切換紀錄，`PgUp`／`PgDn` 捲動。執行清單最多最近 50 筆；任務每頁 50 筆，依閘道總數翻頁。

執行區塊透過 `runs.get` 讀取歷史，嘗試 `runs.subscribe`；只有閘道回覆方法不存在時才顯示每五秒輪詢，其他錯誤不隱藏。即時 `run.step` 必須同時符合員工與執行 ID，最多保留 256 筆，並定期與歷史對帳。已知非 Claude 員工且沒有步驟紀錄時顯示「此 runtime 只回報起訖」；員工目前的 runtime 並不能證明舊紀錄使用的 runtime。預設不顯示執行或工具內容；按 `c` 閱讀警告，再按 `c` 才顯示，其他鍵取消。警告每次開啟控制室只確認一次，之後 `c` 切換顯示。預覽只是截短，沒有遮蔽機密。

任務區塊讀取 `tasks.list_page`、`tasks.iterations`、`tasks.timeline`、`tasks.changes` 與 `tasks.stop_status`。預設顯示回合判定、事件類型、變更路徑，不顯示評語、原始碼片段或工具內容。`Enter` 開啟既有目標決策卡；已結束目標可輸入接續訊息再繼續。具 Operator／Owner 綁定者可按 `e` 補充未結束目標的方向、`s` 停止。方向最多 4,000 字，輸入後按 `Enter` 進入確認；是否啟用 steering 仍由閘道判定。停止帶入看見的 `expected_authority_revision`，目標決策帶 `expected_updated_at`。

任務區塊按 `b` 切換至該員工的持續責任，`[`／`]` 選取責任，顯示 `responsibilities.get` 提供的下次觸發與 `responsibilities.fires` 最近紀錄。`p` 暫停、`d` 停用，帶入 `expected_control_epoch`。`o` 依閘道提供的任務 ID 開啟此次執行，再使用相同的方向與停止控制。長期授權與合約變更仍在儀表板處理。

日誌使用 `logs.subscribe`，限 Manager／Admin；其他角色會看到所需權限。最多保存 256 行、每行 2,048 字，全部經過 `TerminalText`。閘道沒有日誌重播，遺失的行無法補回。

自主排程區顯示已啟用與已暫停的 cron（Admin），以及心跳狀態（Manager／Admin）。排程 `p` 暫停／恢復、`n` 執行一次；心跳 `n` 立即觸發。排程立即執行附上新的 `request_id`。`cron.list` 的 `next_run` 使用閘道回傳的 RFC3339；空值顯示「未排定或未知」，不自行推算。心跳列顯示實際 `last_run` 時間，不把它當成成功結果。詳情顯示排程規則、時區與可用的上次執行／結果。

清單焦點選取員工後，`p` 立即送出 `autonomy.pause {agent_id}`，`u` 立即送出 `autonomy.resume {agent_id}`，不開卡片、不等待確認。需要 Manager 與該員工的有效 Operator／Owner 綁定，閘道會重新查驗權限。輸入焦點的 `p`／`u` 仍是文字。責任區塊的 `p` 操作該責任；選取排程時，cron 的 `p` 及 cron／心跳的 `n` 不再要求詳情區塊取得焦點。立即執行、心跳觸發與任務停止保留確認卡。

Admin 可在 `Ctrl-P` 選擇「暫停全部自主工作」或「恢復全部自主工作」，立即送出 `{all:true}`；恢復全部沒有單鍵捷徑。狀態列顯示「自主: 已暫停（阿嘟）」或「自主: 全部暫停」；最多顯示兩個名字，各限十二字，其餘顯示 `+N`。連線、重連、漏接事件及每次 `autonomy.changed` 都會重讀 `autonomy.status`，資料過期、等待重讀或無法讀取時，員工列、標記與狀態列都顯示「待確認」，不以舊資料表示自主工作已暫停或正在執行。操作遭拒時顯示原因，不先改畫面假裝成功。

自主暫停獨立於員工狀態保存，阻止新的自主工作，人直接發起的對話仍可使用；進行中的回合可先完成，再阻擋下一輪。恢復全部只解除全域暫停，個別暫停仍保留。員工列會區分自主暫停、員工狀態暫停及停止。命令面板也保留「暫停員工狀態（需確認）」／「恢復員工狀態（需確認）」，透過 `agents.pause`／`agents.resume` 與既有確認卡變更員工本身的運作狀態，不會解除獨立的自主暫停。

自主暫停與恢復是立即送出的例外，不開確認卡；任務、責任、排程及員工狀態操作仍保留獨立決策卡：開卡後一秒內忽略按鍵、核對完整請求、輸入新的兩位確認碼；資料過期或目標內容改變就拒絕送出。不自動重送請求。接受、拒絕與衝突都重新讀取；停止被接受仍可能是 `cancel_pending`，畫面不提前顯示成功。受限沙箱內的 socket 假閘道、真實閘道與原生終端驗收為 NOT RUN；程序內假 RPC 測試涵蓋請求欄位與確認狀態機。

## 自主子系統畫面

清單焦點或 `Ctrl-P` 可開啟 `W` 工作流程、`A` 自動規則、`E` 演化與經驗、`B` 預算事件、`G` 最新摘要，支援分割、焦點切換與捲動。空資料、拒絕、過期與不可用分開呈現；可見範圍沒有資料不代表系統正常。閘道文字都經終端清理，每欄最多 240 字、表格最多 50 列，省略內容會提示到儀表板查看。

- **工作流程**：先在任務區塊選取來源任務，再按 `W`。讀取該任務草稿第一頁（最多 20 筆）、每份草稿最多 20 次執行，不含測試執行。`[`／`]` 切換執行並取得步驟；`s` 開啟單向取消確認卡。需要 Manager 與 Operator 權限，閘道重新檢查來源任務與草稿擁有者。不提供啟用流程或常設權限操作。
- **自動規則**：僅 Admin 可讀，顯示規則及實際 `closed`、`open`、`half_open` 狀態與開啟時間。引擎不可用或缺少某條規則的斷路器資料時，不顯示為已關閉。
- **演化**：Manager／Admin 可看狀態與停滯訊號；另外以 Viewer 權限取得所選員工的經驗條目，不增加修改路徑。
- **任務**：詳情顯示驗收條件紀錄的模式、條件、證據、未解決項目與更新回合，以及團隊角色回合。缺少驗收紀錄明示未提供；角色資料讀取失敗另行顯示。
- **預算與摘要**：預算事件需要 Manager／Admin，屬於歷史紀錄，不代表斷路器目前仍開啟。摘要顯示權限範圍內最近一次保存的結果及交付項目名稱，不提供回饋寫入。

`budget.breaker_open` 與 `autopilot.breaker_open` 會成為有容量上限的資訊列，指出員工或規則；`Enter` 開啟預算或自動規則畫面，不開決策卡。這是本次連線觀測到的事件，不是完整歷史收件匣。審核與暫停目標列也顯示員工、審核種類或暫停原因。

命令面板選「建立自主目標」，或選取員工後按 `N`。輸入目標，以 `Tab` 切換「先擬計畫」（初始開啟），`Enter` 進入確認卡。送出 `tasks.goal_create` 的 `agent_id`、`description`、`plan_first`。有待核准計畫時顯示「核准計畫」：捲到卡片底部，輸入兩位確認碼後送出。實際 RPC 動作仍是 `retry`，此時停用未標明用途的 `r`。過長的任務卡改為唯讀，提示到儀表板處理。

已結束目標按一次 `c` 就聚焦接續訊息輸入；可輸入或貼上，`Esc` 清除訊息並關閉；只有 `Enter` 進入核對，顯示目標任務及訊息全文。核對時重新開始一秒防護並產生新兩位數確認碼，須捲動到底、輸入確認碼，再按 `Enter` 送出；內容過長須改用儀表板，空訊息不能送出。卡片保留一秒按鍵防護、資料有效性與權限檢查、版本綁定，失敗不自動重送。

頁首顯示本次連線已觀測到的執行數；重連或漏接事件會失去這份觀測。回合事件的選填 `task_id` 讓員工的 `T` 操作連到任務，缺少時代表未知，不猜任務。事件沒有執行結果或 run ID，完成／錯誤標記仍由歷史查詢取得。執行標題顯示閘道來源與已知回合，不編造回合上限。Admin 費用以 `cost.summary {since:<本機午夜的 RFC3339>}` 查詢，只有閘道確認相同界線且回傳有效費用時才標「今日」。午夜採當日當地時區，包含日光節約時間變更。舊閘道改查 `hours:24` 並標「近 24 小時」；拒絕或不可用時隱藏金額。`since` 優先於 `hours`，拒絕格式錯誤與未來時間，最遠為資料保留期（目前 30 天）與 31 天中的較短者。清單焦點頁尾顯示所選名稱、`Ctrl-P` 與 `q`。

## 查看單一員工紀錄

`duduclaw tui watch adu` 輸出清理過的純文字行，適合窄分割視窗，不切換 alternate screen。員工模式明示「輪詢模式」，每五秒讀取 `runs.list` 與 `runs.get`；閘道訂閱需要唯一的 `run_id`，因此員工模式不發送訂閱請求。取最近四次執行、每次最近 256 筆事件，並限制去重紀錄大小。使用 `--run` 可訂閱單次執行；舊版閘道回應未知方法時，才顯示提示並改為每五秒輪詢。`Ctrl-C` 離開；同樣拒絕 AI 工作階段，沿用帳號登入。

預設只輸出時間、狀態、員工、步驟類型或工具名稱，不顯示使用者與助理文字或工具參數。使用 `duduclaw tui watch adu --content` 才會顯示內容預覽，並在 stderr 警告內容未經機密遮蔽。兩種模式遇到未知事件格式都只顯示名稱，絕不輸出 JSON payload。

連線錯誤也以固定文字「DuDuClaw：連線中斷，請檢查控制室」通知，共用失焦條件與每分鐘一次限制。

## 終端通知

預設關閉，設有 `SSH_CONNECTION` 也不會自動開啟。可在 `tui.toml` 明確設定 `notifications = true`。終端失焦且有效收件匣件數增加時，VTE／rxvt-unicode 終端發出 OSC 777，其餘使用 OSC 9，文字固定為「DuDuClaw：N 項需要你處理」；只有 N 是數字，沒有員工名稱、任務標題或工具內容。支援時使用終端焦點事件，未提供事件時視為失焦。每分鐘最多一次，被抑制的增加不排隊。tmux 下只有簡單檢查 `tmux show-option -gv allow-passthrough` 回傳 `on` 或 `all` 才使用 passthrough，其餘略過。是否顯示仍取決於終端支援。

## 決策卡

選取收件匣一列後按 `Enter` 開卡。新項目只更新清單與徽章，不會開卡或搶焦點；開卡後一秒內的按鍵全部忽略。`Esc` 關卡，方向鍵與 `PgUp` / `PgDn` 捲動內容。 選取列消失時會選取原位置的下一列，或最後一列；原識別碼仍存在時，新項目與排序變動都不會移動選取。

核准審核時，輸入卡上的兩位數確認碼，再按 `Enter`；`n` 立即拒絕。每次開卡會隨機產生不同於前次的確認碼。所有核准操作會完整顯示內容，把控制字元轉成可見標記；捲到底部後才能輸入確認碼，縮小視窗可能再次鎖住輸入。這只能防誤按或盲打，**無法阻止同 UID、能讀取畫面的程式**，也不是本人在場或身分驗證。 目前所有核准卡都視為高風險：`approvals.list` 雖有 `kind`，但沒有閘道產生的安全分類，不能僅憑操作種類或 `payload` 欄位降低風險。視窗縮放會清除已輸入文字，重畫後才處理排隊按鍵；底部提示依清單、卡片或說明焦點切換。

沒有待核准計畫時，目標卡的 `r` 是重試；`a` 中止、`d` 標為完成、`t` 接手都要再按一次同鍵，沒有倒數，其他按鍵取消確認。已結束目標按 `c` 直接輸入接續訊息，`Esc` 清除訊息並關閉；只有 `Enter` 進入核對，顯示目標任務及訊息全文。核對時重新開始一秒防護並產生新兩位數確認碼，須捲動到底、輸入確認碼，再按 `Enter` 送出；內容過長須改用儀表板。收件匣只列 `needs_human`；已結束目標可在任務區塊開卡接續。`tasks.goal_decide` 接受 `task_id`、`action`、選填 `note`，`continue` 另須 `message`。新增選填 `expected_updated_at`，須與任務回傳的 `updated_at` 字串完全相符；五種操作皆在同一 SQLite 交易內比對並套用決策。不符回傳固定錯誤 `goal_decide_revision_mismatch`，不變更任務、不記錄決策。省略時保留儀表板原有行為。控制室一律送出卡片上的值，缺少時不送出目標決策。

`may_decide=false` 的卡片唯讀並顯示原因。目標操作須由 `users.me` 確認有 Operator／Owner 綁定或 Admin 權限。僅限儀表板的審核、需要填答案的提問及綁定操作仍留在儀表板；TUI 只顯示固定提示，不會開啟伺服器提供的網址。常設授權與全域設定變更也留在儀表板。

核准必須有非空字串 `digest`，並以 `expected_digest` 送出。缺少或為 null（包括內容被遮蔽的檢視者）時，不送核准 RPC，卡片保持開啟，固定顯示：**內容未綁定：這張卡無法確認你看到的就是實際內容，請到儀表板決定**。仍可按 `n` 拒絕。digest 由 `approvals.list` 提供。收到結構化 digest mismatch 時會關卡、重新取得清單並顯示固定變更提示。每次已送出決策（包括 RPC 錯誤、結果不明的逾時）都重新取得清單，不先顯示成功，也不自動重送。錯誤文字經 `TerminalText` 顯示；資料過期、審核到期或缺少有效期限時不能決策。

在清單或卡片按 `s`，只在本機隱藏最多十分鐘。審核不得超過剩餘 TTL 的 80%；剩餘期限達 20% 或十分鐘（取較短者）前會附原因重新出現，原訂提醒較早則以較早時間為準。期限被縮短也會重新顯示。審核到期即拒絕，稍後提醒不會延長期限。`tui-state.json` 只保存識別碼與時間；文字模式 `inbox` 仍列出閘道完整待處理清單。 系統時間退到提醒設定時間之前時，該提醒永久取消隱藏；同次執行也以單調時鐘限制期限。重新啟動無法確認時鐘連續性，因此會重新顯示卡片。

## 本機檔案

| Home 下的檔案 | 用途 |
|---|---|
| `tui-state.json` | 標記已讀或稍後提醒時寫入，只含已讀識別碼與稍後提醒時間；透過同目錄暫存檔原子替換。 |
| `tui.toml` | 操作者可自行建立的選用設定；控制室只讀取，不會建立或改寫。 |

```toml
# ~/.duduclaw/tui.toml
glyphs = "ascii"                 # 或 "unicode"
ambiguous_width = "narrow"        # 或 "wide"，配合終端字寬設定
notifications = false
poll_interval_seconds = 15        # 5..3600
default_layout = "single"         # "vertical" / "horizontal"
```

支援的所有頂層設定如下。無效值只讓該鍵保留預設值並顯示通知，其他有效設定仍生效。未知鍵（包含連線、認證與安全設定）會通知且不生效。TOML 語法錯誤、檔案無法讀取或過大時全部使用預設值。啟動時讀取一次。

| 設定 | 有效值 | 預設與作用 |
|---|---|---|
| `glyphs` | `"ascii"`、`"unicode"` | `"ascii"`；員工狀態字形，框線仍為 ASCII |
| `ambiguous_width` | `"narrow"`、`"wide"` | `"narrow"`；配合終端的模糊寬度字元設定 |
| `poll_interval_seconds` | 5～3600 的整數 | `15`；權威清單重新核對間隔；執行／任務／日誌區塊維持每五秒核對 |
| `notifications` | 布林值 | `false`，SSH 亦同；明確開啟後提供固定文字背景通知 |
| `default_layout` | `"single"`、`"vertical"`、`"horizontal"` | `"single"`；一個詳情區塊、左右兩個詳情區塊、上下兩個詳情區塊；初始焦點為區塊 1 |

操作中的版面變更不會寫回設定。這些設定不能變更連線、認證、權限、確認或任何安全規則。框線一律使用 ASCII。兩個檔案都受既有 agent-file-guard 家目錄政策保護，員工不能寫入。

## 安全限制

每次請求都由閘道授權。客戶端只用記憶體中的帳號 JWT，拒絕舊版管理員 token 與 `system` 身分，無法連線時不改讀閘道資料庫。即使設定 `RUST_LOG=trace`，控制室也不啟用日誌 subscriber、日誌檔或遙測匯出。Unix 會在讀取憑證前停用 core dump；應用程式持有的秘密緩衝區會盡可能清零，但終端、HTTP、TLS、WebSocket 函式庫仍可能保有無法保證清除的副本。Windows 尚未實作當機傾印抑制，因此「秘密不落地」保證僅適用於 Unix。

AI 工作階段拒絕與 Bash 命令守門都是減少誤用的措施。與操作者共用 OS 帳號且有不受限 shell 的員工仍可繞過，也可直接改檔。實際隔離需要不同 OS 身分、任務沙箱，或不授予 Bash。

閘道文字會先清理終端控制字元，詳情把移除的字元顯示為可見標記。保留 U+FE00–U+FE0F 變體選擇符以維持 CJK／emoji 呈現；U+E0000–U+E0FFF 整段移除，包含補充變體選擇符。JSON 保留來源文字；stdout 為終端機時，額外逸出清理器禁止的所有字元（含雙向文字與預設忽略字元），非終端輸出則不變；接收端解碼後必須再次清理，才能直接顯示於終端。

傳輸函式庫只允許精確回環位址使用明文。`localhost` 在 REST 與 WebSocket 都固定為 `127.0.0.1`，不受 hosts／DNS 改寫影響；TLS 憑證驗證仍開啟，因此這種 TLS 連線的憑證須對固定 IP 有效。函式庫呼叫端可明確使用 `[::1]` 連到 IPv6 回環介面。


### 多對話與本機提示

`duduclaw tui watch --run <run-id>` 以 `runs.get` 與 `runs.subscribe {run_id}` 追蹤單一執行；原本的位置參數仍是員工名稱，不可與 `--run` 同時使用。沿用內容顯示選項、文字清理與 AI 工作階段拒絕。

`dashboard.navigate` 僅接受 `/inbox?item=` 指向已載入收件匣項目的被動提示，不更動選取、焦點、卡片或 `p`／`u` 的員工目標。`/agents/...`、其他路徑、未知項目與惡意路徑一律忽略；輸入中、PTY 輸入中、說明或確認卡開啟時也不處理提示。

子行程的 OSC 9、OSC 777 `notify` 通知，或 OSC 0／2 標題恰為 `waiting for you`、`waiting for input`、`needs input`（不分大小寫），會顯示固定等待標記，本機輸入後清除。標記僅供查看，不授權、不回答、不呼叫閘道，也不發出主終端通知。過長或格式錯誤的字串會被忽略。
