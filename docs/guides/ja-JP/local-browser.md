# 専用ローカルブラウザー

既存のツール拒否、期限付き権限、操作ルールと操作レビューは維持します。スクリーンショットやスクロールに承認が必要な場合も、判断できるのはローカルのネイティブアプリだけです。移動では従来の Modify と追加の Send ルールを両方確認します。停止は承認を待ちません。マスク済みローカル画像は現在の実行へメモリー上で返し、監査画像として保存しません。

このメモリー内処理の保証は、DuDuClaw のローカル viewport と同意の監査経路に限ります。モデルへ送った画像・本文・URL・キー引数は、外部実行器の会話記録、提供者のキャッシュ、モデルの回答に残る場合があります。回答は通常の会話記録にもなり得ます。専用 Chrome profile はサイトの状態を保存します。モデルや他のシステムにページ内容が保存されないという保証ではありません。

初期値はオフです。macOS のローカルデスクトップアプリが自分で起動した gateway のみ、専用の Chrome／Edge ウィンドウと profile を使えます。Personal と Enterprise の制御は同じです。Windows、Linux、リモート gateway、既存 gateway への接続では利用できません。

Admin が `config.toml [computer_use.local_browser] enabled = true` と、従業員の `[capabilities.computer_use_config] local_browser = true` を両方有効にします。全体設定をオンにする際はリスク説明の確認が必要です。`computer_use = true` と既存のコンテナモードは維持してください。廃止済みのデスクトップ native モードには戻りません。接続先は従業員の `allowed_domains` にある厳密な HTTPS ホスト名に限り、ワイルドカードやローカル／プライベート IP は拒否します。

`computer_session_start` に `target: "local_browser"` を指定します。省略時は `container` です。他の computer ツールは同じ従業員の session を使います。本人との認証済みの会話が現在処理中で、アプリの在席確認が有効である必要があります。スケジュール、派遣、goal、heartbeat、公開訪問者、継承された turn ID や代理人情報だけでは実行できません。未対応の入場経路は拒否し、コンテナへ自動的に切り替えません。

macOS アプリのネイティブメニュー「AI にブラウザーを開かせる…」から、システムダイアログに従業員 ID を入力する方法もあります。起動の許可は六十秒で失効し、一度しか使えません。ペアリング、設定、有効な担当者の関連付けを再確認します。監査上は「ローカルのネイティブ利用者（プラットフォーム上の身元未確認）」であり、特定の担当者や会話の本人確認にはなりません。動作中はメニューバーの画像自体が変色し、停止できます。

AI が既存ページを初めて読む際はネイティブ承認が必要です。承認はメモリー内だけに保持し、厳密な人間の会話ターンと現在の実行接続に最大六十秒間関連付けます。新しいターン、接続の再作成、依頼者変更、担当変更（A→B→A も含む）、設定変更、元のターンの終了後は再承認します。マスク済み画像、ページ本文、タイトルのすべてが対象です。ネイティブメニューからの単独起動では、読み取りを事前承認しません。

承認カードには入力全文、キー、移動先 URL、クリック座標とページ側の対象説明を、スクロール可能な明細として表示します。ページの説明は信頼せず、縮小画像も確認してください。長すぎる明細は省略せず拒否します。操作の承認によって現在のターンの六十秒間の読み取り許可を更新する場合も、カードに明示します。

コントローラーの生存と人の在席は別です。gateway は署名済みネイティブ心拍のサーバー受信時刻でローカル session を維持し、手動ログインや 2FA を通常コンテナの 120 秒のツール無操作期限で中断しません。元の session 上限は維持します。心拍は本人確認・在席証明・読み書き同意にはなりません。画面ロック、離席、人の入力、会話ターンや接続の失効による AI 拒否は維持します。コントローラーが三十秒途絶えれば session を終了します。

専用ウィンドウには本人がログインします。AI はパスワード、ファイル、認識された認証情報欄に入力できません。クリック、入力、キー、移動の各操作をネイティブダイアログで承認します。スクロールとマスク済み viewport の観察は、この承認規則を緩和しません。メニューバーから停止・再開できます。画面ロック、離席、ブラウザー内の人による操作で AI を凍結し、本人の再開操作が必要です。心拍が三秒途切れると操作を拒否し、三十秒で終了します。専用ウィンドウを閉じても終了します。Admin を含む dashboard アカウントには状態と停止のみを提供し、ページ画像、VNC、接管、リセット、承認は提供しません。

データは通常の profile とは別の `<home>/local_browser/<employee>/profile` に保存します。Chrome は OS の認証情報ストアを使用します。CDP は継承された pipe のみを使い、TCP debug ポートを開かず、Chrome のネイティブ sandbox を維持します。認証付き CONNECT proxy、厳密な許可ホスト、全 IP の公開範囲確認と固定 IP 接続を使用します。WebRTC は起動フラグに加えて専用 profile の設定が必要です。ダウンロード、アップロード、追加 target、HTTPS 以外の移動、サイト権限、ブラウザーやクリップボードのショートカットを拒否します。バックアップから除外し、担当変更・削除や許可ホストの縮小後には旧状態を再利用しません。

別 OS ユーザーや VM による隔離ではありません。同じ OS ユーザーの無制限プログラムは製品の制御を回避できます。ブラウザーバージョンと通信の挙動は各リリースで再検証してください。

起動前に、終了未確認の状態をマシンの lease ファイルへ永続化します。専用プロセス全体の終了を確認した場合だけ解除します。gateway の異常終了、初回のプロセス確認失敗、清掃の不確実性があれば、次のローカル起動を拒否します。`duduclaw doctor` がファイルの場所を示します。復旧はオフラインの操作者が app／gateway を停止し、監査と lease の複製を残し、記録済み PID・開始時刻・実行ファイルから専用プロセスの終了を確認して行います。不明なまま解除したり、Chrome という名前だけで一括終了したりしないでください。確認後、表示された既存 lease の長さだけをゼロにし、削除・置換や通常の profile の消去はしません。自動解除はありません。

現時点では Chrome 156 の合成 native pipe／proxy／UDP／ダウンロード spike が成功しています。以前の STUN 漏出と無効な cleanup 実行も保存しています。backend／アプリ全体の統合、実際の画面ロック、本人のサービスログイン、出荷承認は別の確認項目です。
