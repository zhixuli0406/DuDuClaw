# 外部システムから AI 社員の状況を照会する

社内の業務システム（たとえば Odoo の「私の AI アシスタント」カード）から、AI 社員の仕事の状況を読み取れるようにします。進行中の件数、あなたの確認待ちの件数、今日と直近 7 日間に完了した件数、最後に完了した仕事のタイトルです。外部システムが受け取るのは件数と状態だけで、会話の内容やタスクの説明は一切含まれません。

English: [External systems: query AI employee status](../external-status.md) · 繁體中文：[外部系統查詢 AI 員工狀態](../zh-TW/external-status.md)

## 表示される社員

資格情報を作成した人のアカウントに **直接紐付いている** AI 社員だけで、照会のたびに最新の状態を読み直します。

- 管理者が紐付けを外すと、次の照会からその社員は表示されません。
- アカウントが停止・削除されると資格情報はすぐに使えなくなります。退職処理（offboard）では永久に失効します。
- 上長が部下経由で得る「チーム」権限は含みません。本人の直接の紐付けだけです。
- アーカイブ済み・削除済みの AI 社員は表示されません。

## 1. 管理者が機能を有効にする

初期状態は無効です。無効の間は、すべての照会に「存在しない URL」と同じ `404` を返し、新しい資格情報も作成できません。作成済みの資格情報は保持されたまま停止し、再び有効にすると、失効していないものが使えるようになります。

**ダッシュボードから有効にする：** 管理者は「設定 → 詳細設定 → セキュリティと記録」で「外部システムからの照会」を開き、スイッチをオンにします。オンにする前に、黄色の「オンにする前にご確認ください」の説明を読んでください。外部システムが取得できるのは件数と最近完了した 1 件のタイトル（個人情報はマスク済み）だけであること、資格情報を持つ人はその情報を見られること、1 人あたり最大 5 件であること、オフにすると全資格情報が停止することが書かれています。同じ場所の「全社員のトークン」表には全員の資格情報（資格情報そのものは含まない）が並び、管理者は「取り消す」を押せます（確認ダイアログが出ます。すぐに有効になり、元に戻せません）。管理者が取り消した資格情報は、その社員の「外部システム連携」ページで「取り消し済み」と表示されます。

`config.toml` に次を追加する方法もあります。

```toml
[external_status]
enabled = true
```

または管理者が `system.update_config` を `{"external_status_enabled": true}` で呼び出します。設定は照会のたびに読み直すため、gateway の再起動は不要です。

## 2. 各自が自分の読み取り専用資格情報を作成する

資格情報は各自がダッシュボードの「外部システム連携」ページ（左メニューの「設定」グループ。従業員アカウントは左下のアカウントメニューから開きます）で、自分のアカウントについて作成・失効させます。

- 管理者が有効にしていない間は「管理者がこの機能をまだ有効にしていません」と表示され、「トークンを作成」は押せません。
- 一覧には名前、作成日時、最終使用、状態（使用中／取り消し済み）が表示されます。
- 「外部システムが取得するデータ」カードで、外部システムが受け取る 5 つの値（進行中、確認待ち、本日完了、7 日間の完了、最近完了した作業）を説明しています。
- 「トークンを作成」で名前を入力すると、一度だけ表示されるダイアログが開きます。「コピー」して外部システムに貼り付け、「コピーしたので閉じる」を押してください。閉じた後は二度と表示されません。紛失したら取り消して作り直します。
- 使用中の資格情報が 5 件に達すると「トークンを作成」は無効になり、案内が表示されます。

画面の裏で呼び出している RPC は、他のクライアントからも直接使えます。

| RPC | パラメーター | 内容 |
| --- | --- | --- |
| `me.status_tokens.create` | `{"name": "Odoo カード"}` | 資格情報を作成します。名前は 1〜60 文字。応答の `secret`（`ddc_status_…`）は **この一度しか表示されません**。すぐに外部システムへ貼り付けてください。 |
| `me.status_tokens.list` | `{}` | 自分の資格情報（名前、作成日時、最終使用日時、失効済みかどうか）。資格情報そのものは含みません。 |
| `me.status_tokens.revoke` | `{"id": "…"}` | 自分の資格情報を失効させます。すぐに反映されます。 |

1 アカウントで同時に有効にできるのは 5 件までで、失効済みは数えません。管理者は `status_tokens.admin_list` で全員の資格情報（資格情報そのものは含まない）を確認し、`status_tokens.admin_revoke {"id": "…"}` で任意の資格情報を失効できます。

これらの RPC のエラーコードです（ダッシュボードは日本語・英語・繁体字中国語の分かりやすいメッセージに変換して表示します）。

| エラーコード | 意味 |
| --- | --- |
| `external_status_disabled` | 管理者がこの機能をまだ有効にしていません。 |
| `status_token_invalid_name` | 名前は 1〜60 文字にしてください。 |
| `status_token_limit_reached` | すでに有効な資格情報が 5 件あります。先に 1 件失効させてください。 |
| `status_token_account_inactive` | アカウントが有効ではないため、資格情報を作成・使用できません。 |
| `status_token_not_found` | この資格情報が見つかりません（または自分のものではありません）。 |
| `status_token_unavailable` | 一時的に処理できません。しばらくしてからやり直してください。 |

サーバーが保存するのは SHA-256 ハッシュだけです。紛失した資格情報は復元できないため、失効させて作り直してください。

## 3. 外部システムからの照会

URL は **ダッシュボード gateway** のアドレス（ダッシュボードにログインするのと同じもの。例：`https://ai.example.com`、ローカルの既定は `http://127.0.0.1:18789`）で、MCP サーバーのアドレスではありません。

```bash
curl -s https://ai.example.com/api/v1/status/employees \
  -H "Authorization: Bearer ddc_status_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"
```

特定の社員だけ：

```bash
curl -s "https://ai.example.com/api/v1/status/employees?agent_id=sales" \
  -H "Authorization: Bearer ddc_status_…"
```

応答：

```json
{
  "generated_at": "2026-11-08T09:30:00.000000000+00:00",
  "employees": [
    {
      "agent_id": "sales",
      "display_name": "営業アシスタント",
      "in_progress": 3,
      "awaiting_confirmation": 1,
      "done_today": 2,
      "done_7d": 9,
      "latest_done": { "title": "第4四半期の顧客見積を整理", "completed_at": "2026-11-08T08:12:45+00:00" }
    }
  ]
}
```

| フィールド | 意味 |
| --- | --- |
| `in_progress` | 作業中・待機中のタスク（未着手、キュー、実行中、修正中）。 |
| `awaiting_confirmation` | 人の対応待ちのタスク（レビュー待ち、人の判断が必要、承認待ち）と、この社員の未決定の承認リクエスト。承認リクエストは、この人がダッシュボードの承認センターで読める分だけを数えます（マネージャー〔Manager〕以上）。 |
| `done_today` | 今日（gateway ホストのタイムゾーン）完了したタスク数。 |
| `done_7d` | 直近 7 日間に完了したタスク数。 |
| `latest_done` | この人が見られる、最後に完了したタスクのタイトルと完了日時。なければ `null`。**タイトルを返すのは、端末内の個人情報検出モデルがインストールされている場合だけです**（マスキングのルールセット「AIスマート検出」のモデル。ローカルで動く OpenAI Privacy Filter で、そのルールセットを選ぶとカードからダウンロードできます。詳しくは[データマスキングの説明](../../features/55-data-sources.md)）。さらに、そのタイトルに対してモデルが正常に動作する必要があります。それ以外の場合 `title` は常に `null` で、`completed_at` だけが返ります。検出の前に、見えない文字・ゼロ幅文字・双方向制御文字を取り除き、NFKC で正規化します。1 つの語に見た目の似た別の文字体系が混在する場合（たとえばラテン文字のメールアドレスにキリル文字の `а` が混じる場合）、`title` は `null` になります。続いて先にマスクしてから最大 60 文字に切り詰めます。モデルが見つけた氏名・住所・メールアドレス・電話番号・口座番号、および資格情報らしき文字列、メールアドレス、電話番号（全角数字や `+886` を含む）、身分証・在留カード番号、8 桁以上の連続した数字（口座・顧客・カード番号）、ラベル付きの識別情報（「帳號」「客戶編號」、`account no.`）、敬称付きの氏名（「王先生」、`Mr. Smith`）、共有 wiki の人物ディレクトリにある氏名は `＊＊＊` になり、切り詰めた結果をもう一度検査します。モデルが失敗した場合や安全にマスクできない部分がある場合、`title` は `null` になります。モデルは個人情報を減らしますが、まったく含まれないことを保証するものではありません。 |

数字はすべて、この人がダッシュボードで見るのと同じ範囲です。他のアカウントが A2A で開始したタスク、チームの引き継ぎ対象にこの人が含まれないタスク、読む権限のない承認リクエストは数えないため、同じ社員に紐付いた 2 人でも数字が異なることがあります。

応答には会話の内容、タスクの説明、タスク id、`agent_id` 以外の id は含まれません。

### エラー応答

| ステータス | 条件 |
| --- | --- |
| `404 {"error":"not_found"}` | 機能が無効。または `agent_id` がこの人に紐付いた社員ではない。 |
| `401 {"error":"unauthorized"}` | 資格情報がない、誤っている、失効済み、またはアカウントが有効でない。 |
| `400 {"error":"bad_request"}` | `agent_id` 以外のクエリーパラメーター、`agent_id` の重複、または形式の誤り。 |
| `405 {"error":"method_not_allowed"}` | `GET` 以外。 |
| `429 {"error":"rate_limited"}` | 1 つの資格情報で 1 分間に 60 回、同一の接続元アドレス（IPv6 は /64 単位）から 1 分間に 240 回、または全体で 1 分間に 600 回を超えた。`Retry-After` 秒後に再試行してください。 |
| `503 {"error":"unavailable"}` | タスク、承認、ID、アクセスのデータを一時的に読めない（0 で代用することはありません）。または gateway がすでに 4 件の状況照会を処理中で、2 秒以内に空きが出なかった（`Retry-After: 5`）。 |

ダッシュボードで機能をオフにした場合は次の照会から反映されます。`config.toml` を直接編集した場合は 2 秒以内に反映されます。

## セキュリティ

- 独立した資格情報の種類で、呼び出せるのはこの URL だけです。ダッシュボードのログイン、`/api/*`、MCP サーバー（`/mcp`、`/mcp/v1/call`、`/ingest/transcript`）は `ddc_status_` で始まる資格情報をすべて拒否します。`[mcp_keys]` のキーではなく、MCP のスコープ設定の影響も受けません。
- CORS ヘッダーはありません。サーバー間の呼び出し専用で、ブラウザー側のコードに埋め込まないでください。応答には `Cache-Control: no-store` が付きます。
- 識別できる呼び出しはすべて監査します（資格情報 id、アカウント id、結果、社員数）。応答の内容は記録しません。呼び出しは「資格情報・結果・10 分ごと」に集約されます。その 10 分間の最初の呼び出しで `status_token.used`／`status_token.refused` の監査ログを 1 行書き込み、同じ 10 分間の以降の呼び出しは回数と最終時刻を増やすだけです。毎秒ポーリングする連携でも、結果ごとに 1 時間あたり最大 6 行です。資格情報の最終使用日時の更新も 10 分ごとに最大 1 回です。これらの監査ログと回数は 90 日間保持し、その後は少しずつ自動で削除します。ほかの監査ログには影響しません。
- HTTPS を使い、漏えいの疑いがあればすぐに失効させてください。

## Odoo について

- 既存の DuDuClaw Connector モジュールは「Gateway URL」を `/ingest/transcript`（MCP サーバー）に使い、MCP API キーで認証します。社員の状況照会に必要なのは **ダッシュボード gateway の URL** と本人の `ddc_status_` 資格情報で、互いに代用できません。
- 各自のカードには本人の資格情報を使い、本人に紐付いた社員だけが見えるようにしてください。全社で 1 つを共有しないでください。
- Odoo ホストからダッシュボード gateway に到達できる必要があります。カード本体（Odoo 側モジュールの更新）は今回の範囲外です。
