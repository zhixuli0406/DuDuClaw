# Enterprise 管理者向け個人 Google 接続ガイド

各利用者が自分の Google アカウントを使える AI 社員を選ぶ場合の手順です。アカウント本人の接続と同意が必要です。会社の共用接続、OAuth クライアント作成、ドメイン全体の委任は [Google を接続する](google-setup.md)から進めてください。

## 環境を準備する

1. **管理 → 連携 → Google** で Google アプリを設定し、Google Workspace 連携を有効にします。個人接続は全体スイッチを変更しません。
2. 「セキュリティ → 認証情報の保護」を有効にします。個人接続には、対応する macOS／Windows のキーチェーン、[Docker person-credentials オーバーレイ](docker.md#74-個人アカウントperson-credentials-オーバーレイ)、または[ネイティブ Linux の保護システムサービス](linux-protected-service.md)が必要です。通常の Docker と Linux ユーザーサービスは未対応です。パスワードだけの保護、利用できないキーチェーンや独立鍵、読み取れない保存済み認証情報では利用を拒否します。
3. **自分の接続** に表示される完全な戻り先を Google クライアントに登録します。個人用は `/api/me/google/callback`、共用接続ウィザードは `/api/mcp/oauth/callback` です。利用する経路の URL を登録します。承認済み HTTPS ダッシュボードはその URL、それ以外はローカル HTTP と戻り URL 入力欄を使います。ホスト・ポート・パスを一致させ、障害回避のためにローカル callback を公開しないでください。
4. [設定ガイド](google-setup.md)でアカウントとアプリの制限を確認します。External + Testing は七日ごとに再認可が必要です。制限付き Gmail 権限の本番利用前に Google 検証やセキュリティ評価が必要な場合があります。
5. Google データ利用説明と AI 提供元の条件を確認します。Workspace データを汎用モデルの訓練・改善に使うことはできません。条件を確認できない場合は適切なローカルモデルを使うか、Google を接続しません。

Google 専用の接続画面を使ってください。カスタム OAuth やリモートサーバー設定では必要なデータ説明を置き換えられません。学習対象から Workspace データを除外できる保証がないため、この環境ではデータセット作成・エクスポート・新規微調整を拒否します。既存ジョブの確認・取消とデータセット削除は可能です。古い接続は現在の説明を受け入れて再接続するまで、利用・更新できません。

## 本人に接続してもらう

1. 本人が Enterprise ダッシュボードにログインし、**自分の接続** を開きます。再ログインを求められた場合は完了します。
2. データ説明を読み同意し、**自分の Google を接続** を選び、Google 画面でサービスを許可します。許可しなかったサービスは使えません。
3. 自分の接続へ戻ります。ローカルページが開けない場合は完全なアドレスバー URL を元の画面に貼ります。URL を他人に渡さないでください。開始した本人と同じログインで十分以内に完了する必要があり、失効・置換された場合はやり直します。
4. 接続した Google メールを確認します。DuDuClaw のログインメールと異なる場合があります。
5. 本人が社員ごとに許可・拒否を選びます。管理者によるアカウント選択だけでは本人同意になりません。

## 会議録画の取り込みを個別に有効にする

本人が **自分の接続** で会議録画アクセスを有効にし、別の同意手続きを行います。通常の初回個人接続は Drive／Meet 権限を要求しません。有効化した場合だけ、既存の Google 認可に `https://www.googleapis.com/auth/drive.file` と `https://www.googleapis.com/auth/meetings.space.readonly` を追加します。どちらかを拒否した場合は取り込めません。以前の広い権限は自動取消されません。

既存の従業員向け Drive ツールや Google リモート MCP が必要な場合、本人は接続後に **自分の接続** で **従業員の Drive ツールを有効にする** を別途選べます。`https://www.googleapis.com/auth/drive.readonly` を要求し、その Google アカウントがアクセスできる全 Drive ファイルの読み取りを許可します。録画の取り込みとは別の同意であり、取り込みにこの広い権限は不要です。従業員には引き続き本人の利用同意とロール制限が適用されます。追加認可の手続きは一度に一つずつ完了してください。

Gateway は基本サービス、会議録画、従業員の Drive ツールへのローカル同意を別々に保存し、暗号化した資格情報と認可記録に結び付けます。各機能には Google の実際の範囲と対応するローカル用途への同意の両方が必要です。会議の認可で `drive.readonly` や `drive` が追加で返されても、従業員の Drive ツールは有効になりません。追加認可は以前の用途同意を維持し、以前の Google 範囲をすべて保持する必要があります。保存時には元の資格情報のバージョンも照合し、範囲の欠落や同時更新があれば既存の資格情報を置き換えません。ローカル用途同意のない旧記録は再接続が必要です。基本サービスの再接続では用途を基本サービスに戻すため、会議録画と従業員の Drive ツールは改めて個別に有効にしてください。

`drive.file` と Google Picker はアプリが作成していない既存の録画も選択できるため、取り込みでは `drive.readonly` を要求しません。Google の `drive.file` 権限は選択・共有したファイルの作成と変更も許可しますが、DuDuClaw の取り込みは読み取りだけを実行します。DuDuClaw 内の検索はアプリに共有済みの音声・動画だけを表示します。それ以外のファイルや未共有の最近の Meet 録画は Google Picker で選択します。[Google の権限説明](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)と [Picker 設定](https://developers.google.com/workspace/drive/picker/guides/web-picker)も確認してください。

管理者は OAuth アプリの Google Cloud プロジェクトで **Google Drive API**、**Google Meet API**、**Google Picker API** を有効にします。Web アプリケーション用 OAuth クライアントを使い、ダッシュボードのオリジンを承認済み JavaScript オリジンへ追加し、前述の個人接続 callback URI を保持します。`config.toml` にブラウザーキーと数字のプロジェクト番号を設定します。

```toml
[integrations.google_meeting_picker]
developer_key = "your-browser-restricted-google-picker-key"
app_id = "123456789012" # Google Cloud project number, not project ID
```

キーとプロジェクト番号はブラウザーへ渡す公開設定で、OAuth クライアントシークレットではありません。Google OAuth クライアントと同じプロジェクトを使います。キーを Google Picker API と必要な Web サイトのオリジンに制限してください。Picker は iframe で実行されるため、Google の現在の手順では `https://docs.google.com/*` も許可する必要があります。サーバー用や文字起こし提供元の API キーを指定しないでください。設定がない、または不正な場合は Picker を利用できません。

Picker は Google Identity Services から `drive.file` のみ、`include_granted_scopes=false` の短期ブラウザートークンを要求し、本人に再確認を求める場合があります。このトークンは選択処理内でのみ使い、ブラウザーストレージへ保存しません。Gateway の保存済みアクセストークン・更新トークンはブラウザーへ渡しません。取り込みにはログイン中の本人の gateway 接続を使い、Google 画面でアカウントを変更しても別人の gateway 接続へは切り替わりません。

**会議の文字起こし** でファイルを選択し、指定した社員と設定済み文字起こし提供元への送信を確認します。この操作は社員に Drive の閲覧権限を与えません。Meet の参照は Google 自身のアクセス規則に従い、録画ファイルの共有が別途必要になる場合があります。[会議の成果物のアクセス規則](https://developers.google.com/workspace/meet/api/guides/artifacts)と[会議の文字起こし](../../features/ja-JP/73-meeting-transcripts.md)を参照してください。

取り込みにはサーバー発行の確認レシートが毎回必要です。これは JWT で認証されたダッシュボード利用者が、過去 5 分以内にこの正確な Drive ファイル ID を、この受け取り先の社員に渡すことを明示的に登録・確認したと証明します。社員／MCP トークンでは登録できません。レシートは一回限りで、利用者、社員、ファイル ID に結び付き、同じ利用者と社員への新しい確認は以前のレシートを置き換えます。ダッシュボードは利用者が取り込みを確認した時点でファイルを登録します。欠落、期限切れ、再使用、結び付きの不一致は拒否します。取り込み処理に入ると後続の検査が失敗してもレシートを消費するため、再試行には新しい確認が必要です。サーバーはさらに、その利用者の Google 接続で Drive メタデータの `isAppAuthorized=true` を検査します。レシートもこの Google フラグも Google Picker 内のクリックを証明しません。ダッシュボード呼び出し元は、既知の ID を使って以前にアプリへ認可したファイルを明示的に確認できます。

ダッシュボード専用の `POST /api/meeting-drive/selection` は `agent_id`、`file_id`、`confirm: true` を必須とし、`selection_receipt` と `expires_in` を返します。登録リクエストは利用者ごとに毎分 20 回まで、有効なレシートは最大 8 件です。`POST /api/meeting-drive/import` はそのレシートを送信する必要があります。

`google_status` はアカウント、状態、ローカル用途で絞り込んだ範囲メタデータだけを読み取り、資格情報の復号、トークンの更新、bearer の返却は行いません。Token エンドポイントは明示的なツール許可リストを使い、個人資格情報には対応するローカル用途と Google 範囲の両方を要求します。状態照会と未知のツールは bearer を取得できません。

ローカルの Drive 出所記録には、選択したアカウント、Google メール、ファイル ID、バージョンを保存します。取消、失敗、アップロードの失効では、対応する状態変更と同じデータベーストランザクションで出所記録を削除します。それ以外の記録（成功した取り込みを含む）は `imported_at` から 30 日間保持し、期限後は Gateway 稼働中に 60 秒間隔で動く既存の清掃処理で削除します。停止後は次の清掃で処理します。文字起こしファイルと監査ログの保持規則は別で、この出所メタデータの清掃では削除しません。

`user.google_connect` の監査には認可用途、返された範囲集合のハッシュ、想定外の範囲を記録します。Drive／Meet 一覧の読み取りと早期の拒否も記録します。トークンやファイル内容は保存せず、取り込み識別子はハッシュ化します。

個人 Google 接続を解除すると、ローカルで以後の取り込みアクセスを拒否します。追加した Google 認可を取り消す場合は、Google の接続済みアプリを確認し、必要なサービスだけで再接続してください。取り込み中もローカルの接続と実際の権限を確認します。Google 側の取消は API の拒否、または更新した権限への反映で検出します。接続解除は取り込み済みコピー、文字起こし、提供元へ送信済みのデータを回収しません。OAuth、Picker、提供元の処理は実アカウントでの受け入れ確認が必要です。

## 社員と共有範囲を選ぶ

1. 社員の **接続** タブで **主担当者に従う** または **同僚を選ぶ** を選択します。対象者は有効で、その社員に直接 Owner として紐付いている必要があります。
2. Owner が複数で主担当者が未確定なら明示的に選びます。二人目の追加では元の主担当者を保持します。主担当者の削除・降格で指定を解除し、一人だけ残れば自動で選びます。
3. 主担当者の変更を確認する前に影響を確認します。社員のブラウザーセッションを停止し、保存ログインを消去します。消去に失敗した場合は担当者を変更しません。元に戻してもログインは復活せず、更新後の古い保存ログインにも再ログインが必要な場合があります。
4. 誰がアカウント利用を依頼できるか設定します。本人は同意前に同僚、チャネル、共有ルールを確認できます。
5. 個人アカウントが使えないときに会社データを使う意図を本人に説明できた場合に限り、会社への代替を有効にします。

| 依頼者ルール | 利用を依頼できる人 |
|---|---|
| `bound_people` | 社員に紐付く人。既存のアクセス制限も適用 |
| `owner_only` | 選択した本人。定期処理も社員・アカウント・同意の確認が必要 |
| `anyone` | 管理者の明示確認が必要。公開サイト訪問者は引き続き拒否 |

直接 Owner は **自分の Google を使う** または無効化を選べます。依頼者を狭め、会社への代替をオフにできますが、権限拡大や他人の選択はできません。無効化は代替をオフにし、共有ルールを保持または縮小します。自分の再接続でも共有範囲の確認が必要です。これらは接続タブで操作してください。

個人アカウントが利用不能で、管理者が許可した場合だけ会社への代替を検討します。依頼者の拒否、不正な設定、認証情報保護の失敗は会社アクセスに切り替わりません。個人操作開始後のエラーでも会社データに切り替えません。承認カードのアカウントを確認してください。会社側の Google メールが未検証と明記される場合があります。

## 引き渡し前に試す

1. 全体連携がオンで、本人が現在も有効な Owner であり、対象社員に同意済みか確認します。
2. 読めると分かっているメール、予定、文書で、必要な各サービスの読み取りを社員に一度ずつ依頼します。許可すべき依頼者と拒否すべき依頼者の両方を試します。接続確認のための書き込みは不要です。
3. 会社共用接続はダッシュボードで別にテストします。`google_status` のアカウントやローカル認可情報だけではサービス読取を証明できません。連携または社員の Google が無効なら、このツールは非表示です。
4. 認可の期限切れや追加サービスが必要な場合は再接続します。利用ごとに本人、Owner、同意、付与権限を確認します。同意取消は今後の呼出しを拒否しますが、Google へ送信済みの要求は取り消せません。

社員専用の外部 API キーは社員を識別し、人の依頼者を証明しません。その経路で個人アカウントを使うには、管理者の明示的な `requesters = "anyone"` と通常の同意・承認が必要です。HTTP Google MCP は操作ごとに実際の依頼者を確認します。個人アカウントの stdio マウントは拒否します。他の外部連携は別途受入確認が必要です。

## 切断・退職・履歴を管理する

1. 本人が **自分の接続 → 切断** を選ぶか、管理者が **連携 → Google** で切断します。ローカルの利用と未完了の接続を停止してから、Google の取消を試みます。
2. 退職時は本人を停止または削除します。認証情報の削除が完了しなくても、無効な人の利用は拒否します。
3. Google の取消が確認できたか調べます。同じ認可の取消が他の個人や会社接続にも影響する場合はローカルだけで切断します。不明なアカウント、読めない保存情報、会社アカウントの確認失敗でも自動取消を行いません。全認可を消す場合は Google の接続アプリ設定を確認します。
4. 会社のドメイン全体の委任は別で、個人切断では消えません。Windows の個人切断と動的リモート OAuth 切断は現在ローカルのみです。Google 側のアプリ取消は別途行ってください。
5. 最近三十日の最大 500 件の保存履歴を確認できます。時刻、社員、ツール、成功状態のみで、引数・結果・メール本文は含みません。ログ整理で古い履歴が消える場合があります。個人メールの閲覧権限は送信や外送承認を許可しません。

## Google 取消の結果が不明な場合

取消要求後の期限切れ、プロセス中断、通信失敗では結果が不明になる場合があります。その要求に対する Google の即時 HTTP 200 応答だけが確認になります。ローカル利用は停止したまま、不確定記録がある間は新しい Google・リモート接続を拒否します。自動期限や安全に消せるオンラインボタンはありません。再起動、別 Client ID、Google のアプリ一覧が空であることだけでは、以前の要求の完了を証明できません。

1. 新規接続を停止したまま、事故記録、操作 ID、監査情報、`<home>/locks/google-grant-revoke-uncertain.json` を保存します。
2. Google で旧アプリ認可を取り消し、以前の要求が終了したことを外部で確認します。確認できない場合はブロックを保持し、Google に問い合わせます。任意の待ち時間では不十分です。
3. この環境を使うすべての gateway・CLI を停止します。外部確認の後に限り、オフラインの運用者が不確定記録を有効なファイル名の外へ保管できます。操作 ID と理由を残し、他の認証情報やロックファイルを削除しないでください。
4. 再起動して本人に再接続してもらいます。運用者が外部証拠を基に解除したことを記録します。製品自体は遅れた要求が発生しないことを独立して証明できません。

複数 Client ID が同じ Cloud プロジェクトに属せるため、ID の変更は復旧の証拠になりません。更新後はすべての gateway・CLI を再起動してから操作します。キーチェーン処理は画面の期限後に完了する場合があり、取消でも送信済み Google 変更は戻せません。`result_unconfirmed` など書込み結果が不明な場合は Google を確認してから再試行します。

## 管理者設定と制限

```toml
# config.toml
[integrations.google_identity]
allowed_domains = ["example.com"]
allowed_subject_domains = ["example.com"]

# agent.toml
[google]
identity = "owner"          # or "user:<direct-owner-id>"
fallback = "none"           # explicit company fallback: "home"
requesters = "bound_people" # or "owner_only"; "anyone" needs confirmation
```

`allowed_domains` は個人 OAuth のドメインを制限し、空なら Gmail を含む認証済み Google アカウントを許可します。Google の組織ドメインを優先し、なければメールのドメインを使います。これだけでは Workspace 所属の証明になりません。`allowed_subject_domains` は委任する同僚の住所を制限し、空の扱いも異なります。[Workspace 安全モデル](google-workspace.md)を参照してください。不正な設定は拒否します。

バックアップ・移設時は対応キーチェーンを保持し、個人接続を使う間はダウングレードしないでください。認証情報はディスク上で保護されますが、gateway と同じ OS ユーザーで制限のない Bash を使える社員は、製品制御を回避したりローカル情報を書き換えたりできます。必要な能力だけを与えてください。Google の下書きスコープは API からの送信も許しますが、DuDuClaw の下書きツールは送信しません。

明示した会社の認証経路を優先し、失敗は報告します。旧環境は管理者が経路を保存するまで従来の選択を保持します。Apps Script は Gmail、Calendar、Sheets の七データ操作と状態確認、計八アクションに対応し、CC、参加者、Meet、リモート MCP bearer は対象外です。アカウント選択は正常性の検証ではありません。Google に届いた可能性のある操作を別経路で自動再送してはいけません。

製品外の認証情報変更は直ちに検出できない場合があります。期限切れや取消でも進行中のキーチェーン・ディスク処理を強制停止できず、設定確認から送信までの変更にも制限があります。
