# ターミナルコントロールルーム

[English](../tui.md) · [繁體中文](../zh-TW/tui.md)

`duduclaw tui` は承認待ち、返信が必要な目標タスク、従業員の状態を表示します。行を選択すると詳細を確認できます。ゲートウェイが次回の自律実行時刻を提供する場合、管理者にはその予定も表示されます。画面を閉じても従業員の処理は停止しません。

全画面のコントロールルームで承認と目標の意思決定カードを利用できます。チャット、入力フォーカス、`tui watch`、任意の通知を利用できます。従業員状態の一時停止・再開は M2 の権限検証と確認カードを使います。画面の言語は繁体字中国語です。

## 起動

ゲートウェイを起動し、同じホストで実行します。

```sh
duduclaw tui
duduclaw tui inbox
duduclaw tui inbox --follow
duduclaw tui inbox --follow --json
duduclaw tui watch adu
```

全画面表示にはターミナルが必要です。`inbox` はスナップショットを一度出力して終了します。`--follow` は内容が変わるたびに新しい完全なスナップショットを出力します。`--json` は stdout に `type`、`stale`、`count`、`error`、`items` を持つ JSON オブジェクトを一行ずつ出力します。出力自体に TTY は不要ですが、アカウントログインが必要な場合は対話端末が必要です。無人ログイン用の token 引数や認証情報ファイルはありません。

接続先は `127.0.0.1` です。ポートは `DUDUCLAW_PORT`、`<home>/config.toml [gateway] port`、既定値の順で決まります。Home は `DUDUCLAW_HOME`、未設定なら `~/.duduclaw` です。このバージョンにリモート URL オプションはありません。

**リモートから利用する場合は、SSH でゲートウェイのホストに入り、そのホストで実行してください。ゲートウェイのポートを転送しないでください。** 転送すると、転送元ホストのプログラムもループバック限定のローカルログイン経路にアクセスできます。

## コマンドパレットと終了サマリー（M3）

リスト、ヘルプ、入力フォーカスで `Ctrl-P` を押すとパレットを開きます。繁体字中国語のラベルや `stop`、`steer`、`log` などの英語別名をあいまい検索し、矢印で選択、`Enter` で表示されたキーの処理を実行、`Esc` で下書きを保ったまま元のフォーカスに戻ります。`Ctrl-K` は予約済みです。現在のブロック、ロール、従業員との操作権限、データの鮮度から利用可能な操作を再計算します。制御操作は通常と同じ確認カードを開き、承認や確認を代行しません。カードや内容表示の警告中はパレットを開けません。

`F1` / `?` のヘルプはフォーカス中のブロックだけに表示します。長い home パスは先頭を省略し末尾を残します。最小の 12 行でも受信箱と従業員の一覧に各一行を残し、予定パネルは隠れる場合があります。枠線は常に ASCII で、マウスなしで操作できます。Windows のキー解放イベントでコマンドは実行しません。

終了して端末を復元した後、保留受信件数（ローカルでスヌーズ中の項目を含む）、実行中の従業員名、同じ home に戻るコマンドを標準出力へ表示します。古い件数や従業員情報は `?` です。名前は無害化して長さを制限し、タスク、チャット、ツールなどの内容は出力しません。Unix の復帰コマンドは Bash/Zsh の ANSI-C 引用、Windows は PowerShell を使用します。終了しても従業員は動作を続けます。Windows のクラッシュダンプ抑制は未実装で、クロスコンパイルは実機の端末検証ではありません。

## ログイン

| エディション・状態 | 動作 |
|---|---|
| Personal、ローカル自動ログインが有効 | ゲートウェイが許可すれば入力なしでアカウントセッションを取得します。 |
| Personal、自動ログイン無効、パスワード設定済み | パスワード方式を選び、アカウントのメールアドレスとパスワードを入力します。 |
| Personal、自動ログイン無効、初期設定未完了 | ダッシュボードでパスワードを設定するか、ローカル自動ログインを有効にしてください。 |
| Team / Enterprise | パスワード**または**アカウントのメールアドレスに対応する確認コードを選択します。それぞれ単独でログインが完了します。これらのエディションではローカル自動ログインは許可されません。 |
| パスワード変更が必要 | 先にダッシュボードで変更してください。 |
| セッション期限切れ | メモリ内で token を更新して再接続します。更新に失敗すると再びアカウントログインを求め、自動ログインには戻りません。 |
| 管理者以外 | 権限のある従業員と受信項目のみ表示します。管理者パネルには必要な権限を説明します。 |

OTP は代替のログイン方法であり、**二要素認証ではありません**。正しいパスワードだけでも完全なセッションが発行されます。クライアントはパスワードと OTP を連続させず、第二要素による保護を主張しません。入力したアカウントのメールアドレスを使ってコードを要求し、ゲートウェイに設定・連携済みのチャネルで受け取ります。ダッシュボードでコード受信が利用できることを先に確認してください。パスワードとコードは画面に表示されません。入力案内と固定エラーメッセージは stderr に出力します。

## キー操作と更新

| キー | 操作 |
|---|---|
| 矢印 / `j` / `k` | 選択を移動 |
| `Enter` | 詳細または意思決定カードを開く |
| `r` | 項目、または識別子のある完了実行をこのクライアントで既読にする |
| `PgUp` / `PgDn` | 詳細をスクロール |
| `?` / `F1` | ヘルプの表示切り替え |
| `q` / `Ctrl-C` | 終了 |

新着項目が選択を奪うことはありません。既読にしてもゲートウェイの保留項目は閉じません。完了表示は最近の実行履歴に基づくもので、過去の未読すべてを表すものではありません。

切断、イベント欠落、再取得未完了の場合は `資料可能過期`（古い情報の可能性）を表示し、件数は `?` になります。JSON は `stale: true`、`count: null` です。最後に完全取得できた一覧を保持します。再取得全体の上限は 2,000 行とエンコード済み応答内容 4 MiB で、全従業員、受信項目、最近の実行、予定が共有します。上限を超えると再取得を中止し、部分的な一覧を完全なものとして表示しません。WebSocket メッセージ／frame は最大 256 KiB、イベントキューは 16 件です。大規模な環境ではダッシュボードをご利用ください。

## チャットと入力フォーカス

状態行にフォーカスを常時表示します。一覧では `1`～`4` でブロックを選択し、`C` でチャットを開きます。従業員を選び `i` で入力、`/` ではスラッシュから入力を始めます。`Esc` で下書きを残して一覧へ戻ります。入力中の一文字キーは本文になります。CJK、IME の確定文字、括弧付きペーストに対応し、`Enter` で送信、`Ctrl-C` で終了します。

先頭の `@name ` はクライアントが WebChat の `agent` フィールドに変換し、本文から除きます。指定しなければ入力開始時に選んだ従業員へ送ります。`/goal`、`/status`、`/cost` はそのまま送信します。`/pause`、`/stop`、`/resume` は Computer Use 用であり、**従業員を一時停止しない**という案内を表示します。

右側は最大四ブロックです。操作は次節を参照してください。同時進行は一 turn に制限し、思考とツール手順は状態一行に折り畳みます。ASCII でも回転表示を使います。一覧フォーカスの `PgUp`／`PgDn` で履歴をスクロールでき、最大 2,000 行、各行 512 文字に制限します。新しい出力はフォーカスを移しません。従業員の文字列は `TerminalText` を通し、OSC 8 リンクは生成しません。

`/ws/chat` は一接続だけで、`/ws` のメモリ内トークン更新を共有し、バックオフで再接続します。結果不明の送信を自動再送しません。完了した会話は再接続後も継続でき、相手の変更で新しい会話を始めます。ゲートウェイから `msg_id` 付き frame を受信した場合のみ、一覧で `X` により今回の返答を取り消せます。未対応時は取消不可と表示します。`cancel_accepted` は受付だけで、`cancelled` または最終応答まで待ちます。取消には PR #264 の追加プロトコルが必要ですが、通常のチャットは現行ゲートウェイで動作します。

## ブロックとタスク操作（M2）

右側には一～四ブロックを配置できます。`v` は左右、`x` は上下に分割し、`1`～`4` で選択、`Ctrl-W` でローカルのブロックを閉じます。閉じてもタスクやチャットは停止しません。右側が 64 桁未満または 16 行未満になると、選択中の一枚と非表示数を示し、拡大すると元の配置に戻ります。アプリ再起動後の配置保存はありません。

`D`／`C`／`R`／`T`／`L` は詳細、チャット、実行、タスク、ログです。従業員を選んでから `R`／`T` を押すと対象を固定し、左側の選択変更には追従しません。`C` は既存チャットを選ぶか作成し、チャット表示は一つの会話を共有します。`[`／`]` で記録、`PgUp`／`PgDn` でスクロール。実行は最近 50 件、タスクは一ページ 50 件でゲートウェイの総数に従います。

実行は `runs.get` の履歴を読み、`runs.subscribe` を試します。未知メソッド応答に限り五秒ごとのポーリングを明示し、他の失敗はエラーです。`run.step` は従業員と実行 ID が一致したものだけを受け取り、最大 256 件で履歴も定期取得します。既知の非 Claude 従業員で手順がない場合は「此 runtime 只回報起訖」と表示します。現在の runtime は過去の実行に使用された runtime の証明ではありません。内容は初期状態では非表示。`c` で警告を読み、再度 `c` で表示、他のキーで取消します。警告は起動ごとに一回で、その後は `c` で切替。プレビューは短縮のみで秘密情報はマスクされません。

タスクは `tasks.list_page`、`tasks.iterations`、`tasks.timeline`、`tasks.changes`、`tasks.stop_status` を使用します。初期表示は判定、イベント種別、変更パスのみで、評価コメントやソース断片、ツール内容は出しません。`Enter` で目標カードを開き、終了済み目標も追加メッセージ付きで続行できます。Operator／Owner binding があれば未終了目標の `e` で方向を補足（最大 4,000 文字、`Enter` で確認へ）、`s` で停止します。steering の有効化はゲートウェイが判定します。停止は `expected_authority_revision`、目標決定は `expected_updated_at` を送ります。

タスクで `b` を押すと継続責任へ切り替わり、`[`／`]` で選択、`responsibilities.get` の次回トリガーと `responsibilities.fires` を表示します。`p` 一時停止、`d` 無効化は `expected_control_epoch` 付きです。`o` はゲートウェイが返した今回のタスク ID を開き、同じ方向補足／停止を利用できます。恒常的な権限、契約変更、全体設定はダッシュボードに残します。

ログは `logs.subscribe` を使い Manager／Admin に限定し、他の役割には理由を表示します。最大 256 行、各 2,048 文字で全行 `TerminalText` を通します。ゲートウェイにログの再送機能はなく、欠落行は復元できません。

予定欄は有効・停止中の cron（Admin）と heartbeat（Manager／Admin）を表示します。cron は `p` 一時停止／再開、`n` 一回実行、heartbeat は `n` 手動実行です。cron 手動実行には新しい `request_id` を付けます。現行 `cron.list` に次回時刻、`heartbeat.status` に前回結果はないため、未提供と表示して推測しません。詳細に規則、タイムゾーン、取得できた前回時刻／結果を示します。

従業員の `p` は `agents.pause`／`agents.resume` による状態停止／復帰です。Manager と Operator／Owner binding が必要で、Admin はゲートウェイの管理者規則に従います。このブランチには `autonomy.pause` がなく、カードで全面的な自律停止ではないと明示します。全体停止は提供しません。

新しい操作は独立した確認カードを使い、一秒間のキー無視、全文確認、新しい二桁コードを要求します。古いデータや表示対象の変更時は送信を拒否し、自動再送はしません。受付、拒否、競合後は再取得し、成功状態を先に表示しません。停止受付後も `cancel_pending` の場合があります。制限付き sandbox では socket 偽ゲートウェイ、実ゲートウェイ、ネイティブ端末検証は NOT RUN。プロセス内の偽 RPC テストで wire 形式と確認状態遷移を検証します。

## 従業員一人の監視

`duduclaw tui watch adu` は無害化した文字列を行形式で出し、alternate screen を使いません。最初に `runs.subscribe { agent_id }` を試し、現行ゲートウェイの未知メソッド応答ではポーリングを明示して、五秒ごとに `runs.list` と `runs.get` を読みます。最近四実行、各実行の末尾 256 イベントと上限付き重複検出を使用します。対応ゲートウェイの `run.step` も受信し、保存履歴を定期確認します。`Ctrl-C` で終了します。AI セッションでの拒否とアカウント認証は他のサブコマンドと同じです。

既定では時刻、状態、従業員、ステップ種別またはツール名のみを表示し、ユーザーやアシスタントの文章、ツール引数は表示しません。`duduclaw tui watch adu --content` で内容プレビューを有効にすると、機密情報がマスクされていない旨を stderr に警告します。未知のイベント形式はどちらのモードでも名前のみを表示し、JSON ペイロードは出力しません。

## 端末通知

既定で無効で、`SSH_CONNECTION` があっても自動的に有効にはなりません。`tui.toml` の `notifications = true` で明示的に有効にします。端末が非アクティブで最新の受信件数が増えた時、OSC 9 で固定文 `DuDuClaw：N 項需要你處理` だけを出します。N は数値で、従業員名、タスク名、ツール内容は含みません。利用可能ならフォーカスイベントを使い、それ以外は非アクティブと扱います。一分に一回までで、抑制した増加は後から通知しません。tmux では `tmux show-option -gv allow-passthrough` が `on` または `all` を返す場合のみ passthrough を使い、それ以外は省略します。実際の表示は端末の対応によります。

## 意思決定カード

受信行を選び `Enter` でカードを開きます。新着は一覧とバッジのみ更新し、カードを開いたりフォーカスを奪ったりしません。開いてから最初の一秒間はすべてのキー入力を無視します。`Esc` で閉じ、矢印と `PgUp` / `PgDn` でスクロールします。 選択行が消えた場合は同じ位置の次の行、または最後の行を選びます。選択 ID が残る限り、新着や並び替えでは選択を移しません。

承認は表示された二桁の確認コードを入力して `Enter`、拒否は `n` です。開くたびに直前と異なるランダムなコードを生成します。すべての承認操作は制御文字を可視化してペイロード全体を表示し、末尾が見えるまでコードを入力できません。画面幅の変更で再びロックされる場合があります。これは誤入力や画面を見ない入力への対策だけです。**同じ UID で画面を読めるプロセスは防げません**。本人の在席証明や認証ではありません。 現在は全承認を高リスクとして扱います。`approvals.list` の `kind` は安全分類ではなく、gateway が生成した安全分類もないため、操作種類だけや `payload` の値ではリスクを下げません。リサイズ時は入力を消去し、再描画後に待機キーを処理します。下部の操作案内は一覧・カード・ヘルプのフォーカスに合わせて変わります。

目標カードでは `r` が再試行です。`a` 中止、`d` 完了、`t` 引き継ぎは同じキーを二回押します。カウントダウンはなく、別のキーで確認を解除します。`c` 続行は終了済みの目標に限り、明示的な追加メッセージが必要です（`i` 編集、`Esc` 編集終了）。受信箱は `needs_human` のみですが、終了済み目標はタスクブロックでカードを開いて続行できます。`tasks.goal_decide` は `task_id`、`action`、任意の `note`、続行時に必須の `message` を受け取ります。任意の `expected_updated_at` はタスクの `updated_at` 文字列との完全一致を要求し、全五操作で比較と更新を同じ SQLite トランザクション内で行います。不一致は固定エラー `goal_decide_revision_mismatch` となり、タスク更新も決定記録も行いません。省略時は従来のダッシュボード動作を維持します。コントロールルームはカードの値を常に送り、欠落時は目標決定を送信しません。

`may_decide=false` は理由付きの読み取り専用です。目標操作には `users.me` の Operator／Owner バインディング、または Admin 権限が必要です。ダッシュボード限定の承認、回答が必要な質問、バインドされた操作はダッシュボードに残ります。固定の案内を表示し、サーバー由来の URL は開きません。恒常的な権限や全体設定の変更もダッシュボードで行います。

承認には空でない文字列 `digest` が必要で、`expected_digest` として送信します。欠落または null（閲覧者向けの内容非表示を含む）の場合、承認 RPC は送信せずカードを開いたまま、固定文 **內容未綁定：這張卡無法確認你看到的就是實際內容，請到儀表板決定** を表示します。`n` による拒否は可能です。コントロールルームからの承認には、`approvals.list` に digest を追加する **PR #261 のマージが必要**です。構造化された digest 不一致ではカードを閉じて再取得し、固定の変更通知を表示します。RPC エラーや結果不明のタイムアウトを含め、送信後は再取得し、成功の先行表示や自動再送はしません。エラー文は `TerminalText` を通し、古い情報、期限切れ、期限不明の承認は操作できません。

一覧またはカードの `s` は最大十分間、行をローカルで隠します。承認は残り TTL の 80% が上限で、残り 20% または十分の短い方になる前に理由付きで再表示します。指定した再表示時刻が早い場合はそちらを優先し、期限短縮時も再表示します。期限切れは拒否を意味し、スヌーズで延長できません。識別子と時刻のみ `tui-state.json` に保存し、行形式の `inbox` は引き続き全保留一覧を表示します。 時計が設定時刻より前へ戻ると、そのスヌーズの非表示を解除します。同じセッション内では単調時計でも期限を制限し、再起動後は時計の連続性を確認できないためカードを再表示します。

## ローカルファイル

| Home 内のファイル | 用途 |
|---|---|
| `tui-state.json` | 既読またはスヌーズ時に書き込みます。既読の識別子とスヌーズの時刻のみを保存し、同じディレクトリの一時ファイルを使って原子的に置き換えます。 |
| `tui.toml` | 操作者が任意に作成する設定。TUI は読み取るだけで、作成・変更しません。 |

```toml
# ~/.duduclaw/tui.toml
glyphs = "ascii"                 # または "unicode"
ambiguous_width = "narrow"        # または "wide"。端末の文字幅に合わせる
notifications = false
poll_interval_seconds = 15        # 5..3600
default_layout = "single"         # "vertical" / "horizontal"
```

対応するすべてのトップレベルキーを示します。不正な値はそのキーだけ既定値を維持して通知し、他の有効なキーは適用します。未知のキー（接続、認証、安全設定を含む）は通知して無視します。TOML の構文エラー、読み取り失敗、容量超過では全項目を既定値に戻します。設定は起動時に一回読み取ります。

| キー | 有効値 | 既定値と効果 |
|---|---|---|
| `glyphs` | `"ascii"`, `"unicode"` | `"ascii"`。従業員状態の記号、枠線は ASCII |
| `ambiguous_width` | `"narrow"`, `"wide"` | `"narrow"`。端末の曖昧幅に合わせる |
| `poll_interval_seconds` | 5～3600 の整数 | `15`。一覧の再照合間隔。実行／タスク／ログの照合は五秒のまま |
| `notifications` | 真偽値 | `false`。SSH も同様。明示的な有効化で固定文の背景通知 |
| `default_layout` | `"single"`, `"vertical"`, `"horizontal"` | `"single"`。詳細一個、左右二個、上下二個。初期フォーカスはブロック 1 |

セッション中の配置変更は保存しません。接続、認証、権限、確認、安全規則は変更できません。枠線は ASCII です。両ファイルとも既存の agent-file-guard のホームディレクトリ保護対象です。

## セキュリティ上の制限

要求ごとにゲートウェイが権限を確認します。アカウント JWT はメモリ内に保持し、旧管理者 token や `system` 身分は拒否します。接続できなくてもゲートウェイのデータベースを直接読みません。`RUST_LOG=trace` でもログ subscriber、ログファイル、テレメトリの出力を初期化しません。Unix では認証情報を取得する前に core dump を無効化します。アプリ側の秘密バッファは可能な範囲で消去しますが、端末、HTTP、TLS、WebSocket ライブラリ内部のコピーの消去は保証できません。Windows のクラッシュダンプ抑制は未実装のため、「秘密をディスクに残さない」という保証は Unix のみに適用されます。

AI セッションでの起動拒否と Bash コマンドガードは、誤用を減らすための措置です。同じ OS ユーザーとして無制限の shell を使える従業員は回避や直接のファイル変更が可能です。実際の隔離には OS 身分の分離、タスクサンドボックス、または Bash 権限を与えない運用が必要です。

表示前にゲートウェイ由来の制御文字を除去し、詳細では除去した文字を可視化します。CJK／emoji 表示のため U+FE00–U+FE0F は保持します。U+E0000–U+E0FFF は補助異体字セレクタも含め全範囲を除去します。JSON は元の文字を保持します。stdout が端末の場合は無害化処理が禁止する全ての文字（双方向制御文字と既定で無視される文字を含む）を追加でエスケープし、端末以外の出力は変更しません。受信側はデコードした文字列を端末に表示する前に無害化してください。

通信ライブラリは正確なループバックアドレスでのみ平文を許可します。`localhost` は REST と WebSocket ともに `127.0.0.1` に固定され、hosts／DNS の変更を使いません。TLS 検証は有効なままなので、この接続には固定 IP に有効な証明書が必要です。ライブラリの呼び出し元は IPv6 ループバックを `[::1]` で指定できます。
