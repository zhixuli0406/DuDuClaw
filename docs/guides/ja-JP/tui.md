# ターミナルコントロールルーム

[English](../tui.md) · [繁體中文](../zh-TW/tui.md)

`duduclaw tui` は承認待ち、返信が必要な目標タスク、従業員の状態を表示します。行を選択すると詳細を確認できます。ゲートウェイが次回の自律実行時刻を提供する場合、管理者にはその予定も表示されます。画面を閉じても従業員の処理は停止しません。

全画面のコントロールルームで承認と目標の意思決定カードを利用できます。チャット、入力フォーカス、`tui watch`、任意の通知を利用できます。従業員状態の一時停止・再開は 既存の権限検証と確認カードを使います。画面の言語は繁体字中国語です。

## サイドバーのワークスペース

左のサイドバーは 28～34 桁です。スタッフごとに二行のカードを表示し、一行目は状態記号・表示名・状態、二行目は現在の作業情報です。要対応、エラー、作業中、待機（未読の完了を含む）、一時停止／終了の順で、同じ分類では名前順に並びます。左の強調色の線はこのクライアントで未読の受信項目がある印で、選択は背景色で示します。幅が 100 桁未満なら記号と短い名前だけの一行になります。

二行目は受信項目の種類／題名、読み込み済みタスクの現在の目標ラウンドと経過分、次のハートビート、自律作業の停止理由、待機の順で選びます。ラウンド上限が不明なら分母を省略し、推測しません。ハートビートは Manager／Admin のみ取得でき、古いタスク・予定のスナップショットは要約に使いません。下部の `收件匣 N ▸` は情報行を含む表示項目数です。`I`、または入口を選んで `Enter` を押すと、スタッフと理由を含む受信箱がメイン領域に開きます。`Esc` でサイドバーへ戻ります。小文字の `i` はチャット入力のままです。

右側の `對話 / 任務 / 紀錄` タブは `Tab`／`Shift-Tab` で切り替えます。`[`／`]` はタスク・実行・ワークフローの前後レコードに使います。既存のチャット・タスク・実行ブロックを使い、`L` はログです。切り替えても下書き、実行中の返信、スクロール位置を保持します。非表示タブを含め最大四会話で、未使用の空会話は回収できます。四つとも内容がある場合は不要な会話へ戻り `Ctrl-W` で閉じます。他のスタッフを選ぶと、そのタスクタブは開けます。分割 `v`／`x`、フォーカス `1`～`4`、PTY、意思決定カード、自律作業のブロックは既存のキーや `Ctrl-P` から利用できます。

次のハートビートはスタッフカードに表示します。Manager／Admin は `S` または予定の入口から完全な一覧を開き、`Enter` で詳細を確認できます。Cron の可視性と確認・認可の処理は変わりません。未実行の予定は `尚未執行`、不正な時刻は `時間不明` と表示します。

一行のヘッダーに接続、バージョン、取得可能な費用を表示します。ドルは小数二桁、ゼロ以外で $0.01 未満なら四桁です。独自の home は幅に合わせて短縮し、`?` には既定の home を含む完全なパスを表示します。最小サイズは 24×12 のままです。Unicode と ASCII のスナップショットは 80×24、100×30、140×40、200×50 を対象とし、今回のネイティブ端末での受け入れ確認を意味しません。


## 起動

ゲートウェイを起動し、同じホストで実行します。

```sh
duduclaw tui
duduclaw tui inbox
duduclaw tui inbox --follow
duduclaw tui inbox --follow --json
duduclaw tui watch adu
```

全画面表示にはターミナルが必要です。`inbox` はスナップショットを一度出力して終了します。`--follow` は内容が変わるたびに新しい完全なスナップショットを出力します。`--json` は stdout に `type`、`stale`、`count`、`error`、`items` を持つ JSON オブジェクトを一行ずつ出力します。出力自体に TTY は不要ですが、アカウントログインが必要な場合は対話端末が必要です。無人ログイン用の token 引数や認証情報ファイルはありません。

接続先は `127.0.0.1` です。ポートは `DUDUCLAW_PORT`、`<home>/config.toml [gateway] port`、既定値の順で決まります。Home は `DUDUCLAW_HOME`、未設定なら `~/.duduclaw` です。このバージョンにリモート URL オプションはありません。

**リモートから利用する場合は、SSH でゲートウェイのホストに入り、そのホストで実行してください。ゲートウェイのポートを転送しないでください。** 転送すると、転送元ホストのプログラムもループバック限定のローカルログイン経路にアクセスできます。

## 組み込みローカル端末

リストフォーカスで `P` を押すか、コマンドパレットで `pty` を選ぶと、現在のブロックに操作者自身の端末が開きます。既定は `$SHELL`、未設定なら `/bin/sh` です。操作者の環境を継承し、すべての `DUDUCLAW_*` 変数を除去します。ゲートウェイ JWT はメモリ内に保持され、子プロセスの環境には追加されません。AI セッション内での起動拒否も維持します。ゲートウェイの応答からローカルコマンドを指定することはできません。

端末入力中は **`Ctrl-\` または `F12` でコントロールルームに戻ります**（従来の端末が返す `Ctrl-4` も受け付けます）。`Esc`、`Ctrl-C`、`Ctrl-P`、矢印、ファンクションキー、ページキーなどの通常の端末キーは子プロセスに渡します。`Enter` / `i` で入力に戻れます。コントロールルーム側のフォーカスで `PgUp` / `PgDn` を押すと、最大 5,000 行の履歴をスクロールします。貼り付けは改行と Tab を保持するテキストとして渡し、bracketed paste を解除できる制御文字を除去します。子プロセスが要求した場合だけ bracketed paste で囲みます。同じバッチのキー入力はまとめて専用 writer から順番に送信します。子プロセスが読み取りを停止してもホスト端末のイベントを読み続けるため、戻るキー、コントロールルームの終了、リサイズを操作できます。端末入力中は `F12`／`Ctrl-\` の後に `q` で終了します。キュー内と書き込み中の合計上限は 1 MiB で、超える入力は全体を拒否してメッセージを表示します。PTY 入力フォーカス中、表示範囲内かつ子がマウス報告を有効にした場合だけ転送します。従来形式、UTF-8（1005）、urxvt（1015）、SGR（1006）に対応し、座標はブロックと表示文字幅に合わせます。SGR-Pixels（1016）はホストのセル寸法からブロック内の 1 始まりのピクセル座標を推定します。寸法が得られない場合は 1 セルを 8×16 ピクセルとし、セル内の正確なポインター位置は取得できません。優先順位は 1016 > 1006 > 1015 > 1005 > 従来形式です。他のブロックには送りません。ステータス行にフォーカスと戻るキーを表示します。

ブロックが起動するのは、コントロールルームを起動した人の環境にあるシェルだけです。Unix は `$SHELL`（未設定時 `/bin/sh`）、Windows は `%ComSpec%`（未設定時 `cmd.exe`、Windows PTY は引き続き無効）を使用します。他のプログラムはそのシェルから実行してください。`tui.toml` は信頼できる実行境界ではありません。旧 `[pty] command` は削除され、残っているキーは設定通知とともに無視されます。他の有効な設定は維持します。

専用の解析スレッドが VT モデルを更新し、可視セルだけのサイズ制限付きスナップショットを公開します。描画と決定カードは解析を待ちません。固定容量の前処理フィルタが 7-bit OSC、DCS、APC、PM、SOS の文字列制御を破棄します。OSC は最大 256 bytes だけ調べて表示専用の待機マーカーを更新し、内容を転送しません。CAN／SUB は列を取り消し、ESC はエスケープ解析を再開します。有効な UTF-8 に含まれない生の 8-bit C1 バイトは破棄し、UTF-8 文字は全体の検証後に通します。ESC はホワイトリスト内の短いエスケープ、文字集合指定、CSI が完成した場合だけ出力します。CSI は導入符の後で最大 128 bytes、32 パラメータ（サブパラメータを含む）とし、超過した列は破棄します。回数と位置のパラメータだけを `max(行数, 列数, 1)` に制限し、スクロール領域は画面の行数以内に制限します。フィルタは読み取り境界をまたいでも、長さ制限内の CSI を終端バイトまで保持します。SGR 色、プライベート列、モード、レポート、ウィンドウ操作、カーソル保存列はそのまま通します。描画するのはサニタイズしたセル文字、色、太字です。OSC のクリップボード・タイトル・リンク、DCS、sixel、端末モード列はホスト端末に再送しません。レイアウト変更で PTY をリサイズし、最大 200 行 × 500 列に制限します。CJK 全角セルと結合文字は両方の幅設定で描画します。parser は ambiguous 文字の narrow 座標を使い、wide 描画では文字を広げてブロック境界で切り取ります。ambiguous 文字の wide カーソル座標に依存する全画面アプリは未検証です。

起動待ち／実行中の子プロセスがあるブロックの閉鎖・置換は `y` で確認し、`Esc` で取り消します。終了時にはローカル PTY プロセスを停止しますが、ゲートウェイの従業員は継続します。Unix は既存のプロセスグループ helper を使い、シェルの回収前に同一 session のジョブグループも列挙します。意図的に離脱したプロセス（`setsid` など）は通常の端末と同様に実行を続けます。同一 session の終了に成功してもすべての子孫の停止は証明できないため、クリーンアップは未確認と表示します。列挙・シグナル送信の失敗時も同様です。Windows は ConPTY ツリーの終了が未検証のため無効です。既存の Job Object helper は他の起動経路で利用されています。端末文字から「返答待ち」を推定するバッジは追加しておらず、端末出力が操作を承認することはありません。

通常終了時、RPC `/ws` と WebChat `/ws/chat` は Close を送信し、相手の応答を最大一秒待ちます。コントロールルーム、inbox、watch の入口は終了処理を待ちます。


## コマンドパレットと終了サマリー

リスト、ヘルプ、入力フォーカスで `Ctrl-P` を押すとパレットを開きます。繁体字中国語のラベルや `stop`、`steer`、`log` などの英語別名をあいまい検索し、矢印で選択、`Enter` で表示されたキーの処理を実行、`Esc` で下書きを保ったまま元のフォーカスに戻ります。`Ctrl-K` は予約済みです。現在のブロック、ロール、従業員との操作権限、データの鮮度から利用可能な操作を再計算します。自律作業の停止／再開は即時送信します。他の制御操作は通常と同じ確認カードを開き、承認を代行しません。カードや内容表示の警告中はパレットを開けません。

`F1` / `?` のヘルプはフォーカス中のブロックだけに表示します。ヘッダーの home パスは `~/.duduclaw` と異なる場合だけ表示し、ユーザーのホームを `~` に、長いパスの中間を省略します。最小の 12 行でもスタッフカードと受信箱・予定の入口を残し、選んだ一覧をメイン領域で開きます。ヘルプには完全な home パスも表示します。Unicode モードでは角丸の枠線、ASCII モードでは ASCII の枠線を使い、マウスなしで操作できます。Windows のキー解放イベントでコマンドは実行しません。

コントロールルームの操作は、作業を停止するか一段階だけ進めるものです。恒常的な権限は付与しません。Admin は自律作業の全体停止／再開を操作できます。`cron run now`、`heartbeat trigger`、タスク停止は一方向の操作で、確認カードを通じて実行します。操作がすべて元に戻せるわけではありません。

終了して端末を復元した後、保留受信件数（ローカルでスヌーズ中の項目を含む）、実行中の従業員名、同じ home に戻るコマンドを標準出力へ表示します。古い件数や従業員情報は `?` です。名前は無害化して長さを制限し、タスク、チャット、ツールなどの内容は出力しません。Unix の復帰コマンドは Bash/Zsh の ANSI-C 引用、Windows は PowerShell を使用します。終了しても従業員は動作を続けます。Windows のクラッシュダンプ抑制は未実装で、クロスコンパイルは実機の端末検証ではありません。

## ログイン

| エディション・状態 | 動作 |
|---|---|
| Personal、ローカル自動ログインが有効 | ゲートウェイが許可すれば入力なしでアカウントセッションを取得します。 |
| Personal、自動ログイン無効、パスワード設定済み | パスワード方式を選び、アカウントのメールアドレスとパスワードを入力します。 |
| Personal、自動ログイン無効、初期設定未完了 | ダッシュボードでパスワードを設定するか、ローカル自動ログインを有効にしてください。 |
| Team / Enterprise | パスワード**または**アカウントのメールアドレスに対応する確認コードを選択します。MFA 設定済みの場合は、その後に認証アプリのコードまたはリカバリーコードが必要です。これらのエディションではローカル自動ログインは許可されません。 |
| パスワード変更が必要 | 先にダッシュボードで変更してください。 |
| セッション期限切れ | メモリ内で token を更新して再接続します。更新に失敗すると再びアカウントログインを求め、自動ログインには戻りません。 |
| 管理者以外 | 権限のある従業員と受信項目のみ表示します。管理者パネルには必要な権限を説明します。 |

パスワードとチャネルコードは、最初のログイン方法として選択できます。MFA を設定済みのアカウントでは、どちらの方法でも、その後に認証アプリの6桁コードまたはリカバリーコードによる第二段階の認証が必要です。誤ったコードはゲートウェイの試行上限内で再入力できます（端末側でも最大5回）。期限切れや上限到達時は再ログインしてください。MFA の登録が必要な場合はダッシュボードで設定してください。端末では登録トークンを使用しません。

チャネルコードは入力したメールアドレスで要求し、設定・連携済みのチャネルで受け取ります。ダッシュボードで受信できることを先に確認してください。パスワード、認証コード、リカバリーコードは表示されず、案内と固定エラーは stderr に出力します。対話端末がなくコード入力が必要な場合は、`tui inbox --json` でも待機せずエラーで終了します。MFA 非対応のゲートウェイでは従来のログイン手順を維持します。

## キー操作と更新

| キー | 操作 |
|---|---|
| 矢印 / `j` / `k` | 選択を移動 |
| `Enter` | サイドバーの入口、詳細または意思決定カードを開く |
| `I`／`S` | 受信箱／予定を開く。`Esc` でサイドバーへ戻る |
| `Tab`／`Shift-Tab` | 次／前のスタッフタブ。`[`／`]` はレコードの切り替え |
| `r` | 項目、または識別子のある完了実行をこのクライアントで既読にする |
| `PgUp` / `PgDn` | 詳細をスクロール |
| `?` / `F1` | ヘルプの表示切り替え |
| `q` / `Ctrl-C` | 終了 |

新着項目が選択を奪うことはありません。既読にしてもゲートウェイの保留項目は閉じません。完了表示は最近の実行履歴に基づくもので、過去の未読すべてを表すものではありません。

切断、イベント欠落、再取得未完了の場合は `資料可能過期`（古い情報の可能性）を表示し、パネルの見出しでは不明な件数を省略します。JSON は `stale: true`、`count: null` です。最後に完全取得できた一覧を保持します。再取得全体の上限は 2,000 行とエンコード済み応答内容 4 MiB で、全従業員、受信項目、最近の実行、予定が共有します。上限を超えると再取得を中止し、部分的な一覧を完全なものとして表示しません。WebSocket メッセージ／frame は最大 256 KiB、イベントキューは 16 件です。大規模な環境ではダッシュボードをご利用ください。

## チャットと入力フォーカス

状態行にフォーカスを常時表示します。一覧では `1`～`4` でブロックを選択し、`C` でチャットを開きます。従業員を選び `i` で入力、`/` ではスラッシュから入力を始めます。`Esc` で下書きを残して一覧へ戻ります。入力中の一文字キーは本文になります。CJK、IME の確定文字、括弧付きペーストに対応し、`Enter` で送信、`Ctrl-C` で終了します。

先頭の `@name ` はクライアントが WebChat の `agent` フィールドに変換し、本文から除きます。指定しなければ入力開始時に選んだ従業員へ送ります。`/goal`、`/status`、`/cost` はそのまま送信します。`/pause`、`/stop`、`/resume` は Computer Use 用であり、**従業員を一時停止しない**という案内を表示します。

右側は最大四ブロックです。操作は次節を参照してください。異なるチャットは同じ接続上で並行実行でき、各会話は一 turn ずつです。従業員、会話、下書き、履歴、スクロールと取消の確認はブロックごとに保持し、上限エラーも該当ブロックに表示します。未知または矛盾する識別子のフレームは無視します。思考とツール手順は状態一行に折り畳みます。ASCII でも回転表示を使います。一覧フォーカスの `PgUp`／`PgDn` で履歴をスクロールでき、最大 2,000 行、各行 512 文字に制限します。新しい出力はフォーカスを移しません。従業員の文字列は `TerminalText` を通し、OSC 8 リンクは生成しません。

`/ws/chat` は一接続だけで、`/ws` のメモリ内トークン更新を共有し、バックオフで再接続します。結果不明の送信を自動再送しません。完了した会話は再接続後も継続でき、相手の変更で新しい会話を始めます。ゲートウェイから `msg_id` 付き frame を受信した場合のみ、一覧で `X` により今回の返答を取り消せます。未対応時は取消不可と表示します。`cancel_accepted` は受付のみを意味します。キャンセル完了は `type: error`、`code: cancelled` のフレームで通知します。すでに配信を開始している場合は、最終応答でターンが終わることもあります。

そのターンから委任した作業がまだ実行中の場合、ゲートウェイは件数と一回限りの非公開参照値を返します。画面には「還有 N 位員工的工作還在跑，要一起停嗎？ y 停止／n 讓它們跑完」と表示します。**一覧フォーカス**の `y` は停止要求を一度だけ送り、`n` または `Esc` は質問を閉じます。**入力フォーカス**では `y` と `n` は普通の本文で、状態行に一覧へ戻って回答する方法を表示します。新しい出力でフォーカスは変わらず、参照値も表示しません。質問の有効期間は 10 分で、切断時に消え、ゲートウェイの再起動でも失効します。無回答または質問を閉じた場合は要求を送らず、委任作業を続行します。

結果は「已停止 N 項」、必要なら「M 項還在收尾」と表示し、停止処理中の作業を停止済みに数えません。参照値が使えなくなった場合の「這個詢問已失效，下游工作不受影響」は、今回の要求では何も停止していないことを示します。公開 Widget の訪問者にはスタッフの作業を操作する権限がなく、質問を表示しません。資格情報の失効による自動停止は、ターンの実行中、または失効後に停止要求が届いた場合に適用します。すでに完了したターンの作業や、誰も回答しない質問の作業は自動停止しません。

対象は、元の会話とターンが完全に一致する委任実行だけです。他の人に帰属する作業は除外します。実行済みの外部操作は取り消せません。ターンが作成したタスクボードのタスクや目標は追跡せず、それぞれの操作で停止してください。出所情報を失った実行も見つけられません。残した作業は完了まで続けられます。キャンセルしたターンを持つ行はフェンスで遮断され、新たな委任や承認を作成できません。意図的に lineage を捨てたり偽造した実行は追跡しません。スタッフ全体の一時停止ではなく、他の会話には影響しません。

停止済みは、管理対象のプロセスグループと使用中のタスクサンドボックスコンテナが消えたことを意味します。`setsid` などで意図的にグループを離れたプロセスは、従業員がタスクサンドボックスで実行されている場合を除き、この確認の対象外です。Unix のローカル子プロセスは、親プロセスの終了だけでは停止済みとせず、プロセスグループ全体が消えるまで確認します。タスクサンドボックスの実行では、コンテナの後処理も確認します。待機時間内に確認できない実行は「まだ停止処理中」に含めます。Windows の現在のプロセス管理インターフェースでは全プロセスの終了を確認できないため、終了を要求済みでも、キャンセルした子プロセスの実行は保守的に停止処理中として報告します。外部サービスへ送信済みの要求は、ローカルの実行を停止しても取り戻せません。Gemini CLI と Antigravity runtime は削除済みで、ここでのディスパッチ経路はありません。Gemini API プロバイダーは引き続き対応しています。これは実装上の報告範囲の説明であり、ネイティブ環境や外部サービスでの検証完了を示すものではありません。

## ブロックとタスク操作

右側には一～四ブロックを配置できます。`v` は左右、`x` は上下に分割し、`1`～`4` で選択、`Ctrl-W` でローカルのブロックを閉じます。閉じてもタスクやチャットは停止しません。右側が 64 桁未満または 16 行未満になると、選択中の一枚と非表示数を示し、拡大すると元の配置に戻ります。アプリ再起動後の配置保存はありません。

`D`／`C`／`R`／`T`／`L` は詳細、チャット、実行、タスク、ログです。従業員を選んでから `R`／`T` を押すと対象を固定し、左側の選択変更には追従しません。`C` は別のチャットを開きます（詳細ブロックを使用するか追加し、合計最大四個）。`i` はフォーカス中のチャットを使い、他の種類からは既存チャットを開くか新規作成します。入力、`X` による取消、下流停止の確認は対象ブロックだけに属します。`[`／`]` で記録、`PgUp`／`PgDn` でスクロール。実行は最近 50 件、タスクは一ページ 50 件でゲートウェイの総数に従います。

実行は `runs.get` の履歴を読み、`runs.subscribe` を試します。未知メソッド応答に限り五秒ごとのポーリングを明示し、他の失敗はエラーです。`run.step` は従業員と実行 ID が一致したものだけを受け取り、最大 256 件で履歴も定期取得します。既知の非 Claude 従業員で手順がない場合は「此 runtime 只回報起訖」と表示します。現在の runtime は過去の実行に使用された runtime の証明ではありません。内容は初期状態では非表示。`c` で警告を読み、再度 `c` で表示、他のキーで取消します。警告は起動ごとに一回で、その後は `c` で切替。プレビューは短縮のみで秘密情報はマスクされません。

タスクは `tasks.list_page`、`tasks.iterations`、`tasks.timeline`、`tasks.changes`、`tasks.stop_status` を使用します。初期表示は判定、イベント種別、変更パスのみで、評価コメントやソース断片、ツール内容は出しません。`Enter` で目標カードを開き、終了済み目標も追加メッセージ付きで続行できます。Operator／Owner binding があれば未終了目標の `e` で方向を補足（最大 4,000 文字、`Enter` で確認へ）、`s` で停止します。steering の有効化はゲートウェイが判定します。停止は `expected_authority_revision`、目標決定は `expected_updated_at` を送ります。

タスクで `b` を押すと継続責任へ切り替わり、`[`／`]` で選択、`responsibilities.get` の次回トリガーと `responsibilities.fires` を表示します。`p` 一時停止、`d` 無効化は `expected_control_epoch` 付きです。`o` はゲートウェイが返した今回のタスク ID を開き、同じ方向補足／停止を利用できます。恒常的な権限、契約変更、全体設定はダッシュボードに残します。

ログは `logs.subscribe` を使い Manager／Admin に限定し、他の役割には理由を表示します。最大 256 行、各 2,048 文字で全行 `TerminalText` を通します。ゲートウェイにログの再送機能はなく、欠落行は復元できません。

予定欄は有効・停止中の cron（Admin）と heartbeat（Manager／Admin）を表示します。cron は `p` 一時停止／再開、`n` 一回実行、heartbeat は `n` 手動実行です。cron 手動実行には新しい `request_id` を付けます。cron の `next_run` はゲートウェイの RFC3339 値を表示し、null は未予定または不明と扱います。heartbeat は実際の `last_run` 時刻を表示し、成功とは推測しません。詳細に規則、タイムゾーン、取得できた前回時刻／結果を示します。

リストフォーカスで従業員を選択し、`p` で `autonomy.pause {agent_id}`、`u` で `autonomy.resume {agent_id}` を即時送信します。カードや確認待ちはありません。Manager と対象従業員の有効な Operator/Owner バインディングが必要で、ゲートウェイが再確認します。入力フォーカスでは `p`／`u` は文字のままです。責任ブロックの `p` はその責任を操作します。cron の `p`、cron／heartbeat の `n` は選択中のスケジュールに対して動作し、Detail ブロックのフォーカスは不要です。即時実行、heartbeat トリガー、タスク停止の確認カードは維持します。

Admin は `Ctrl-P` で「暫停全部自主工作」または「恢復全部自主工作」を選び、`{all:true}` を即時送信できます。全体再開には単一キーのショートカットがありません。状態行には停止中の名前（最大二名、各十二文字まで、残数は `+N`）または「自主: 全部暫停」を表示します。接続、再接続、イベント欠落、各 `autonomy.changed` の後で `autonomy.status` を取得し、データが古い、再取得待ち、または読み取れない場合は、従業員行、バッジ、状態行に「待確認」を表示し、古い情報から自律作業の停止中・実行中を示しません。拒否理由を表示し、成功を先取りした状態変更はしません。

自律停止は従業員状態と独立して永続化され、新しい自律作業を遮断します。人からの直接会話は利用でき、進行中のターンは完了してから次のラウンドが遮断されます。全体再開は全体停止だけを解除し、個別停止は残ります。従業員行では自律停止、従業員状態の停止、終了を区別します。パレットの「暫停員工狀態（需確認）」／「恢復員工狀態（需確認）」は既存の確認カード付きで `agents.pause`／`agents.resume` を実行します。従業員自身の稼働状態を変更し、独立した自律停止は解除しません。

自律作業の停止・再開は例外として確認カードなしで即時送信します。タスク、継続責任、予定、従業員状態の操作は引き続き独立した確認カードを使い、一秒間のキー無視、全文確認、新しい二桁コードを要求します。古いデータや表示対象の変更時は送信を拒否し、自動再送はしません。受付、拒否、競合後は再取得し、成功状態を先に表示しません。停止受付後も `cancel_pending` の場合があります。制限付き sandbox では socket 偽ゲートウェイ、実ゲートウェイ、ネイティブ端末検証は NOT RUN。プロセス内の偽 RPC テストで wire 形式と確認状態遷移を検証します。

## 自律サブシステムの表示

リストまたは `Ctrl-P` から `W` ワークフロー、`A` 自動ルール、`E` 進化とプレイブック、`B` 予算イベント、`G` 最新ダイジェストを開けます。分割、フォーカス切り替え、スクロールに対応します。空、拒否、古い情報、利用不可を区別し、空の可視範囲を「異常なし」とは表示しません。ゲートウェイの文字列は端末用に無害化し、各フィールドは 240 文字、表は 50 行までです。省略した内容はダッシュボードで確認できます。

- **ワークフロー**：タスクブロックで元のタスクを選択して `W`。そのタスクのドラフト先頭ページ（最大 20 件）と、各ドラフトの最大 20 実行を読みます。テスト実行は除外します。`[`／`]` で実行とステップを確認し、`s` で一方向のキャンセル確認カードを開きます。Manager と Operator 権限が必要で、ゲートウェイは元タスクとドラフト所有者の権限を再確認します。有効化や恒常的な権限の変更は提供しません。
- **自動ルール**：Admin のみ。ルールと実際の `closed`、`open`、`half_open`、開始時刻を表示します。エンジン利用不可や欠落した状態を closed と扱いません。
- **進化**：Manager／Admin の状態と停滞情報、選択した従業員の Viewer 権限で取得したプレイブックを表示します。変更操作はありません。
- **タスク**：受入条件台帳のモード、条件、証拠、未解決項目、更新ラウンド、およびチームのロール別ターンを表示します。台帳がない場合は未提供、ロール取得失敗は別のエラーとして表示します。
- **予算とダイジェスト**：予算イベントは Manager／Admin 向けの履歴であり、ブレーカーが現在も開いている証明ではありません。ダイジェストは閲覧範囲内の最新保存結果と納品項目名を表示し、フィードバックの書き込みは追加しません。

`budget.breaker_open` と `autopilot.breaker_open` は従業員またはルールを示す、上限付きの情報行になります。`Enter` は対応する表示を開き、決定カードは開きません。現在の接続で観測したイベントであり、完全な履歴ではありません。承認と停止中の目標も従業員、承認種類または停止理由を表示します。

パレットの「建立自主目標」、または従業員を選択して `N` を押すと目標を入力できます。`Tab` で「先擬計畫」（初期値は有効）を切り替え、`Enter` で確認カードへ進みます。`tasks.goal_create` に `agent_id`、`description`、`plan_first` を送ります。承認待ち計画には「核准計畫」を表示し、カード末尾まで確認して二桁コードを入力します。RPC 上は `retry` ですが、この場合の `r` は無効です。長すぎるタスクカードは読み取り専用で、ダッシュボードへ案内します。

終了した目標で `c` を一度押すと継続メッセージ入力に直接フォーカスします。入力または貼り付け後、`Esc` は入力を消去して閉じます。`Enter` だけが対象タスクと全文の確認へ進みます。確認時に一秒のガードと新しい二桁コードを設定し、末尾までスクロールしてコードを入力後、`Enter` で送信します。長すぎる内容はダッシュボードで確認します。空のメッセージは送れません。一秒のキーガード、鮮度・権限・リビジョン確認、自動再送なしという規則は維持します。

ヘッダーは現在の接続で観測した実行数を表示します。再接続やイベント欠落で観測は失われます。ターンの任意の `task_id` があれば従業員の `T` をタスクへ結び付け、欠落は未知として扱います。イベントに結果や run ID はないため、完了・エラー表示は実行履歴を使います。実行タイトルには取得したソースとラウンドを表示し、上限は推測しません。Admin の費用は `cost.summary {since:<ローカル午前零時の RFC3339>}` を使い、ゲートウェイが同じ境界と有効な金額を返した場合だけ「今日」と表示します。日付ごとのタイムゾーンと夏時間を反映します。旧ゲートウェイでは `hours:24` と「近 24 小時」に戻し、拒否・利用不可なら金額を隠します。`since` は `hours` より優先し、不正・未来の時刻を拒否、保持期間（現在 30 日）と 31 日の短い方までに制限します。リストのフッターには選択名と `Ctrl-P`、`q` を表示します。

## 従業員一人の監視

`duduclaw tui watch adu` は無害化した文字列を行形式で出し、alternate screen を使いません。従業員モードではポーリングを明示し、五秒ごとに `runs.list` と `runs.get` を読みます。ゲートウェイの購読には一意の `run_id` が必要なため、従業員モードは購読を要求しません。最近四実行、各実行の末尾 256 イベントと上限付き重複検出を使用します。`--run` では単一実行を購読し、旧版が未知メソッドを返した場合のみ通知して五秒ごとのポーリングへ切り替えます。`Ctrl-C` で終了します。AI セッションでの拒否とアカウント認証は他のサブコマンドと同じです。

既定では時刻、状態、従業員、ステップ種別またはツール名のみを表示し、ユーザーやアシスタントの文章、ツール引数は表示しません。`duduclaw tui watch adu --content` で内容プレビューを有効にすると、機密情報がマスクされていない旨を stderr に警告します。未知のイベント形式はどちらのモードでも名前のみを表示し、JSON ペイロードは出力しません。

## 端末通知

既定で無効で、`SSH_CONNECTION` があっても自動的に有効にはなりません。`tui.toml` の `notifications = true` で明示的に有効にします。端末が非アクティブで最新の受信件数が増えた時、VTE／rxvt-unicode では OSC 777、その他では OSC 9 で固定文 `DuDuClaw：N 項需要你處理` だけを出します。N は数値で、従業員名、タスク名、ツール内容は含みません。利用可能ならフォーカスイベントを使い、それ以外は非アクティブと扱います。一分に一回までで、抑制した増加は後から通知しません。tmux では `tmux show-option -gv allow-passthrough` が `on` または `all` を返す場合のみ passthrough を使い、それ以外は省略します。実際の表示は端末の対応によります。

## 意思決定カード

受信行を選び `Enter` でカードを開きます。新着は一覧とバッジのみ更新し、カードを開いたりフォーカスを奪ったりしません。開いてから最初の一秒間はすべてのキー入力を無視します。`Esc` で閉じ、矢印と `PgUp` / `PgDn` でスクロールします。 選択行が消えた場合は同じ位置の次の行、または最後の行を選びます。選択 ID が残る限り、新着や並び替えでは選択を移しません。

承認は表示された二桁の確認コードを入力して `Enter`、拒否は `n` です。開くたびに直前と異なるランダムなコードを生成します。すべての承認操作は制御文字を可視化してペイロード全体を表示し、末尾が見えるまでコードを入力できません。画面幅の変更で再びロックされる場合があります。これは誤入力や画面を見ない入力への対策だけです。**同じ UID で画面を読めるプロセスは防げません**。本人の在席証明や認証ではありません。 現在は全承認を高リスクとして扱います。`approvals.list` の `kind` は安全分類ではなく、gateway が生成した安全分類もないため、操作種類だけや `payload` の値ではリスクを下げません。リサイズ時は入力を消去し、再描画後に待機キーを処理します。下部の操作案内は一覧・カード・ヘルプのフォーカスに合わせて変わります。

承認待ち計画がない目標カードでは `r` が再試行です。`a` 中止、`d` 完了、`t` 引き継ぎは同じキーを二回押します。カウントダウンはなく、別のキーで確認を解除します。終了済みの目標で `c` を押すと追加メッセージ入力に入り、`Esc` で入力を消去して閉じます。`Enter` で対象タスクと全文を確認し、一秒のガード後、末尾までスクロールして新しい二桁コードを入力し、`Enter` で送信します。長すぎる内容はダッシュボードで確認します。受信箱は `needs_human` のみですが、終了済み目標はタスクブロックでカードを開いて続行できます。`tasks.goal_decide` は `task_id`、`action`、任意の `note`、続行時に必須の `message` を受け取ります。任意の `expected_updated_at` はタスクの `updated_at` 文字列との完全一致を要求し、全五操作で比較と更新を同じ SQLite トランザクション内で行います。不一致は固定エラー `goal_decide_revision_mismatch` となり、タスク更新も決定記録も行いません。省略時は従来のダッシュボード動作を維持します。コントロールルームはカードの値を常に送り、欠落時は目標決定を送信しません。

`may_decide=false` は理由付きの読み取り専用です。目標操作には `users.me` の Operator／Owner バインディング、または Admin 権限が必要です。ダッシュボード限定の承認、回答が必要な質問、バインドされた操作はダッシュボードに残ります。固定の案内を表示し、サーバー由来の URL は開きません。恒常的な権限や全体設定の変更もダッシュボードで行います。

承認には空でない文字列 `digest` が必要で、`expected_digest` として送信します。欠落または null（閲覧者向けの内容非表示を含む）の場合、承認 RPC は送信せずカードを開いたまま、固定文 **內容未綁定：這張卡無法確認你看到的就是實際內容，請到儀表板決定** を表示します。`n` による拒否は可能です。digest は `approvals.list` が提供します。構造化された digest 不一致ではカードを閉じて再取得し、固定の変更通知を表示します。RPC エラーや結果不明のタイムアウトを含め、送信後は再取得し、成功の先行表示や自動再送はしません。エラー文は `TerminalText` を通し、古い情報、期限切れ、期限不明の承認は操作できません。

一覧またはカードの `s` は最大十分間、行をローカルで隠します。承認は残り TTL の 80% が上限で、残り 20% または十分の短い方になる前に理由付きで再表示します。指定した再表示時刻が早い場合はそちらを優先し、期限短縮時も再表示します。期限切れは拒否を意味し、スヌーズで延長できません。識別子と時刻のみ `tui-state.json` に保存し、行形式の `inbox` は引き続き全保留一覧を表示します。 時計が設定時刻より前へ戻ると、そのスヌーズの非表示を解除します。同じセッション内では単調時計でも期限を制限し、再起動後は時計の連続性を確認できないためカードを再表示します。

## ローカルファイル

| Home 内のファイル | 用途 |
|---|---|
| `tui-state.json` | 既読またはスヌーズ時に書き込みます。既読の識別子とスヌーズの時刻のみを保存し、同じディレクトリの一時ファイルを使って原子的に置き換えます。 |
| `tui.toml` | 操作者が任意に作成する設定。TUI は読み取るだけで、作成・変更しません。 |

```toml
# ~/.duduclaw/tui.toml
theme = "auto"                   # "light" / "dark"
# glyphs = "ascii"               # 任意で "ascii" / "unicode" を指定
ambiguous_width = "narrow"        # または "wide"。端末の文字幅に合わせる
notifications = false
poll_interval_seconds = 15        # 5..3600
default_layout = "single"         # "vertical" / "horizontal"
```

対応するすべてのトップレベルキーを示します。不正な値はそのキーだけ既定値を維持して通知し、他の有効なキーは適用します。未知のキー（接続、認証、安全設定を含む）は通知して無視します。TOML の構文エラー、読み取り失敗、容量超過では全項目を既定値に戻します。設定は起動時に一回読み取ります。

| キー | 有効値 | 既定値と効果 |
|---|---|---|
| `theme` | `"auto"`, `"light"`, `"dark"` | `"auto"`。起動時に端末の背景を検出、または明るい／暗い配色を明示指定 |
| `glyphs` | `"ascii"`, `"unicode"` | UTF-8 ロケールで `TERM` が `linux`、`dumb` 以外なら Unicode、それ以外は ASCII。明示設定を優先し、Unicode では角丸の枠線 |
| `ambiguous_width` | `"narrow"`, `"wide"` | `"narrow"`。端末の曖昧幅に合わせる |
| `poll_interval_seconds` | 5～3600 の整数 | `15`。一覧の再照合間隔。実行／タスク／ログの照合は五秒のまま |
| `notifications` | 真偽値 | `false`。SSH も同様。明示的な有効化で固定文の背景通知 |
| `default_layout` | `"single"`, `"vertical"`, `"horizontal"` | `"single"`。詳細一個、左右二個、上下二個。初期フォーカスはブロック 1 |

`theme = "auto"` は起動時に OSC 11 で端末の背景を問い合わせ、約 150 ミリ秒でタイムアウトします。有効な応答がなければ `COLORFGBG`、暗い配色の順にフォールバックします。`light` または `dark` の明示指定では背景検出を行いません。色は `COLORTERM=truecolor` または `24bit`、`256color` を含む `TERM`、16 色 ANSI の順で対応します。`NO_COLOR` 環境変数は空文字を含む任意の値で色を無効にし、太字と反転で強調や選択を示します。

Unix の OSC 11 検出は raw mode の有効化後、イベントループと同じ crossterm reader で行い、通常のキー入力を保持します。Windows のネイティブ console、非 TTY 入力、`TERM=linux` または `dumb`、`NO_COLOR` 設定時は問い合わせを省略し、`COLORFGBG`、暗い配色の順に使います。16 色のコントラスト計算は参照 ANSI パレットに基づき、実際のコントラストは端末で設定された ANSI 色によって決まります。

入力の復元には時間制限があります。ESC 導入部の断片が 50 ミリ秒を超えて離れた場合、または識別済みの応答が 150 ミリ秒を超えて途切れた場合は、応答の断片と通常のキーを確実に区別できません。任意に遅延した断片は検証済みの復元範囲外です。

記号の既定値は `LC_ALL`、`LC_CTYPE`、`LANG` の順に最初の空でない値を使います。Unicode の状態記号は `◉` 要対応、`●` 作業中、`○` 待機、`✓` 完了、`✕` エラー、`⏸` 一時停止です。100 桁以上ではどちらのモードでも状態の文字を表示します。時刻はローカル時間を使い、一時間以内は繁体字中国語の相対表記、当日は `HH:MM`、それ以外は `MM/DD HH:MM`、無効な時刻は `時間不明` と表示します。空のパネルには表示される内容の説明があり、フッターではキーと説明を別々に強調します。

セッション中の配置変更は保存しません。接続、認証、権限、確認、安全規則は変更できません。両ファイルとも既存の agent-file-guard のホームディレクトリ保護対象です。

## セキュリティ上の制限

要求ごとにゲートウェイが権限を確認します。アカウント JWT はメモリ内に保持し、旧管理者 token や `system` 身分は拒否します。接続できなくてもゲートウェイのデータベースを直接読みません。`RUST_LOG=trace` でもログ subscriber、ログファイル、テレメトリの出力を初期化しません。Unix では認証情報を取得する前に core dump を無効化します。アプリ側の秘密バッファは可能な範囲で消去しますが、端末、HTTP、TLS、WebSocket ライブラリ内部のコピーの消去は保証できません。Windows のクラッシュダンプ抑制は未実装のため、「秘密をディスクに残さない」という保証は Unix のみに適用されます。

AI セッションでの起動拒否と Bash コマンドガードは、誤用を減らすための措置です。同じ OS ユーザーとして無制限の shell を使える従業員は回避や直接のファイル変更が可能です。実際の隔離には OS 身分の分離、タスクサンドボックス、または Bash 権限を与えない運用が必要です。

表示前にゲートウェイ由来の制御文字を除去し、詳細では除去した文字を可視化します。CJK／emoji 表示のため U+FE00–U+FE0F は保持します。U+E0000–U+E0FFF は補助異体字セレクタも含め全範囲を除去します。JSON は元の文字を保持します。stdout が端末の場合は無害化処理が禁止する全ての文字（双方向制御文字と既定で無視される文字を含む）を追加でエスケープし、端末以外の出力は変更しません。受信側はデコードした文字列を端末に表示する前に無害化してください。

通信ライブラリは正確なループバックアドレスでのみ平文を許可します。`localhost` は REST と WebSocket ともに `127.0.0.1` に固定され、hosts／DNS の変更を使いません。TLS 検証は有効なままなので、この接続には固定 IP に有効な証明書が必要です。ライブラリの呼び出し元は IPv6 ループバックを `[::1]` で指定できます。


### 会話とローカル通知

`duduclaw tui watch --run <run-id>` は `runs.get` と `runs.subscribe {run_id}` で一つの実行を追跡します。位置引数は従来どおり従業員名で、`--run` と併用できません。内容表示の明示選択、サニタイズ、AI セッション拒否は共通です。

`dashboard.navigate` は `/inbox?item=` で読み込み済みの受信項目を示す受動的な通知のみ受け付けます。選択、フォーカス、カード、`p`／`u` の対象従業員は変更しません。`/agents/...`、その他のパス、未知の項目、不正なパスは無視します。入力中、PTY 入力中、ヘルプや確認カード表示中も通知を処理しません。

子の OSC 9、OSC 777 `notify`、または OSC 0／2 のタイトルが `waiting for you`、`waiting for input`、`needs input` と一致する場合（大文字小文字を区別しない）、固定の待機マーカーを表示します。ローカル入力で解除します。表示専用であり、許可・応答・ゲートウェイ呼び出し・ホスト通知には使いません。長すぎる文字列や不正な列は無視します。

接続エラーの通知も固定文 `DuDuClaw：連線中斷，請檢查控制室` だけで、非アクティブ条件と毎分一回の制限を共有します。
