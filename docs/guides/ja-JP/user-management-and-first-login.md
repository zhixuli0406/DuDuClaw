# メンバーの追加と初回ログインの案内

管理者は **ユーザー → メンバーを追加** から一度に最大10人を追加できます。名前、メールアドレス、役割、任意の部署を入力し、AI分身と追加の AI スタッフを選びます。各スタッフへのアクセスは「操作可能」または「閲覧のみ」です。AI分身は必要な権限がある場合に新しい会話や仕事の依頼の初期選択になります。AI分身の指定だけで権限が増えることはありません。端末を操作するスタッフには従来の専用承認が必要で、この画面では紐付けできません。

同じAIを複数メンバーの分身にはできません。割り当て済みなら別のAIを選んでください。分身は管理者が設定し、メンバー自身では切り替えられません。退職処理で分身を解除し、従来の移管手順は維持します。

「招待メールを送信」は初期状態でオンです。「招待メールをプレビュー」では画面の言語に対応する保存済みの内容を確認できます。プレビューのリンクでアカウントを有効にすることはできません。共通パスワードや仮パスワードは作成しません。送信をオフにしてアカウントと紐付けだけを作り、後からユーザー一覧で招待できます。

各行は独立したデータベース取引です。アカウント、紐付け、AI分身、必要な招待情報、初回案内の進捗、監査記録がすべて成功した場合だけ保存します。1行が失敗しても成功した行は残ります。メール送信は保存後に行うため、**送信に失敗してもアカウントは作成済み**です。管理者はリンクをコピーするか招待を再発行できます。再発行すると古いリンクは無効になります。失敗した行を再試行しても成功した行は再送しません。ブラウザが結果を受け取れなかった場合は、再試行する前にユーザー一覧を確認してください。

既存のメール設定と宛先ポリシーを使用します。ゲートウェイに公開 URL を設定してください。未設定の場合は現在の画面のオリジンを使用します。招待に使う公開 URL はすべて HTTPS が必須です。localhost を含むループバック URL も例外ではありません。リンクは7日間有効で1回だけ使用でき、データベースにはハッシュのみ保存します。パスワード設定後は通常のログインを行い、必要な場合は第二要素も確認します。

## 招待メールを編集する

管理者が **設定 → 招待メール** を開き、繁体字中国語、英語、日本語ごとに冒頭文、設定手順、3つの例を編集できます。初期の例は資料の要約、返信案の作成、リマインダーです。任意の講座リンクは HTTPS のみ使用でき、URL 内にユーザー名やパスワードを含めることはできません。

プレビューと送信メールは同じ処理で作成します。文章はエスケープし、対応する `**太字**` と改行のみを表示に反映します。生の HTML、画像、Markdown リンクは文字として扱います。パスワード設定リンクと有効期限はシステムが追加します。プレビューは有効な招待を発行せず、メールも送信しません。

## 初回ログイン

招待されたメンバーがパスワードを設定してログインすると、ホームに「あと少しで準備完了」が表示されます。

- パスワード設定はアカウントの状態から自動的に完了します。
- チャネルは管理者が本人のチャネル ID を確認して紐付けます。スキップできます。
- Google は「自分の接続」から接続します。スキップできます。保存済みの状態を確認するもので、Google API の実動作テストではありません。
- 例を選ぶと新しい会話に下書きを入力します。自動送信はしません。
- AI スタッフの能力、制限、承認、誤り、プライバシーの説明を読み、既読にします。

進捗はログイン中の本人ごとにサーバーに保存します。接続の完了は検証済みの記録から判断し、ブラウザから成功を申告することはできません。すべて完了またはスキップするか、閉じるとカードが消えます。案内によって権限は増えず、パスワードや多要素認証の手順も省略しません。移行時に既存アカウントへ自動表示しませんが、既存の招待リンクを使用した人にも案内を有効にします。

## 検証範囲

データベースと RPC のテストを含みます。実際の SMTP 送信、稼働中ゲートウェイでの初回ログイン、ブラウザ操作は別途受け入れ確認が必要です。

AI分身には「操作可能」権限が必要です（既存の Owner 権限も対象です）。「閲覧のみ」は追加スタッフ向けで、分身の選択やダッシュボードでの会話開始・再開には使えません。既存のメイン設定と分身も現在の権限で再確認され、閲覧のみに変更すると会話候補から外れます。招待とコースの URL は localhost を含め HTTPS が必須で、認証情報を埋め込むことはできません。

## AI 分身とライセンス枠

**AI 分身は従業員枠を消費しません**。有効なメンバー本人の Personal AI で、本人が Owner 権限を持ち、１人１体・１体１人の条件を満たす必要があります。共有社員の割り当て、Operator 権限だけの AI、設定フラグ、読み取れない本人情報は免除対象外です。アーカイブした AI は枠を消費し、削除すると枠が空きます。ユーザー、AI 社員、ライセンスの各ページには通常の使用枠と免除された分身数を別々に表示します。

分身の変更・解除、Owner の紐付け解除、メンバーの停止・退職、AI のアーカイブで上限を超える場合は保存を拒否します。不要な AI を削除するか、ライセンス枠を増やしてください。管理者は `users.set_avatar` に `agent_id: null` と `delete_avatar: true` を指定して、同じリクエストで分身 AI を削除し割り当てを解除できます。通常の認証情報クリーンアップと Personal 書き込み権限確認（ネイティブ分離で追加認証が必要な場合は `step_up_csrf`）も実施し、失敗時は削除済みであることと再試行が必要な処理を返します。

通常枠が満員でも、管理者は `agents.create` に `{ "name": "member-avatar", "avatar_for_user": "MEMBER_ID" }` を指定して新しい Personal 分身を作れます。有効で分身未設定のメンバーが対象です。Personal 所有情報、Owner 紐付け、分身設定をまとめて作成し、既存の通常社員は変換できません。ネイティブ Linux 分離環境では管理者が `isolation.employee_propose` に `binding_kind: "personal"`、`owner_id`、`as_avatar: true` を指定します。追加認証と既存の root 配置承認を維持し、承認前の AI は実行されません。既存の RM-212 分身は現在の Owner と Personal 記録を確認してから免除され、移行時に共有 AI を Personal AI に変えません。`license.status` は `seats_used` と `avatars_exempt` を返し、不明な値は `null` です。
