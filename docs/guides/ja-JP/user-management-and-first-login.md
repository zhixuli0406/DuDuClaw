# メンバーの追加と初回ログインの案内

管理者は **ユーザー → メンバーを追加** から一度に最大10人を追加できます。名前、メールアドレス、役割、任意の部署を入力し、主担当と追加の AI スタッフを選びます。各スタッフへのアクセスは「操作可能」または「閲覧のみ」です。主担当は必要な権限がある場合に新しい会話や仕事の依頼の初期選択になります。主担当の指定だけで権限が増えることはありません。端末を操作するスタッフには従来の専用承認が必要で、この画面では紐付けできません。

「招待メールを送信」は初期状態でオンです。「招待メールをプレビュー」では画面の言語に対応する保存済みの内容を確認できます。プレビューのリンクでアカウントを有効にすることはできません。共通パスワードや仮パスワードは作成しません。送信をオフにしてアカウントと紐付けだけを作り、後からユーザー一覧で招待できます。

各行は独立したデータベース取引です。アカウント、紐付け、主担当、必要な招待情報、初回案内の進捗、監査記録がすべて成功した場合だけ保存します。1行が失敗しても成功した行は残ります。メール送信は保存後に行うため、**送信に失敗してもアカウントは作成済み**です。管理者はリンクをコピーするか招待を再発行できます。再発行すると古いリンクは無効になります。失敗した行を再試行しても成功した行は再送しません。ブラウザが結果を受け取れなかった場合は、再試行する前にユーザー一覧を確認してください。

既存のメール設定と宛先ポリシーを使用します。ゲートウェイに公開 URL を設定してください。未設定の場合は現在の画面のオリジンを使用します。招待に使う公開 URL はすべて HTTPS が必須です。localhost を含むループバック URL も例外ではありません。リンクは7日間有効で1回だけ使用でき、データベースにはハッシュのみ保存します。パスワード設定後は通常のログインを行い、必要な場合は第二要素も確認します。

## 招待メールを編集する

管理者が **設定 → 招待メール** を開き、繁体字中国語、英語、日本語ごとに冒頭文、設定手順、3つの例を編集できます。初期の例は資料の要約、返信案の作成、リマインダーです。任意の講座リンクは HTTPS のみ使用でき、URL 内にユーザー名やパスワードを含めることはできません。

プレビューと送信メールは同じ処理で作成します。文章はエスケープし、対応する `**太字**` と改行のみを表示に反映します。生の HTML、画像、Markdown リンクは文字として扱います。パスワード設定リンクと有効期限はシステムが追加します。プレビューは有効な招待を発行せず、メールも送信しません。

## 初回ログイン

招待されたメンバーがパスワードを設定してログインすると、ホームに「あと少しで準備完了」が表示されます。

- パスワード設定はアカウントの状態から自動的に完了します。
- チャネルは管理者が本人のチャネル ID を確認して紐付けます。スキップできます。
- Google は「自分の接続」から接続します。スキップできます。保存済みの状態を確認するもので、Google API の実動作テストではありません。
- 例を選ぶと新しい会話に下書きを入力します。自動送信はしません。
- AI スタッフの能力、制限、承認、誤り、プライバシーの説明を読み、既読にします。

進捗はログイン中の本人ごとにサーバーに保存します。接続の完了は検証済みの記録から判断し、ブラウザから成功を申告することはできません。すべて完了またはスキップするか、閉じるとカードが消えます。案内によって権限は増えず、パスワードや多要素認証の手順も省略しません。移行時に既存アカウントへ自動表示しませんが、既存の招待リンクを使用した人にも案内を有効にします。

## 検証範囲

データベースと RPC のテストを含みます。実際の SMTP 送信、稼働中ゲートウェイでの初回ログイン、ブラウザ操作は別途受け入れ確認が必要です。

メインの AI スタッフには「操作可能」権限が必要です（既存の Owner 権限も対象です）。「閲覧のみ」は追加スタッフ向けで、メインの選択やダッシュボードでの会話開始・再開には使えません。既存のメイン設定も現在の権限で再確認され、閲覧のみに変更すると会話候補から外れます。招待とコースの URL は localhost を含め HTTPS が必須で、認証情報を埋め込むことはできません。
