# 合成サポート shadow 検証

リポジトリのルートから、1 つのコマンドで C7 エンジニアリング fixture を実行します。

```bash
CARGO_INCREMENTAL=0 cargo test -p duduclaw-gateway c7_synthetic_shadow_harness --lib -- --nocapture
```

デフォルトのテストスレッドのスタックサイズで十分です（2026-09 に検証済み。`RUST_MIN_STACK` を設定しなくても harness は約 90 秒で完了し、CI も `duduclaw-gateway` のテストスイートをそのように実行しています）。将来この fixture の変更でスタック使用量がデフォルトを超える場合は、`RUST_MIN_STACK=33554432` でワーカースレッドのスタックサイズを引き上げられます。これは任意であり、現時点では不要です。

テストは `C7_SYNTHETIC_SHADOW_SUMMARY=` で始まる JSON を 1 行出力します。含まれるのはケース数、レビューの判断、失敗コードだけで、チケット ID、ソーステキスト、テナントデータは含まれません。テストが通ると、現在のバックログとチケット SLA の shadow エンジンが、決定的な 21 日間のシーケンスを処理でき、各日の予測がその日の結果ソースが存在する前にコミットされていることが示されます。続いて、スコアの欠落、最終日の集計とチケット結果に対するレビュー済みの訂正、ソースの削除を確認します。欠落、期限切れ、失効した証拠は、完全なウィンドウのレビューを抑止しなければなりません。保存済みの過去の画面は、リンクされたソースが失効するまで元の意味を保ちます。

過去の日付と取り込み時刻は、`#[cfg(test)]` の fixture 内だけで設定されます。本番の policy、予測、スコアリングのメソッドは引き続き壁時計を使い、遅れたコミットを拒否します。この fixture は合成のエンジニアリング上の証拠です。実際のサポートデータでのスキルの測定、不確実性のキャリブレーション、モデルの昇格の承認、人員配置の実行の承認は行いません。Decision Lab の合成エンジニアリング検証は、現在のローカル fixture に対するダッシュボード上のビューのままです。このテストの出力は、運用上の証拠とは意図的に分けられています。
