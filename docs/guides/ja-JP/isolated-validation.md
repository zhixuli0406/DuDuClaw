# 明示したアカウントプールで検証する

[English](../isolated-validation.md) · [繁體中文](../zh-TW/isolated-validation.md)

DuDuClaw のデータディレクトリを分けても、アカウントローテーターは通常、ホストの Claude ログインやプロセス環境のプロバイダー API キーを検出します。明示した認証情報だけを使う検証環境では、その環境の `config.toml` に次を追加してください。

```toml
[account_loading]
inherit_host_credentials = false
```

既定値は `true` で、設定ファイルが存在しない場合も同じです。`false` にすると、すべてのアカウント読み込み経路で同じポリシーが適用されます。ローテーターは `claude auth status` を実行せず、読み込み時の `ANTHROPIC_API_KEY` フォールバックと、選択時の各プロバイダーの環境変数フォールバックを無効にします。空のプールは空のままで、環境から補充されません。`true` から `false` に変更して再読み込みすると、以前自動読み込みされたアカウントも削除されます。

明示した `[[accounts]]`、`[api]`、暗号化した認証情報、`secret://env/...` 参照は引き続き利用できます。明示した OAuth profile も、指定したホスト profile を利用できます。認証情報なしの検証では、これらの明示的な設定も検証ファイルから省略してください。

TOML が不正、`account_loading` が table 以外、`inherit_host_credentials` が真偽値以外、またはファイル不存在以外の読み込みエラーがある場合、読み込みは失敗し、プールは空になり、環境フォールバックも無効になります。設定を修正して再読み込みしてください。

この設定が制御するのは、ローテーターによる検出と選択だけです。子プロセスの環境、OS キーチェーン、runtime 固有の認証、ファイルアクセス、ネットワークは隔離しません。これらの境界が必要な場合は、runtime が対応するコンテナ隔離を使ってください。空のプールで確認できるのは認証情報なしの経路です。プロバイダー実行には、別途許可された有効な認証情報と実際の受け入れ検証が必要です。
