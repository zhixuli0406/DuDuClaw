# ブラウザーのログインを保存する

未リリース機能です。Unix ホストのコンテナーブラウザーが対象で、普段使う
ブラウザープロファイルは使用しません。

管理者が「設定 → システム」でログイン保存を許可し、社員の権限で個別の保存を
有効にします。どちらも既定では無効です。

```toml
# config.toml
[computer_use.profiles]
enabled = true
max_bytes = 67108864
retention_days = 30 # 0 は自動削除なし
```

```toml
# agent.toml
[capabilities]
computer_use = true
[capabilities.computer_use_config]
persist_login = true
```

保存 helper を含むコンテナーイメージを事前にインストールしてください。
自動取得は行いません。古いイメージでは保存付きの起動を拒否します。
既存のマシン暗号鍵が必要です。鍵がなければ平文で保存せず、doctor が警告します。

正常終了時に Chromium を閉じ、Cookies、Local Storage、IndexedDB だけを保存します。
gateway はアーカイブを展開せず、ホーム、社員インスタンス、プロファイルの識別子に
結び付けた AES-256-GCM で暗号化します。設定、パスワード、拡張機能、キャッシュ、
Service Worker は対象外です。既定上限は社員ごとに64 MiB、最大128 MiBです。
保存に失敗した場合は前回のスナップショットを保持します。
保存全体の制限は10秒です。新しい暗号化世代は索引の確定後に有効になります。
RED、緊急停止、インジェクションによる一時停止後の終了では現在の変更を保存しません。
引き継ぎ権限のある人は一時停止後の終了画面でログインの保存を明示できますが、
RED と緊急停止では保存を拒否します。

次回は Chromium の起動前に復元します。許可サイトを減らすと全体をリセットし、
追加だけなら保持します。社員の再作成、所有者・主所有者の変更、所有者の停止後に
以前のログインは再利用できません。社員を削除・アーカイブすると保存状態を削除します。
「ログイン状態を削除」はブラウザーを終了し、現在の状態を保存せずに削除します。
操作にはブラウザーの引き継ぎと同じ権限が必要です。
`duduclaw ops computer-profiles list` はメタデータだけを表示します。

ログインを保存すると、悪意のあるページに操られた社員もそのアカウントで操作できる
可能性があります。許可サイトを絞り、クリックや入力に承認ルールを設定してください。
人によるログインは引き継ぎで行い、クリップボード貼り付けは無効です。
クラッシュやコンテナーの緊急削除では最後の保存以降の変更を失う場合があります。
サイトによっては再認証が必要です。エクスポート、手動・定期バックアップには含めません。

検証範囲：アーカイブの許可リスト、リンク、パス、サイズ制限はローカルテスト済みです。
最終Rust、dashboard、実コンテナー復元、実サイト認証、他プラットフォームの検証は
未完了です。ライブ画面とローカルデスクトップブラウザーは別の作業です。
