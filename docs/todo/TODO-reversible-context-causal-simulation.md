## Scope and invariants

- Build a local, reversible compression path for tool results. A marker must never be emitted before its original is durably retrievable.
- Keep source-backed causal *claims* separate from accepted facts and estimated causal effects. Text alone cannot establish an intervention effect.
- Run strategy scenarios against versioned, replayable state-transition models. An LLM may propose a model or explain results, but cannot supply numeric outcomes as if they were simulated.
- Preserve tenant, agent, session, source ACL, retention, and deletion boundaries across every derived artifact.
- Simulation is read-only. Promoting a recommendation into an external action uses existing approval and policy gates.

## Delivery gates

1. **CCR gate:** the original is retrievable within its authorized lifetime, unauthorized reads fail, and quality/net cost are measured against uncompressed controls.
2. **Evidence gate:** every accepted claim resolves to a source span; contradictory claims and uncertainty remain visible. A textual claim alone is not an approved effect.
3. **Twin gate:** identical snapshots and seeds replay bit-for-bit; held-out performance beats the specified simple baselines for the pilot KPI. Until then, the UI labels runs as exploratory scenarios.
4. **Decision gate:** a brief can be audited back to snapshot, model, parameter, and source versions; external actions still pass the existing human and policy gates.

## Current implementation inventory

- `duduclaw-llm/src/ccr.rs` now stores post-redaction originals in scoped SQLite WAL rows with opaque IDs, digest, version, TTL, quotas, and bounded retrieval. Retrieval verifies digest, byte length, and transform version before returning text. Grants and refusals are recorded in a bounded database audit without query text or result content. Exact source-call revocation deletes matching originals and blocks reinsert of the same call; whole-scope revocation deletes every original in one tenant/agent/session/CCR-ACL boundary and tombstones future inserts. The local `duduclaw ccr-revoke-scope` command exposes that scope kill switch. The tool loop withholds the output when source-call revocation rejects compression. The shared tool loop exposes an internal retrieval tool and emits a preview only after the original commits. Gateway native API paths can opt in through `[ccr] enabled = true`. Current `source_acl` is an agent/session boundary, not an upstream per-source authorization mapping; upstream ACL/deletion hooks still need to invoke revocation. Previews compact JSON and JSON Lines without dropping records when useful, prioritize serious diagnostic lines, and preserve bounded search query matches; cross-turn tracking and broader result-type routing remain open. The legacy history trimmer says that stripped bytes are unavailable instead of claiming a nonexistent `tool_call_history` tool.
- `duduclaw-memory/src/causal.rs` now has immutable source versions, separate candidate claims and exact evidence spans, reviewer-controlled acceptance with append-only review records, bounded scoped curation reads, scoped source invalidation/deletion, and retention expiry scrubbing. Repeated extraction within one lineage reuses a semantic claim, while every exact span remains auditable; curation can inspect active support/opposition counts by distinct lineage. `causal_revision.rs` creates source-verified candidate revisions, permanently supersedes the old claim, and clears effects for dependent models. `causal_memory.rs` imports live agent memories into the same agent-private scope and uses SQLite lifecycle triggers to scrub copied text and downstream claims/effects when those memories change, become quarantined, or are deleted. `causal_wiki.rs` imports both agent-private and workspace-shared Wiki pages into their respective scopes, rechecks live Markdown and trust state before every causal read, and binds shared namespace policy changes into the source version. `causal_extract.rs` parses structured model proposals, validates whole-batch spans, and commits only candidates in one response-level transaction. `causal_model.rs` adds versioned variables and DAG drafts, requires human review of active asserted edges and new opposing evidence, and records assumption reviews before any estimator is allowed. `causal_identify.rs` checks classical backdoor admissibility in the reviewed DAG by excluding treatment descendants and testing d-separation. `causal_effect.rs` binds joint strata to pre-treatment variable values and computes a limited stratified observational contrast only from approved models and scoped immutable datasets; it checks time order and within-stratum positivity, returns `Unknown` on failures, runs a deterministic within-stratum placebo-label diagnostic, and hides/scrubs results after source revocation. The gateway now exposes instance-admin JWT-gated claim, source, DAG-model, and reviewed-alias reads plus compare-and-set claim/model/alias review and claim revision over the same local memory DB; the admin dashboard has a scoped causal curation page for these routes; model review binds the observed opposing-evidence digest. `causal_alias.rs` resolves exact scoped names only for future extraction and invalidates dependent claims and effects when a mapping changes. It does not prove the DAG is complete, exchangeability, or interval calibration. Measured extraction quality, authoritative lineage IDs, source ingestion, stronger identification and negative-control refutations, upstream ACL change/deletion hooks and tenant-bound user API remain open. `duduclaw causal-demo --db ...` provides source-grounded synthetic candidates and a draft DAG for this curation page without asserting any measured effect.
- `duduclaw-gateway/src/decision_sim.rs` now runs deterministic, read-only, daily FIFO support-queue transitions with conservation and replay hashes. `decision_event.rs` adds exact ticket-arrival FIFO service under explicit synchronized shift slots, wait quantiles and second-level SLA checks; the synthetic pilot reports both daily and event scenarios, while service-time distributions remain unfitted. `decision_store.rs` stores immutable, scoped snapshot/model/scenario, source-verified empirical-parameter inputs, and recomputed empirical-run manifests with digests for replay; it reconstructs event inputs from the exact ticket source and scrubs snapshots, parameter fits, and run manifests on exact source-version revocation. `decision_ingest.rs` reconstructs snapshots and observed daily stocks from strict ticket and staffing exports. `decision_synthetic.rs` generates a reproducible FIFO fixture for end-to-end engineering verification. `decision_brief.rs` compares two scenarios, includes exact input digests, verified source-artifact links, optional digest-matched empirical evidence, separately linked reviewed observational effects, and structured replay arguments; it labels the result exploratory without inventing calibrated intervals. `duduclaw decision-brief`, `duduclaw decision-replay`, `duduclaw decision-event-replay`, and `duduclaw decision-empirical-replay` read from owner-protected local stores; `duduclaw decision-demo` persists a synthetic pilot and emits executable replay commands. `decision_calibration.rs` fits capacity only from saturated days, checks capacity with observed arrivals, runs a separate prior-only one-day demand/backlog forecast diagnostic against three baselines, and reports rolling residual-band coverage and recent misses without claiming calibrated intervals. `decision_sensitivity.rs` runs bounded common-draw scenarios with supplied uniform ranges. `decision_empirical.rs` adds training-prefix empirical arrival/capacity resampling with optional contiguous demand blocks, common scenario draws, and explicit operator ranges when capacity is unidentified. `decision_policy.rs` checks explicit staffing feasibility and finds deterministic capacity thresholds at which its stated choice rule flips. Real historical data, validated demand forecasting and uncertainty calibration, shadow mode, and action bridge remain open. This is not yet a calibrated digital twin.
